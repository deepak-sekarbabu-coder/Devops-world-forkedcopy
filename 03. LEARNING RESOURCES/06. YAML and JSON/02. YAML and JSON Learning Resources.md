# YAML Skills Every DevOps Engineer Should Know

## Mappings

Understand:

```yaml
application:
  name: api
````

---

## Sequences

Understand:

```yaml
regions:
  - us-east-1
  - us-west-2
```

---

## Nested Structures

Understand:

```yaml
application:
  database:
    host: db.internal
    port: 5432
```

---

## Scalars

Understand:

* Strings
* Numbers
* Booleans
* Null values

---

## Quoting

Understand when values should be quoted.

Example:

```yaml
version: "1.0"
```

Do not assume that every YAML parser interprets ambiguous scalar values exactly the same way.

---

## Multi-Line Strings

Learn:

```yaml
message: |
  Deployment started.
  Waiting for health checks.
```

and folded style:

```yaml
message: >
  Deployment started.
  Waiting for health checks.
```

---

## Multiple Documents

Understand:

```yaml
---
```

This is common when multiple Kubernetes resources appear in one file.

---

## Anchors and Aliases

Understand concepts such as:

```yaml
defaults: &defaults
  replicas: 3
```

and:

```yaml
application:
  <<: *defaults
```

Do not overuse anchors in production configuration.

Readability matters.

# JSON Skills Every DevOps Engineer Should Know

## Objects

Understand:

```json
{
  "name": "api"
}
```

---

## Arrays

Understand:

```json
{
  "regions": [
    "us-east-1",
    "us-west-2"
  ]
}
```

---

## Nested Objects

Understand:

```json
{
  "database": {
    "host": "db.internal",
    "port": 5432
  }
}
```

---

## JSON Data Types

Know:

* String
* Number
* Boolean
* null
* Object
* Array

---

## Strict Syntax

JSON does not permit the loose syntax that many configuration formats allow.

Pay close attention to:

* Quotes
* Commas
* Braces
* Brackets
* Escaping

# jq Skills Every DevOps Engineer Should Know

Start with:

```bash
jq .
```

---

## Select a Field

```bash
jq '.name'
```

---

## Nested Fields

```bash
jq '.application.name'
```

---

## Arrays

```bash
jq '.items[]'
```

---

## Select Specific Objects

```bash
jq '.items[] | select(.status == "running")'
```

---

## Raw Output

```bash
jq -r '.name'
```

---

## Create New JSON

```bash
jq '{name: .name, status: .status}'
```

---

## API Example

```bash
curl -s https://example.com/api | jq .
```

---

## AWS Example

```bash
aws ec2 describe-instances | jq .
```

---

# yq Skills Every DevOps Engineer Should Know

## Read YAML

```bash
yq '.' config.yaml
```

---

## Read a Value

```bash
yq '.application.name' config.yaml
```

---

## Update YAML

```bash
yq -i '.application.replicas = 5' config.yaml
```

---

## Read Array Values

```bash
yq '.containers[].name' deployment.yaml
```

---

## YAML to JSON

```bash
yq -o=json '.' config.yaml
```

---

## JSON to YAML

```bash
yq -p=json '.' config.json
```

# Production Troubleshooting Practice

A DevOps engineer should eventually be able to investigate:

* YAML indentation error
* Duplicate YAML key
* JSON parsing error
* Missing comma
* Extra comma
* Wrong quotation marks
* Wrong data type
* Missing required field
* Incorrect API payload
* Kubernetes manifest rejected
* GitHub Actions workflow rejected
* Docker Compose file rejected
* Ansible playbook parsing failure
* Wrong environment configuration
* Secret accidentally stored in YAML
* JSON query returns null
* jq filter returns nothing
* yq modifies the wrong path
* YAML-to-JSON conversion behaves unexpectedly

Use a systematic troubleshooting flow:

**Validate Syntax → Validate Structure → Validate Types → Compare Git Diff → Check Schema → Check Application Error → Correct → Revalidate → Deploy → Verify**

# Production Rules

For serious DevOps configuration:

* Store YAML and JSON in Git.
* Review configuration changes through pull requests.
* Validate before deployment.
* Use schemas where available.
* Use linters.
* Avoid manual production edits.
* Never hardcode secrets.
* Keep configuration readable.
* Avoid unnecessary YAML complexity.
* Review indentation carefully.
* Understand data types.
* Validate generated configuration.
* Treat configuration changes like code changes.
* Inspect Git diffs before merging.
* Test configuration in lower environments first.

---

# Security Rules

Never store secrets directly in YAML or JSON such as:

* Passwords
* API keys
* AWS access keys
* Azure credentials
* Google Cloud credentials
* Database passwords
* Private SSH keys
* TLS private keys
* Access tokens

Use systems such as:

* HashiCorp Vault
* AWS Secrets Manager
* Azure Key Vault
* Google Secret Manager
* GitHub Actions Secrets
* Kubernetes secret-management solutions

Also be careful with:

* Untrusted YAML
* Unsafe YAML deserialization
* Untrusted JSON input
* API payload validation
* Third-party Kubernetes manifests
* Untrusted CI/CD configuration
* Overly permissive cloud policies
