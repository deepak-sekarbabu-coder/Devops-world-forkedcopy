## What It Is

Git and GitHub are related technologies, but they are not the same thing.

**Git** is a distributed version control system used to track changes to files over time. It allows engineers to create commits, work with branches, compare changes, merge development histories, restore previous versions, and collaborate without overwriting one another's work.

**GitHub** is a cloud-based development and collaboration platform built around Git repositories. It provides repository hosting and additional capabilities such as:

- Pull requests
- Code reviews
- Issues
- Discussions
- GitHub Actions
- Releases
- Packages
- Projects
- Security scanning
- Repository permissions
- Branch protection
- Rulesets
- Webhooks
- APIs

In DevOps, Git repositories frequently become the source of truth for application code, infrastructure definitions, deployment configuration, automation, documentation, and operational changes.

## What It Does

Git records and manages changes to files.

Git allows engineers to:

- Initialize repositories
- Clone repositories
- Track files
- Stage changes
- Create commits
- Create branches
- Switch between branches
- Merge branches
- Rebase commits
- Compare changes
- Restore previous versions
- Tag releases
- Work with remote repositories
- Resolve merge conflicts
- Inspect repository history

GitHub extends Git with remote collaboration and software delivery capabilities.

GitHub allows teams to:

- Host Git repositories
- Collaborate through pull requests
- Review changes
- Protect important branches
- Manage repository access
- Track issues
- Manage projects
- Publish releases
- Store packages
- Run CI/CD workflows
- Automate repository operations
- Scan dependencies and code
- Integrate engineering tools
- Maintain technical documentation

## Why Engineers Use It

Git is fundamental to modern DevOps workflows because infrastructure and application changes should be versioned, reviewable, reproducible, and auditable.

DevOps engineers commonly store the following in Git:

- Application source code
- Terraform configurations
- OpenTofu configurations
- Ansible playbooks
- Kubernetes manifests
- Helm charts
- Dockerfiles
- Docker Compose files
- CI/CD pipelines
- GitHub Actions workflows
- Jenkinsfiles
- Argo CD configuration
- Shell scripts
- Python automation
- YAML configuration
- Documentation
- Runbooks
- Policy definitions

GitHub provides the collaboration and automation layer around these repositories.

Together, Git and GitHub allow engineering teams to move infrastructure and software changes through controlled workflows rather than making undocumented changes directly in production.
