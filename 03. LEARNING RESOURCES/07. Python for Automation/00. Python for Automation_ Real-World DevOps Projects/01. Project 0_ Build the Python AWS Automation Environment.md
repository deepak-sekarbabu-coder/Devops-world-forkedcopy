Before we automate EC2, S3, IAM, EBS, RDS, security groups, resource tagging, or CloudWatch, we need a reliable Python automation environment.

"Install Python and Boto3."

# 2. Python Versus Bash for Operational Automation

DevOps engineers should understand both.

They solve overlapping problems, but they are not identical.

## Bash is excellent for:

* running Linux commands
* connecting commands with pipes
* manipulating files
* simple deployment tasks
* CI/CD job steps
* environment setup
* system administration
* small automation scripts

For example:

```bash
df -h
```

or:

```bash
systemctl status nginx
```

Bash is ideal when the workflow primarily involves operating-system commands.

## Python becomes attractive when we need:

* complex logic
* structured data
* dictionaries and lists
* JSON processing
* REST APIs
* AWS APIs
* multiple services
* reusable modules
* larger programs
* sophisticated error handling
* testing
* reporting
* CSV generation
* maintainable automation

Consider an AWS API response containing nested structures.

Python can naturally process:

```python
instance["InstanceId"]
```

and:

```python
instance.get("PrivateIpAddress")
```

and:

```python
for tag in instance.get("Tags", []):
    print(tag)
```

The decision is not:

```text
Python OR Bash
```

A real DevOps environment often uses:

```text
Bash + Python + AWS CLI + APIs + IaC + CI/CD
```

Use the tool that best fits the operation.

# 7. Understand AWS SDKs

SDK means Software Development Kit.

AWS provides SDKs for multiple programming languages.

An SDK gives our application programmatic access to AWS services.

Instead of manually doing:

```text
AWS Console
→ EC2
→ Instances
→ inspect resources
```

Python can communicate with AWS APIs.

Conceptually:

```text
Python Code
    |
    v
Boto3
    |
    v
AWS API
    |
    v
EC2 / S3 / IAM / RDS / CloudWatch
```

Boto3 handles much of the low-level work required to construct authenticated AWS API requests.

For example:

```python
import boto3

ec2 = boto3.client("ec2")
response = ec2.describe_instances()
```

That small amount of code represents an authenticated API request to EC2.

# 8. Understand Boto3 Clients and Resources

You will encounter two major Boto3 interfaces:

* clients
* resources

## Client

Example:

```python
import boto3

ec2 = boto3.client("ec2")
```

Clients provide lower-level service operations that closely resemble AWS API operations.

Example:

```python
response = ec2.describe_instances()
```

Another example:

```python
s3 = boto3.client("s3")
response = s3.list_buckets()
```

## Resource

Some AWS services also expose a higher-level resource interface.

Example:

```python
s3 = boto3.resource("s3")

for bucket in s3.buckets.all():
    print(bucket.name)
```

## Which will we use?

For these DevOps projects, we will rely heavily on clients.

Why?

They provide broad AWS API coverage and make it easier to understand exactly which API operation our automation is performing.

When you see:

```python
ec2.describe_instances()
```

you should begin thinking:

```text
Which API is being called?
What permissions does it require?
Is the response paginated?
What structure does it return?
What exceptions can occur?
```

That mindset matters more than memorizing Boto3 syntax.

# 10. Configure AWS Credentials Safely

One of the worst ways to write AWS automation is:

```python
import boto3

session = boto3.Session(
    aws_access_key_id="AKIA...",
    aws_secret_access_key="..."
)
```

Do not build our projects this way.

Why?

The secret becomes part of the source code.

If the file enters Git history, simply deleting the line later may not remove the secret from previous commits.

Instead, allow AWS tooling to obtain credentials from supported credential providers.

For a local lab using long-lived IAM credentials where appropriate, AWS CLI configuration can create local credential files.

For example:

```bash
aws configure
```

It may request:

```text
AWS Access Key ID:
AWS Secret Access Key:
Default region name:
Default output format:
```

For modern organizational environments, SSO, IAM Identity Center, assumed roles, temporary credentials, and workload roles are generally preferable to distributing long-lived access keys.

The exact authentication method depends on the environment.

# 12. Use boto3.Session()

Instead of creating unrelated clients throughout our program, we can create a Boto3 session.

Example:

```python
import boto3

session = boto3.Session(profile_name="veriqta-dev")

ec2 = session.client("ec2")
s3 = session.client("s3")
```

The session can represent important execution context such as:

* profile
* credentials
* region

We can inspect it:

```python
print(session.profile_name)
print(session.region_name)
```

A more flexible pattern is to avoid forcing one developer's profile name into reusable source code.

For example:

```python
import boto3


def create_session(profile_name=None, region_name=None):
    if profile_name:
        return boto3.Session(
            profile_name=profile_name,
            region_name=region_name
        )

    return boto3.Session(region_name=region_name)
```

Now the same code can operate in different environments.

# 14. Test AWS API Connectivity

Before building complex automation, test the simplest possible authenticated request.

STS is useful for this.

Create:


```python
import boto3
from botocore.exceptions import ClientError, NoCredentialsError


def main():
    try:
        session = boto3.Session()
        sts = session.client("sts")

        identity = sts.get_caller_identity()

        print("AWS connection successful")
        print(f"Account: {identity['Account']}")
        print(f"ARN: {identity['Arn']}")

    except NoCredentialsError:
        print("No AWS credentials were found.")

    except ClientError as error:
        print(f"AWS rejected the request: {error}")


if __name__ == "__main__":
    main()
```

# 15. Understand IAM Permissions for Automation

Authentication and authorization are different.

Authentication asks:

```text
Who are you?
```

Authorization asks:

```text
What are you allowed to do?
```

Your Python script may authenticate successfully but still fail when calling EC2.

For example:

```python
ec2.describe_instances()
```

might return:

```text
AccessDenied
```

That does not necessarily mean the Python code is broken.

It may mean the authenticated principal lacks permission.

An illustrative policy for a limited EC2 inventory lab could contain:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "ec2:DescribeInstances",
        "ec2:DescribeRegions"
      ],
      "Resource": "*"
    }
  ]
}
```

Do not automatically attach broad administrator access simply because an automation script receives AccessDenied.

Investigate the permission actually required.

# 18. Understand IAM Roles and Temporary Credentials

Long-lived access keys should not become the default mental model for AWS automation.

When code runs on AWS infrastructure, IAM roles can often provide credentials.

For example:

```text
EC2 Instance
     |
     v
IAM Role
     |
     v
Temporary Credentials
     |
     v
Boto3
     |
     v
AWS API
```

The application does not need an access key embedded in the code.

Temporary credentials typically include:

```text
Access Key ID
Secret Access Key
Session Token
Expiration
```

AWS SDK credential providers can obtain and refresh appropriate credentials in supported environments.

This becomes important later when automation moves from a developer laptop into:

* EC2
* ECS
* Lambda
* CI/CD
* scheduled workloads
* other AWS compute environments

Local development and production workload authentication should not be treated as identical problems.

# 19. Add Structured Logging

A production-style script should tell us what happened.

Do not rely on dozens of random:

```python
print()
```

statements.

Create:

```text
src/logging_config.py
```

Add:

```python
import logging
from pathlib import Path


def setup_logger(name="veriqta_aws_automation"):
    log_directory = Path("logs")
    log_directory.mkdir(parents=True, exist_ok=True)

    logger = logging.getLogger(name)
    logger.setLevel(logging.INFO)

    if logger.handlers:
        return logger

    formatter = logging.Formatter(
        "%(asctime)s | %(levelname)s | %(name)s | %(message)s"
    )

    console_handler = logging.StreamHandler()
    console_handler.setFormatter(formatter)

    file_handler = logging.FileHandler(
        log_directory / "automation.log"
    )
    file_handler.setFormatter(formatter)

    logger.addHandler(console_handler)
    logger.addHandler(file_handler)

    return logger
```

Example usage:

```python
from src.logging_config import setup_logger

logger = setup_logger()

logger.info("Starting AWS inventory")
logger.warning("Resource missing required tag")
logger.error("AWS API request failed")
```

Example output:

```text
2026-09-11 12:00:00 | INFO | veriqta_aws_automation | Starting AWS inventory
```

Logs become essential when automation runs without someone watching a terminal.

# 20. Add Exception Handling

Network operations fail.

Credentials expire.

Permissions change.

Regions become unavailable.

Resources disappear between API calls.

Code must expect failure.

Bad:

```python
response = ec2.describe_instances()
```

with no thought about what happens when the request fails.

Better:

```python
try:
    response = ec2.describe_instances()

except Exception as error:
    print(error)
```

But catching every exception generically is still weak.

We should catch meaningful exceptions when possible.

# 21. Handle AWS ClientError

Boto3 uses exceptions from Botocore.

Import:

```python
from botocore.exceptions import ClientError
```

Example:

```python
try:
    response = ec2.describe_instances()

except ClientError as error:
    code = error.response["Error"]["Code"]
    message = error.response["Error"]["Message"]

    logger.error(
        "EC2 request failed. Code=%s Message=%s",
        code,
        message
    )
```

Now we can distinguish AWS failures from arbitrary Python failures.

Possible cases include:

```text
AccessDenied
UnauthorizedOperation
InvalidParameterValue
RequestLimitExceeded
ExpiredToken
```

A useful DevOps troubleshooting model is:

```text
Symptom
   ↓
Exception
   ↓
AWS Error Code
   ↓
Likely Cause
   ↓
Diagnostic Check
   ↓
Fix
   ↓
Retry
   ↓
Verify
```

Do not immediately change code every time an AWS call fails.

The code may be correct.

# 22. Understand Pagination

This is one of the most important AWS automation concepts.

AWS APIs do not necessarily return every resource in one response.

Imagine an account containing thousands of resources.

AWS may return:

```text
Page 1
Page 2
Page 3
...
```

If your script reads only Page 1, your inventory is incomplete.

That is dangerous because the script may still look successful.

Boto3 provides paginators for supported operations.

Example:

```python
ec2 = session.client("ec2")

paginator = ec2.get_paginator("describe_instances")

for page in paginator.paginate():
    for reservation in page.get("Reservations", []):
        for instance in reservation.get("Instances", []):
            print(instance["InstanceId"])
```

Think:

```text
API
 |
 +-- Page 1
 |
 +-- Page 2
 |
 +-- Page 3
       |
       v
Combine Results
```

Every time we build inventory automation, one question should be:

"Is this API paginated?"

# 23. Work With AWS API Response Dictionaries

AWS API responses commonly become nested Python dictionaries and lists.

A simplified EC2 response might resemble:

```python
{
    "Reservations": [
        {
            "Instances": [
                {
                    "InstanceId": "i-0123456789",
                    "InstanceType": "t3.micro",
                    "State": {
                        "Name": "running"
                    },
                    "PrivateIpAddress": "10.0.1.15"
                }
            ]
        }
    ]
}
```

Access the instance ID:

```python
instance_id = instance["InstanceId"]
```

Access state:

```python
state = instance["State"]["Name"]
```

But not every field is guaranteed to exist.

This could fail:

```python
public_ip = instance["PublicIpAddress"]
```

because some instances have no public IP.

Safer:

```python
public_ip = instance.get("PublicIpAddress", "N/A")
```

This distinction becomes extremely important when processing infrastructure at scale.

Never assume every resource has identical optional attributes.

# 24. Export Results to JSON and CSV

Console output is useful while debugging.

Reports are useful operationally.

We will support both JSON and CSV.

Create:

```text
src/exporters.py
```

Add:

```python
import csv
import json
from pathlib import Path


def export_json(data, filename):
    output_directory = Path("reports/json")
    output_directory.mkdir(parents=True, exist_ok=True)

    output_path = output_directory / filename

    with output_path.open("w", encoding="utf-8") as file:
        json.dump(data, file, indent=4, default=str)

    return output_path


def export_csv(rows, filename):
    if not rows:
        return None

    output_directory = Path("reports/csv")
    output_directory.mkdir(parents=True, exist_ok=True)

    output_path = output_directory / filename

    with output_path.open(
        "w",
        newline="",
        encoding="utf-8"
    ) as file:

        writer = csv.DictWriter(
            file,
            fieldnames=rows[0].keys()
        )

        writer.writeheader()
        writer.writerows(rows)

    return output_path
```

Why both?

JSON preserves nested structured data well.

CSV is convenient for:

* spreadsheets
* filtering
* reporting
* analysts
* operations teams
* quick human review

```python
import boto3


def create_aws_session(profile_name=None, region_name=None):
    if profile_name:
        return boto3.Session(
            profile_name=profile_name,
            region_name=region_name
        )

    return boto3.Session(

def create_client(

    session,
    region_name=None

        service_name,
```

# 30. Run the First AWS Automation Script

Now we combine the concepts.

Create:

```text
scripts/first_aws_script.py
```

Add:

```python
import sys
from pathlib import Path

from botocore.exceptions import (
    BotoCoreError,
    ClientError,
    NoCredentialsError,
    ProfileNotFound,
)

PROJECT_ROOT = Path(__file__).resolve().parents[1]

if str(PROJECT_ROOT) not in sys.path:
    sys.path.insert(0, str(PROJECT_ROOT))

from src.aws_session import create_aws_session
from src.exporters import export_csv, export_json
from src.logging_config import setup_logger


logger = setup_logger()


def get_account_identity(session):
    sts = session.client("sts")
    return sts.get_caller_identity()


def discover_ec2_regions(session):
    ec2 = session.client("ec2", region_name="us-east-1")

    response = ec2.describe_regions(
        AllRegions=False
    )

    return sorted(
        region["RegionName"]
        for region in response.get("Regions", [])
    )


def main():
    logger.info("Starting VERIQTA AWS automation environment test")

    try:
        session = create_aws_session()

        identity = get_account_identity(session)

        account = identity.get("Account", "Unknown")
        arn = identity.get("Arn", "Unknown")

        logger.info(
            "Authenticated successfully. Account=%s ARN=%s",
            account,
            arn
        )

        regions = discover_ec2_regions(session)

        logger.info(
            "Discovered %d enabled EC2 regions",
            len(regions)
        )

        report = {
            "account": account,
            "arn": arn,
            "regions": regions,
            "region_count": len(regions),
        }

        json_path = export_json(
            report,
            "aws_environment_test.json"
        )

        csv_rows = [
            {
                "region": region,
                "account": account
            }
            for region in regions
        ]

        csv_path = export_csv(
            csv_rows,
            "aws_regions.csv"
        )

        logger.info(
            "JSON report created: %s",
            json_path
        )

        if csv_path:
            logger.info(
                "CSV report created: %s",
                csv_path
            )

        logger.info(
            "VERIQTA AWS automation environment test completed successfully"
        )

        return 0

    except ProfileNotFound as error:
        logger.error(
            "AWS profile was not found: %s",
            error
        )
        return 1

    except NoCredentialsError:
        logger.error(
            "AWS credentials could not be located."
        )
        return 1

    except ClientError as error:
        error_details = error.response.get(
            "Error",
            {}
        )

        logger.error(
            "AWS API request failed. Code=%s Message=%s",
            error_details.get("Code", "Unknown"),
            error_details.get("Message", str(error)),
        )

        return 1

    except BotoCoreError as error:
        logger.error(
            "AWS SDK error: %s",
            error
        )
        return 1

    except Exception:
        logger.exception(
            "Unexpected application failure"
        )
        return 1


if __name__ == "__main__":
    raise SystemExit(main())
```

Run:

```bash

```

When an AWS API supports pagination, deliberately compare:
