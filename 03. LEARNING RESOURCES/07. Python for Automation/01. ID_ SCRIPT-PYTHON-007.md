## What It Is

Python is a high-level, general-purpose programming language widely used for scripting, automation, infrastructure operations, cloud engineering, APIs, data processing, testing, and system administration.

Python for Automation focuses specifically on using Python to automate engineering and operational tasks rather than learning Python primarily for application or software development.

For DevOps engineers, Python provides a step beyond basic shell scripting when automation requires:

- More complex logic
- Structured data
- APIs
- JSON and YAML processing
- Error handling
- Reusable modules
- Cloud SDKs
- Testing
- Concurrent operations
- Larger automation workflows

Python works particularly well alongside Linux, Bash, Git, cloud platforms, CI/CD systems, containers, Kubernetes, and Infrastructure as Code.

Python allows engineers to create scripts and automation programs that interact with operating systems, files, APIs, cloud platforms, infrastructure services, databases, containers, monitoring systems, and other engineering tools.

## Why Engineers Use It

Python is useful when automation becomes too complex or difficult to maintain in Bash.

For example, an engineer may need to:

1. Call a cloud API.
2. Retrieve hundreds of resources.
3. Parse JSON responses.
4. Filter resources by tags.
5. Check their configuration.
6. Generate a report.
7. Send the results to another API.
8. Log failures.
9. Retry temporary errors.
10. Return an appropriate exit code.

Python provides better structures for this type of automation than a large collection of shell commands.

Engineers also use Python because it has:

- Readable syntax
- A large standard library
- Extensive third-party packages
- Strong API support
- Cloud SDKs
- Testing frameworks
- Cross-platform support
- Mature package management
- Strong community adoption

## Environment Variables

Use environment variables for runtime configuration.

Example:

```python
import os

environment = os.getenv("APP_ENV", "development")
```

Do not hardcode secrets into Python scripts.

## JSON Processing

JSON is extremely important for DevOps automation because APIs and cloud services frequently return JSON.

Example:

```python
import json

with open("config.json") as file:
    config = json.load(file)

print(config["environment"])
```

Engineers should understand:

* JSON objects
* Arrays
* Nested structures
* Serialization

## System Command Automation

Python can execute operating-system commands using `subprocess`.

Example:

```python
import subprocess

result = subprocess.run(
    ["systemctl", "is-active", "nginx"],
    capture_output=True,
    text=True,
    check=False
)

print(result.stdout)
```

Prefer argument lists rather than building shell command strings from untrusted input.

## Production Notes

Python automation used in production should be treated as production software.

Automation that modifies infrastructure, terminates instances, changes IAM policies, performs deployments, modifies Kubernetes resources, rotates credentials, or deletes data can cause serious outages.

Production automation should therefore be:

* Stored in Git
* Version controlled
* Peer reviewed
* Tested
* Documented
* Logged
* Observable
* Reproducible
* Predictable
* Idempotent where appropriate
* Designed with failure handling
* Designed with rollback or recovery where appropriate

---

## Virtual Environments

Avoid installing every dependency globally.

Use isolated Python environments.

Example:

```bash
python -m venv .venv
```

Activate:

```bash
source .venv/bin/activate
```

Install dependencies:

```bash
python -m pip install requests
```

Dependency isolation helps reduce conflicts between automation projects.

---

## Dependency Management

Production automation should define its dependencies.

Common files and approaches include:

```text
requirements.txt
pyproject.toml
```

Avoid relying on whatever package versions happen to exist on a server.

Reproducible automation requires controlled dependencies.

---

## Logging

Use structured and meaningful logging instead of relying only on `print()` for serious automation.

Example:

```python
import logging

logging.basicConfig(level=logging.INFO)

logging.info("Starting infrastructure inventory")
```

Logs should help engineers understand:

* What operation started
* Which resource was affected
* Whether it succeeded
* Why it failed
* How long it took

Never log passwords, tokens, private keys, or other secrets.

---

## Error Handling

Production automation should anticipate failure.

Example:

```python
try:
    perform_operation()
except Exception as error:
    logging.exception("Operation failed")
    raise
```

More specific exceptions should generally be caught when the program knows how to handle them.

Engineers should understand:

* Exceptions
* Custom exceptions
* Retries
* Timeouts
* Backoff
* Partial failures
* Cleanup
* Exit codes

## Timeouts

Network automation should not wait forever.

For example:

```python
response = requests.get(
    url,
    timeout=10
)
```

Timeouts are important when interacting with:

* APIs
* Cloud services
* Monitoring systems
* Kubernetes
* External services

---

## Retries

Temporary failures may require controlled retries.

Examples include:

* HTTP 429
* HTTP 503
* Temporary network failures
* Cloud API throttling

Retries should normally use:

* Maximum retry limits
* Backoff
* Jitter where appropriate
* Clear logging

Do not retry every failure indefinitely.

---

## Idempotency

Infrastructure automation should be idempotent where possible.

Running the automation repeatedly should not create unintended duplicate resources or progressively damage the environment.

Before creating or modifying resources, scripts may need to determine the existing state first.

Think:

```text
Inspect State
     |
Compare Desired State
     |
Change Only What Is Necessary
     |
Verify Result
```

## Security Notes

Python automation frequently interacts with privileged infrastructure.

Security must therefore be built into the automation.

Important practices include:

* Never hardcode passwords
* Never hardcode API tokens
* Never hardcode cloud credentials
* Never commit secrets to Git
* Use environment variables appropriately
* Use secret-management systems
* Apply least privilege
* Validate external input
* Validate API responses
* Use HTTPS
* Verify TLS certificates
* Protect configuration files
* Protect logs
* Protect temporary files
* Keep dependencies updated
* Review third-party packages
* Pin or constrain dependencies where appropriate
* Avoid unsafe deserialization
* Avoid executing untrusted code
* Avoid unsafe shell execution
* Restrict cloud IAM permissions
* Rotate credentials
* Prefer short-lived credentials where possible

---

## Shell Injection

Avoid building shell commands using untrusted strings.

Risky:

```python
import os

os.system("command " + user_input)
```

Prefer structured subprocess execution:

```python
import subprocess

subprocess.run(
    ["command", user_input],
    check=True
)
```

Avoid `shell=True` unless it is actually required and its security implications are understood.

---

## YAML Security

Do not deserialize untrusted YAML using unsafe loaders.

Prefer:

```python
yaml.safe_load(data)
```

When using PyYAML for normal configuration data.

## Troubleshooting Model

When Python automation fails, investigate systematically.

### 1. Identify the Exception

Read the traceback.

Do not immediately focus only on the final line.

Understand:

* Exception type
* Exception message
* File
* Function
* Line number
* Call stack

### 2. Check the Environment

Verify:

```bash
python --version
which python
python -m pip --version
```

Check:

* Python version
* Virtual environment
* Installed dependencies
* Environment variables
* Working directory

### 3. Check Dependencies

```bash
python -m pip list
```

Determine whether required libraries are installed and compatible.

### 4. Check Authentication

For cloud or API automation, verify:

* Credentials
* Tokens
* IAM permissions
* Credential expiration
* Service accounts

### 5. Check Connectivity

Verify:

* DNS
* Network path
* Firewall
* Proxy
* TLS
* API availability

### 6. Check Input Data

Validate:

* JSON
* YAML
* Environment variables
* Configuration files
* Command-line arguments
* API responses

### 7. Check Logs

Use application and platform logs to determine where the operation failed.

### 8. Reproduce Safely

Reproduce the failure in a controlled environment where possible.

### 9. Fix

Correct the underlying problem rather than only suppressing the exception.

### 10. Verify

Confirm:

* Automation completes
* Desired state exists
* No unintended resources changed
* Logs are clean
* Monitoring remains healthy
