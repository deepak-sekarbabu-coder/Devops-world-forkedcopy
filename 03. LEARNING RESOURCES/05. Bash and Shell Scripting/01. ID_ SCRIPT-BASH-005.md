## What It Is

Bash, short for Bourne Again Shell, is a command interpreter and scripting language widely used on Linux and Unix-like operating systems.

A shell provides an interface between users, scripts, and the operating system.

Bash can be used interactively in a terminal or non-interactively through scripts.

Shell scripting is the practice of combining commands, variables, conditions, loops, functions, pipelines, redirection, and operating-system utilities into reusable automation.

For DevOps engineers, Bash is one of the most important scripting tools because it connects Linux administration, automation, CI/CD, cloud operations, containers, and infrastructure tooling.

## Production Notes

Bash should be treated as production code when it performs important operational tasks.

A Bash script that deploys applications, modifies infrastructure, changes permissions, deletes resources, manages services, or rotates data can have the same production impact as application code.

Production Bash scripts should generally be:

- Stored in Git
- Version-controlled
- Reviewed through pull requests
- Tested before production use
- Documented
- Predictable
- Observable
- Clear about dependencies
- Clear about privileges
- Careful with destructive operations
- Idempotent where appropriate

Engineers should understand:

- Exit codes
- Error handling
- Signals
- Traps
- Logging
- Quoting
- Variable expansion
- Input validation
- Dependency validation
- Environment differences

Where appropriate, scripts may use:

```bash
set -euo pipefail
````

These options can improve failure handling, but they should be understood rather than copied blindly.

Before performing destructive operations, validate important variables and assumptions.

Example:

```bash
if [[ -z "${TARGET_DIR:-}" ]]; then
    echo "TARGET_DIR is not set" >&2
    exit 1
fi
```

When scripts run successfully from a terminal but fail in automation, compare:

* User
* Shell
* PATH
* Environment variables
* Working directory
* Permissions
* Dependencies

This is especially important with:

* Cron
* systemd
* Jenkins
* GitHub Actions
* GitLab CI/CD
* Docker
* Kubernetes

## Security Notes

Shell scripts can create serious security risks when credentials, privileges, external input, or commands are handled incorrectly.

Important security practices include:

* Never hardcode passwords
* Never hardcode API keys
* Never hardcode cloud credentials
* Never commit secrets to Git
* Quote variables correctly
* Validate external input
* Avoid unnecessary `eval`
* Avoid unnecessary root execution
* Restrict `sudo`
* Protect script permissions
* Protect configuration files
* Avoid exposing secrets through command-line arguments
* Avoid exposing secrets in shell history
* Avoid exposing secrets in logs
* Use secure temporary files
* Use HTTPS for remote resources
* Validate downloaded scripts
* Apply least privilege
* Review scripts before executing them
* Protect CI/CD secrets
* Use secret-management systems where appropriate

Avoid blindly running commands such as:

```bash
curl https://example.com/script.sh | bash
```

Remote scripts should be reviewed and their source verified before execution.

Production secrets should come from appropriate systems such as:

* HashiCorp Vault
* AWS Secrets Manager
* Azure Key Vault
* Google Secret Manager
* GitHub Actions Secrets
* Kubernetes secret-management solutions
