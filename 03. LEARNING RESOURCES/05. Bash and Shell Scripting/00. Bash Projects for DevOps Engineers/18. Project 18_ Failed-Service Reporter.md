# Project 18: Failed-Service Reporter

## Real-World systemd Incident Reporting for DevOps and On-Call Engineers

A Linux server may be reachable.

CPU may look normal.

Disk may have plenty of space.

But one critical service may have failed.

Examples:

```text
nginx.service
docker.service
jenkins.service
postgresql.service
ssh.service
```

During an incident, an engineer should be able to answer quickly:

```text
Which services failed?

When did they fail?

What state are they in?

What exit code did they return?

What does systemd think happened?

What do the most recent journal logs show?

What should I investigate next?
```

In this project, we will build:

```text
failed-service-reporter.sh
```

Example output:

```text
==========================================================================
                        FAILED SERVICES REPORT
==========================================================================

Host:                veriqta-linux-01
Generated:           2026-09-11 10:45:00 UTC
Failed Services:     2

--------------------------------------------------------------------------
nginx.service
--------------------------------------------------------------------------

Active State:        failed
Sub State:           failed
Result:              exit-code
Exit Status:         1

Recent Relevant Logs:

Sep 11 10:41:02 nginx[3842]: bind() to 0.0.0.0:80 failed
Sep 11 10:41:02 nginx[3842]: bind(): address already in use
Sep 11 10:41:02 systemd[1]: nginx.service: Failed with result 'exit-code'

Likely Investigation:
Check whether another process is already listening on the required port.

--------------------------------------------------------------------------
docker.service
--------------------------------------------------------------------------

Active State:        failed
Sub State:           failed
Result:              exit-code
Exit Status:         1

Recent Relevant Logs:

Sep 11 10:42:19 dockerd[4101]: failed to start daemon
Sep 11 10:42:19 systemd[1]: docker.service: Failed with result 'exit-code'

==========================================================================
Overall Status:      CRITICAL
==========================================================================
```

The central production lesson is:

```text
Detecting that a service failed is only the beginning.

A useful operations report should preserve enough evidence to help explain why it failed.
```

# 7. Is systemd Actually Running?

Having:

```text
systemctl
```

installed does not prove systemd is PID 1.

Check:

```bash
ps -p 1 -o comm=
```

```text

```

* Containers
* WSL configurations
* Minimal distributions
* Alternative init systems

# 8. Find Failed Units

Run:

```bash
systemctl --failed
```

This lists units systemd currently considers failed. systemd retains failed state information until it is reset or the unit state changes, so a failed entry can sometimes represent an earlier failure rather than a service that just failed seconds ago.

Example:

```text
UNIT             LOAD   ACTIVE SUB    DESCRIPTION
nginx.service    loaded failed failed A high performance web server
docker.service   loaded failed failed Docker Application Container Engine
```

---

# 9. Restrict to Services

We specifically want service failures.

Use:

```bash
systemctl \
    --failed \
    --type=service
```

This avoids mixing service failures with other unit types.

# 13. `status` Also Shows Journal Lines

`systemctl status` normally includes recent journal entries for the unit. The number of displayed lines can be controlled with `-n` or `--lines=`.

Example:

```bash

    nginx.service \
    --no-pager \
    -n 20
```

# 14. Why We Should Not Parse `systemctl status`

The output is intended primarily for humans.

Formatting can vary.

For scripts, use:

```bash
systemctl show
```

for structured properties.

Then use:

```bash
journalctl
```

for logs.

This separation makes the script more reliable.

# 24. Failure Timestamp

Useful systemd properties can include timestamps associated with state changes and process execution.

Rather than depending on one timestamp property across every unit type and systemd version, our report will combine:

```text
systemd state
journal timestamps
```

The journal provides the incident timeline.

---

# 25. `journalctl`

Run:

```bash
journalctl \
    -u nginx.service
```

This displays journal entries associated with that unit.

---

# 26. Recent Logs

For operations:

```bash
journalctl \
    -u nginx.service \
    -n 20 \
    --no-pager
```

This gives the latest twenty journal entries.

---

# 27. Why Recent Logs Matter

Suppose:

```text
Status: failed
Result: exit-code
Exit Status: 1
```

This is useful.

But the journal might reveal:

```text
bind(): address already in use
```

That points directly toward the next investigation.

---

# 28. ISO Timestamps

Use:

```bash
journalctl \
    -u nginx.service \
    -n 20 \
    --no-pager \
    -o short-iso
```

Example:

```text
2026-09-11T10:41:02+0000 nginx[3842]: bind(): address already in use
```

Consistent timestamps make reports easier to correlate.

---

# 29. More Precise Timestamps

Where supported:

```bash
journalctl \
    -u nginx.service \
    -n 20 \
    --no-pager \
    -o short-iso-precise
```

Useful when several events happen within one second.

---

# 30. Time-Based Journal Filtering

`journalctl` supports filtering by time with options such as:

```text
--since
--until
```

and unit filtering with:

```text
-u
```

which is useful for incident windows.

Example:

```bash
journalctl \
    -u nginx.service \
    --since "30 minutes ago"
```

---

# 31. Why Our Default Uses Recent Lines

Suppose a service failed:

```text
6 hours ago
```

and is still marked failed.

If we always use:

```text
--since "30 minutes ago"
```

we may retrieve no evidence.

Therefore the default production script will use:

```text
latest N entries
```

per failed service.

A time window will be an optional filter.

---

# 32. Journal Permissions

Some journal entries may require additional privileges.

A normal user may receive incomplete results depending on system configuration.

The script should not automatically execute:

```bash
sudo journalctl
```

because unattended privilege escalation is inappropriate.

Instead, report:

```text
Journal access may be incomplete.
```

where appropriate.

---

# 33. Do Not Automatically Restart Services

This project is diagnostic.

It will not run:

```bash
systemctl restart nginx
```

automatically.

Why?

Because restarting can:

* Destroy useful failure state
* Rotate/change logs
* Hide reproducible symptoms
* Cause more impact
* Restart a database unexpectedly
* Restart Docker and affect containers
* Trigger dependencies
* Mask root cause

# 37. Beginner Script

```bash
#!/usr/bin/env bash

set -u
set -o pipefail

if ! command -v systemctl >/dev/null 2>&1; then

    printf 'ERROR: systemctl is required.\n' >&2
    exit 3
fi

if ! command -v journalctl >/dev/null 2>&1; then

    printf 'ERROR: journalctl is required.\n' >&2
    exit 3
fi


FAILED_SERVICES=$(
    systemctl \
        --failed \
        --type=service \
        --no-legend \
        --plain |
    awk '{print $1}'
)


if [[ -z "$FAILED_SERVICES" ]]; then

    printf '%s\n' \
        "No failed services detected."

    exit 0
fi


printf '%s\n' \
    "=========================================================================="

printf '%s\n' \
    "                         FAILED SERVICES"

printf '%s\n' \
    "=========================================================================="

printf '\n'


while IFS= read -r service; do

    [[ -z "$service" ]] && continue


    ACTIVE_STATE=$(
        systemctl show \
            "$service" \
            -p ActiveState \
            --value
    )


    SUB_STATE=$(
        systemctl show \
            "$service" \
            -p SubState \
            --value
    )


    RESULT=$(
        systemctl show \
            "$service" \
            -p Result \
            --value
    )


    EXIT_STATUS=$(
        systemctl show \
            "$service" \
            -p ExecMainStatus \
            --value
    )


    printf '%s\n' \
        "--------------------------------------------------------------------------"

    printf '%s\n' \
        "$service"

    printf '%s\n' \
        "--------------------------------------------------------------------------"

    printf 'Active State: %s\n' \
        "$ACTIVE_STATE"

    printf 'Sub State:    %s\n' \
        "$SUB_STATE"

    printf 'Result:       %s\n' \
        "$RESULT"

    printf 'Exit Status:  %s\n' \
        "$EXIT_STATUS"


    printf '\nRecent Logs:\n\n'


    journalctl \
        -u "$service" \
        -n 10 \
        --no-pager \
        -o short-iso


    printf '\n'

done <<< "$FAILED_SERVICES"


exit 2
```

# 41. Why Exit 2?

Our status model will eventually be:

```text
0 = no failed services

1 = report warning / incomplete evidence

2 = one or more failed services

3 = script/systemd/configuration error
```

A failed system service deserves a non-zero status.

# 48. Production Script

```bash
#!/usr/bin/env bash

set -u
set -o pipefail

umask 077

# ------------------------------------------------------------------
# Failed-Service Reporter
# ------------------------------------------------------------------
#
# Read-only systemd incident inspection utility.
#
# Exit codes:
#
#   0 = no failed services / inspected service not failed
#   1 = report completed with evidence-access warning
#   2 = one or more failed services detected
#   3 = dependency/configuration/systemd error
#
# ------------------------------------------------------------------

TARGET_SERVICE=""

LOG_LINES=25
SINCE_TIME=""

OUTPUT_FILE=""

FAILED_COUNT=0
INSPECTION_WARNINGS=0

OVERALL_STATUS="HEALTHY"

HOST_NAME=""
GENERATED_AT=""
BOOT_ID=""
SYSTEMD_VERSION=""

SCRIPT_DIR=$(
    cd -- "$(dirname -- "${BASH_SOURCE[0]}")" &&
    pwd
)

readonly SCRIPT_DIR

LOG_DIR="$SCRIPT_DIR/logs"
AUDIT_LOG="$LOG_DIR/failed-service-reporter.log"

TMP_DIR=""
REPORT_TMP=""

declare -a SERVICES=()


show_help() {

    cat <<EOF
Usage:

  $0

  $0 \
    --service nginx.service

Options:

  --service UNIT
      Inspect one service explicitly.

  --lines N
      Number of recent journal lines per service.
      Default: 25

  --since TIME
      Optional journal time filter.

      Examples:
        "30 minutes ago"
        "2 hours ago"
        "today"

  --output FILE
      Write the complete report to FILE
      as well as displaying it.

  --help
      Display this help.

Examples:

  $0

  $0 \
    --lines 50

  $0 \
    --service nginx.service

  $0 \
    --service docker.service \
    --lines 100

  $0 \
    --since "2 hours ago"

  $0 \
    --output reports/failed-services.txt

Exit codes:

  0
      No failed services detected.

  1
      Inspection completed but some evidence
      could not be collected.

  2
      One or more failed services detected.

  3
      Script, dependency, or systemd error.
EOF
}


cleanup() {

    if [[ -n "${TMP_DIR:-}" &&
          -d "$TMP_DIR" ]]; then

        rm -rf -- "$TMP_DIR"
    fi
}


trap cleanup EXIT INT TERM


is_positive_integer() {

    [[ "$1" =~ ^[0-9]+$ ]] &&
    (( $1 > 0 ))
}


parse_arguments() {

    while [[ $# -gt 0 ]]; do

        case "$1" in

            --service)

                [[ $# -ge 2 ]] || {
                    printf 'ERROR: --service requires a value.\n' >&2
                    exit 3
                }

                TARGET_SERVICE="$2"
                shift 2
                ;;

            --lines)

                [[ $# -ge 2 ]] || {
                    printf 'ERROR: --lines requires a value.\n' >&2
                    exit 3
                }

                if ! is_positive_integer "$2"; then

                    printf 'ERROR: --lines must be a positive integer.\n' \
                        >&2

                    exit 3
                fi

                LOG_LINES="$2"
                shift 2
                ;;

            --since)

                [[ $# -ge 2 ]] || {
                    printf 'ERROR: --since requires a value.\n' >&2
                    exit 3
                }

                SINCE_TIME="$2"
                shift 2
                ;;

            --output)

                [[ $# -ge 2 ]] || {
                    printf 'ERROR: --output requires a file.\n' >&2
                    exit 3
                }

                OUTPUT_FILE="$2"
                shift 2
                ;;

            --help|-h)

                show_help
                exit 0
                ;;

            *)

                printf 'ERROR: Unknown option: %s\n' \
                    "$1" >&2

                exit 3
                ;;
        esac

    done
}


check_dependencies() {

    local commands=(
        systemctl
        journalctl
        awk
        grep
        hostname
        date
        mkdir
        mktemp
        rm
        cat
        head
    )

    local cmd

    for cmd in "${commands[@]}"; do

        if ! command -v "$cmd" >/dev/null 2>&1; then

            printf 'ERROR: Required command missing: %s\n' \
                "$cmd" >&2

            exit 3
        fi
    done
}


check_systemd() {

    local init_name

    init_name=$(
        ps -p 1 -o comm= 2>/dev/null |
        awk '{$1=$1; print}'
    )


    if [[ "$init_name" != "systemd" ]]; then

        printf '%s\n' \
            "ERROR: systemd does not appear to be PID 1." \
            >&2

        printf 'PID 1 appears to be: %s\n' \
            "${init_name:-unknown}" >&2

        exit 3
    fi


    if ! systemctl is-system-running \
        >/dev/null 2>&1; then

        local state

        state=$(
            systemctl is-system-running \
                2>/dev/null ||
            true
        )


        # "degraded" can simply mean failed units exist,
        # which is exactly what this tool investigates.
        if [[ "$state" != "degraded" &&
              "$state" != "running" ]]; then

            printf 'WARNING: systemd system state: %s\n' \
                "${state:-unknown}" >&2
        fi
    fi
}


initialize_environment() {

    TMP_DIR=$(
        mktemp -d
    )

    REPORT_TMP="$TMP_DIR/report.txt"

    : > "$REPORT_TMP"


    HOST_NAME=$(
        hostname
    )


    GENERATED_AT=$(
        date -u '+%Y-%m-%d %H:%M:%S UTC'
    )


    if [[ -r /proc/sys/kernel/random/boot_id ]]; then

        BOOT_ID=$(
            cat /proc/sys/kernel/random/boot_id
        )

    else

        BOOT_ID="unknown"
    fi


    SYSTEMD_VERSION=$(
        systemctl --version |
        head -n 1
    )
}


log_audit() {

    local level="$1"
    local message="$2"

    mkdir -p "$LOG_DIR"

    printf '[%s] [%s] host=%s %s\n' \
        "$(date -u '+%Y-%m-%d %H:%M:%S UTC')" \
        "$level" \
        "${HOST_NAME:-unknown}" \
        "$message" \
        >> "$AUDIT_LOG"
}


validate_target_service() {

    [[ -n "$TARGET_SERVICE" ]] || return


    if [[ "$TARGET_SERVICE" != *.service ]]; then

        TARGET_SERVICE="${TARGET_SERVICE}.service"
    fi


    if ! systemctl show \
        "$TARGET_SERVICE" \
        >/dev/null 2>&1; then

        printf 'ERROR: Service does not exist or cannot be inspected: %s\n' \
            "$TARGET_SERVICE" >&2

        exit 3
    fi
}


collect_services() {

    local service


    if [[ -n "$TARGET_SERVICE" ]]; then

        SERVICES=(
            "$TARGET_SERVICE"
        )

        return
    fi


    while IFS= read -r service; do

        [[ -z "$service" ]] && continue

        SERVICES+=(
            "$service"
        )

    done < <(
        systemctl \
            --failed \
            --type=service \
            --no-legend \
            --plain 2>/dev/null |
        awk '{print $1}'
    )
}


get_property() {

    local service="$1"
    local property="$2"

    systemctl show \
        "$service" \
        -p "$property" \
        --value \
        2>/dev/null ||
    true
}


collect_recent_logs() {

    local service="$1"
    local output_file="$2"

    local -a journal_args=(
        -u "$service"
        --no-pager
        -o short-iso-precise
        -n "$LOG_LINES"
    )


    if [[ -n "$SINCE_TIME" ]]; then

        journal_args+=(
            --since "$SINCE_TIME"
        )
    fi


    if ! journalctl \
        "${journal_args[@]}" \
        > "$output_file" \
        2>"$TMP_DIR/journal-error.log"; then

        ((INSPECTION_WARNINGS+=1))

        printf '%s\n' \
            "Journal logs could not be collected completely." \
            > "$output_file"

        return 1
    fi


    return 0
}


extract_relevant_errors() {

    local source_file="$1"
    local output_file="$2"


    grep -Ei \
        'error|failed|failure|fatal|panic|denied|refused|timeout|timed out|address already in use|cannot|unable|oom|killed|segfault|invalid|permission' \
        "$source_file" \
        > "$output_file" \
        2>/dev/null ||
    true
}


append_header() {

    {
        printf '%s\n' \
            "=========================================================================="

        printf '%s\n' \
            "                        FAILED SERVICES REPORT"

        printf '%s\n' \
            "=========================================================================="

        printf '\n%-24s %s\n' \
            "Host:" "$HOST_NAME"

        printf '%-24s %s\n' \
            "Generated:" "$GENERATED_AT"

        printf '%-24s %s\n' \
            "Boot ID:" "$BOOT_ID"

        printf '%-24s %s\n' \
            "systemd:" "$SYSTEMD_VERSION"

        if [[ -n "$TARGET_SERVICE" ]]; then

            printf '%-24s %s\n' \
                "Scope:" "$TARGET_SERVICE"

        else

            printf '%-24s %s\n' \
                "Scope:" "All failed services"
        fi


        if [[ -n "$SINCE_TIME" ]]; then

            printf '%-24s %s\n' \
                "Journal Since:" "$SINCE_TIME"
        fi


        printf '%-24s %s\n' \
            "Journal Lines:" "$LOG_LINES"

    } >> "$REPORT_TMP"
}


inspect_service() {

    local service="$1"

    local description
    local load_state
    local active_state
    local sub_state
    local result
    local main_pid
    local exec_main_code
    local exec_main_status
    local restart_count
    local fragment_path

    local log_file
    local error_file


    description=$(
        get_property \
            "$service" \
            "Description"
    )

    load_state=$(
        get_property \
            "$service" \
            "LoadState"
    )

    active_state=$(
        get_property \
            "$service" \
            "ActiveState"
    )

    sub_state=$(
        get_property \
            "$service" \
            "SubState"
    )

    result=$(
        get_property \
            "$service" \
            "Result"
    )

    main_pid=$(
        get_property \
            "$service" \
            "MainPID"
    )

    exec_main_code=$(
        get_property \
            "$service" \
            "ExecMainCode"
    )

    exec_main_status=$(
        get_property \
            "$service" \
            "ExecMainStatus"
    )

    restart_count=$(
        get_property \
            "$service" \
            "NRestarts"
    )

    fragment_path=$(
        get_property \
            "$service" \
            "FragmentPath"
    )


    log_file="$TMP_DIR/${service}.journal"
    error_file="$TMP_DIR/${service}.errors"


    collect_recent_logs \
        "$service" \
        "$log_file" ||
    true


    extract_relevant_errors \
        "$log_file" \
        "$error_file"


    if [[ "$active_state" == "failed" ]]; then

        ((FAILED_COUNT+=1))
        OVERALL_STATUS="CRITICAL"
    fi


    {
        printf '\n%s\n' \
            "--------------------------------------------------------------------------"

        printf '%s\n' \
            "$service"

        printf '%s\n' \
            "--------------------------------------------------------------------------"

        printf '\n%-24s %s\n' \
            "Description:" \
            "${description:-unknown}"

        printf '%-24s %s\n' \
            "Load State:" \
            "${load_state:-unknown}"

        printf '%-24s %s\n' \
            "Active State:" \
            "${active_state:-unknown}"

        printf '%-24s %s\n' \
            "Sub State:" \
            "${sub_state:-unknown}"

        printf '%-24s %s\n' \
            "Result:" \
            "${result:-unknown}"

        printf '%-24s %s\n' \
            "Main PID:" \
            "${main_pid:-unknown}"

        printf '%-24s %s\n' \
            "Exec Main Code:" \
            "${exec_main_code:-unknown}"

        printf '%-24s %s\n' \
            "Exec Main Status:" \
            "${exec_main_status:-unknown}"

        printf '%-24s %s\n' \
            "Restart Count:" \
            "${restart_count:-unknown}"

        printf '%-24s %s\n' \
            "Unit File:" \
            "${fragment_path:-unknown}"


        printf '\nRelevant Error Lines:\n'
        printf '%s\n' \
            ".........................................................................."


        if [[ -s "$error_file" ]]; then

            cat "$error_file"

        else

            printf '%s\n' \
                "No obvious error keywords found in the captured journal lines."
        fi


        printf '\nRecent Journal Logs:\n'
        printf '%s\n' \
            ".........................................................................."

        cat "$log_file"

        printf '\n'

    } >> "$REPORT_TMP"


    log_audit \
        "INFO" \
        "service=$service active_state=${active_state:-unknown} result=${result:-unknown} exit_status=${exec_main_status:-unknown}"
}


append_no_failures() {

    {
        printf '\n%s\n' \
            "--------------------------------------------------------------------------"

        printf '%s\n' \
            "No failed services detected."

        printf '%s\n' \
            "--------------------------------------------------------------------------"

    } >> "$REPORT_TMP"
}


append_summary() {

    {
        printf '\n%s\n' \
            "=========================================================================="

        printf '%s\n' \
            "                              SUMMARY"

        printf '%s\n' \
            "=========================================================================="

        printf '\n%-24s %s\n' \
            "Services Inspected:" \
            "${#SERVICES[@]}"

        printf '%-24s %s\n' \
            "Failed Services:" \
            "$FAILED_COUNT"

        printf '%-24s %s\n' \
            "Evidence Warnings:" \
            "$INSPECTION_WARNINGS"


        if (( FAILED_COUNT > 0 )); then

            printf '%-24s %s\n' \
                "Overall Status:" \
                "CRITICAL"

        elif (( INSPECTION_WARNINGS > 0 )); then

            printf '%-24s %s\n' \
                "Overall Status:" \
                "WARNING"

        else

            printf '%-24s %s\n' \
                "Overall Status:" \
                "HEALTHY"
        fi


        printf '%s\n' \
            "=========================================================================="

    } >> "$REPORT_TMP"
}


write_report() {

    cat "$REPORT_TMP"


    [[ -n "$OUTPUT_FILE" ]] || return


    local output_dir

    output_dir=$(
        dirname -- "$OUTPUT_FILE"
    )


    if ! mkdir -p \
        "$output_dir"; then

        printf 'ERROR: Cannot create report directory: %s\n' \
            "$output_dir" >&2

        exit 3
    fi


    if ! cat \
        "$REPORT_TMP" \
        > "$OUTPUT_FILE"; then

        printf 'ERROR: Cannot write report: %s\n' \
            "$OUTPUT_FILE" >&2

        exit 3
    fi


    printf '\nReport written to: %s\n' \
        "$OUTPUT_FILE"
}


return_status() {

    if (( FAILED_COUNT > 0 )); then
        return 2
    fi


    if (( INSPECTION_WARNINGS > 0 )); then
        return 1
    fi


    return 0
}


main() {

    parse_arguments "$@"

    check_dependencies

    check_systemd

    initialize_environment

    validate_target_service

    collect_services

    append_header


    if (( ${#SERVICES[@]} == 0 )); then

        append_no_failures

    else

        local service

        for service in "${SERVICES[@]}"; do

            inspect_service \
                "$service"
        done
    fi


    append_summary

    write_report


    log_audit \
        "INFO" \
        "run_complete inspected=${#SERVICES[@]} failed=$FAILED_COUNT evidence_warnings=$INSPECTION_WARNINGS"


    return_status
}


main "$@"
exit $?
```

# 60. Why Error Keyword Extraction Is Only a Hint

Our script searches recent journal lines for terms such as:

```text
error
failed
fatal
denied
timeout
cannot
unable
oom

```

This is helpful.

But it is not root-cause analysis.

A critical message may not contain the word:

```text
error
```

For example:

```text
bind(): address already in use
```

So the full recent journal is included too.

# 61. Never Trust Only Grep


Because errors can be expressed as:

```text

Permission denied

Connection refused
No space left on device
```

And sometimes the root cause appears in an informational line before the final error.

Context matters.

# 68. Exit Code Interpretation

Suppose:

```text

```

That means the process returned status 1 under applicable service conditions.

But:

```text
1
```




# 71. CPU and Memory Connection

A service failure such as:

```text
OOMKilled
```

should lead to:

```text
memory usage
memory limit
application memory behavior
kernel OOM evidence
```

not simply another restart.

# 72. Disk Connection



Then:


Then:

# 73. Permission Failure

Example:

```text
Permission denied
```

Investigate:

```text
file ownership
directory permissions
service user
SELinux/AppArmor where applicable
recent configuration changes
```

Do not immediately run:

```bash
chmod 777
```

That is not responsible troubleshooting.

# 74. Configuration Failure

Example:

```text
nginx: configuration file test failed
```

Before restart:

```bash
nginx -t
```

For another daemon, use its own configuration-validation command where available.

Validate configuration before restarting a failed service.

# 75. systemd Dependency Failure

Run:

```bash
systemctl list-dependencies \
    nginx.service
```

```bash
systemctl show \

    -p Requires \
    -p Wants \
```

# 77. Production Upgrade: Start-Limit Failures

Repeated failures can cause systemd to stop attempting restarts.

Possible result:

```text
start-limit-hit
```

This is a strong signal that:

```text
the service has been repeatedly failing
```

Do not simply reset the failure counter without diagnosing why.

# 78. `reset-failed`

```bash

```

which resets stored failed state.

Do not run this inside the reporter.

The failed state itself is useful evidence.

# 79. Why Stale Failures Exist

A service can fail earlier and remain represented in systemd's failed state until its state is reset or changed.

Therefore:

```text
systemctl --failed
```

does not automatically mean:

```text
service failed in the last 60 seconds
```

Use journal timestamps for timeline context.

```bash

    service \
```

into reports.

```text

tokens
API keys
```

The failed-service reporter does not need them by default.

```bash
systemctl cat \
```

# 110. Security: Least Privilege

The script should run as a normal authorized operational user where possible.

Do not automatically elevate privileges.

# 111. Security: Report Permissions

```bash

```

as the production script does.

# 112. Production Upgrade: Redaction

A stronger tool could redact patterns resembling:

```text
tokens
password parameters
API keys
```

before writing reports.

Redaction is difficult to make perfect.
