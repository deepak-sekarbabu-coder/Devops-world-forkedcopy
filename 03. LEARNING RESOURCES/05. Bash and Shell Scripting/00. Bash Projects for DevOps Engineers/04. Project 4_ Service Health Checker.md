# Project 4: Service Health Checker

A Linux service can fail in several different ways.

The process may stop.

The service may enter a failed state.

The service may be disabled and therefore not start after reboot.

The service may not even be installed.

And there is another important case:

```text
systemctl says the service is running
```

but the application behind the service is not actually working.

That distinction matters.

In this project, we will build:

```text
service-health-checker.sh
```

The script will monitor important Linux services such as:

* SSH
* Nginx
* Apache
* Docker
* Jenkins

It will classify each service and produce a report such as:

```text
======================================================================
                       SERVICE STATUS REPORT
======================================================================
Timestamp:       2026-09-11 12:10:44
Hostname:        veriqta-server-01

Service              Active State     Enabled State    Result
----------------------------------------------------------------------
ssh                  active           enabled          RUNNING
nginx                active           enabled          RUNNING
apache2              inactive         disabled         STOPPED
docker               failed           enabled          FAILED
jenkins              active           enabled          RUNNING

----------------------------------------------------------------------
Running:        3
Stopped:        1
Failed:         1
Missing:        0

Overall Status: CRITICAL
======================================================================
```

We will then extend the project with:

* configurable service lists
* exit codes
* logging
* failed-service diagnostics
* optional restart capability
* restart verification
* application-level health checks
* safe recovery controls

The most important rule in this project is:

```text
Detection and recovery are different responsibilities.
```

The script will never restart a service unless recovery has been explicitly enabled.

Imagine you are supporting a Linux application server.


* Is there a storage problem?

* Did a configuration change trigger the failure?

This project automates the first-level service inspection while still preserving proper troubleshooting discipline.

# 4. Important Distribution Differences

Service unit names are not always the same across Linux distributions.

For example, SSH may be:

```text
ssh
```

on Ubuntu or Debian.

But on some distributions it may be:

```text
sshd
```

Apache may be:

```text
apache2
```

on Debian and Ubuntu.

On RHEL-like systems it is commonly:

```text
httpd
```

That means production service monitoring should not assume identical names everywhere.

For this project, students should verify the service names on their own system.

# 19. Build a Classification Function

Create:

```bash
classify_service() {

    local service="$1"
    local active_state

    if ! service_exists "$service"; then
        printf 'MISSING'
        return
    fi

    active_state=$(get_active_state "$service")

    case "$active_state" in

        active)
            printf 'RUNNING'
            ;;

        failed)
            printf 'FAILED'
            ;;

        inactive)
            printf 'STOPPED'
            ;;

        activating)
            printf 'STARTING'
            ;;

        deactivating)
            printf 'STOPPING'
            ;;

        *)
            printf 'UNKNOWN'
            ;;
    esac
}
```

Now our report has meaningful states.

# 34. Production Upgrade: Optional Service Recovery

Now we reach the dangerous part.

We want the script to optionally support:

```bash
systemctl restart nginx
```

But it must never do this by default.

Default:

```text
Restart disabled
```

Recovery must require explicit configuration.

We will require two conditions:

```text
1. Restart support was enabled.
2. The service is in an approved restart list.
```

That provides basic guardrails.

---

# 35. Approved Restart List

Create:

```bash
RESTART_ALLOWED_SERVICES=(
    "nginx"
)
```

This means even when restart mode is enabled, only Nginx can be restarted automatically.

Docker and Jenkins will not be restarted automatically unless explicitly added.

---

# 36. Why Docker Is Not Automatically Restarted

Restarting Docker can affect:

* Containers
* Application availability
* CI workloads
* Networks
* Deployment processes

Likewise, restarting Jenkins may interrupt builds.

Automatic recovery must understand application impact.

That is why we do not make:

```bash
systemctl restart "$service"
```

the default response to every failure.

---

# 37. Check Whether Restart Is Allowed

Create:

```bash
restart_allowed() {

    local requested_service="$1"
    local allowed

    for allowed in "${RESTART_ALLOWED_SERVICES[@]}"; do

        if [[ "$allowed" == "$requested_service" ]]; then
            return 0
        fi

    done

    return 1
}
```

---

# 38. Recovery Function

Create:

```bash
attempt_recovery() {

    local service="$1"

    if [[ "$RESTART_ENABLED" != true ]]; then
        return
    fi

    if ! restart_allowed "$service"; then

        printf 'Recovery skipped for %s: restart not approved.\n' \
            "$service"

        return
    fi

    printf 'Attempting restart: %s\n' "$service"

    if sudo systemctl restart "$service"; then

        sleep 2

        if systemctl is-active --quiet "$service"; then

            printf 'Recovery successful: %s is active.\n' \
                "$service"

        else

            printf 'Recovery failed: %s is still unhealthy.\n' \
                "$service" >&2
        fi

    else

        printf 'Restart command failed for %s.\n' \
            "$service" >&2
    fi
}
```

---

# 39. Why We Verify After Restart

This is not enough:

```bash
systemctl restart nginx
```

A command can return successfully and the application can fail shortly afterward.

At minimum, verify:

```bash
systemctl is-active nginx
```

A stronger implementation would also perform an application-level check.

For Nginx:

```bash
curl -f http://127.0.0.1/
```

That distinction becomes important later.

---

# 40. Service Health vs Application Health

Suppose:

```bash
systemctl is-active nginx
```

returns:

```text
active
```

But:

```bash
curl -f http://127.0.0.1/
```

returns:

```text
500 Internal Server Error
```

Systemd says Nginx is running.

But the application is not healthy.

Therefore:

```text
Service running
```

does not always mean:

```text
Application healthy
```

Professional monitoring usually combines both.

# 42. Complete Working Script

Replace `service-health-checker.sh` with:

```bash
#!/usr/bin/env bash

set -u
set -o pipefail

# ----------------------------------------------------------------------
# Service Health Checker
#
# Exit codes:
#   0 = OK
#   1 = WARNING
#   2 = CRITICAL
#   3 = Script/configuration error
# ----------------------------------------------------------------------

SERVICES=(
    "ssh"
    "nginx"
    "apache2"
    "docker"
    "jenkins"
)

RESTART_ALLOWED_SERVICES=(
    "nginx"
)

ENABLE_LOG=true
SHOW_DIAGNOSTICS=false
RESTART_ENABLED=false

OVERALL_STATUS="OK"

RUNNING_COUNT=0
STOPPED_COUNT=0
FAILED_COUNT=0
MISSING_COUNT=0
OTHER_COUNT=0

TIMESTAMP=""
HOSTNAME_VALUE=""

SCRIPT_DIR=$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")" && pwd)
readonly SCRIPT_DIR

LOG_DIR="$SCRIPT_DIR/logs"
LOG_FILE="$LOG_DIR/service-health.log"


show_help() {

    cat <<EOF
Usage:
  $0 [options]

Options:
  --services LIST      Comma-separated service list
  --diagnostics        Show diagnostics for unhealthy services
  --no-log             Disable log output
  --restart-enabled    Permit explicitly approved service restarts
  --help               Display this help

Examples:
  $0

  $0 --services ssh,nginx,docker

  $0 --diagnostics

  $0 --services nginx \
     --diagnostics \
     --restart-enabled

Important:
  Automatic restart is disabled by default.

  Even with --restart-enabled, only services listed in
  RESTART_ALLOWED_SERVICES may be restarted.
EOF
}


parse_arguments() {

    while [[ $# -gt 0 ]]; do

        case "$1" in

            --services)

                if [[ $# -lt 2 || -z "$2" ]]; then
                    printf 'ERROR: --services requires a value.\n' >&2
                    exit 3
                fi

                IFS=',' read -r -a SERVICES <<< "$2"

                shift 2
                ;;

            --diagnostics)

                SHOW_DIAGNOSTICS=true
                shift
                ;;

            --no-log)

                ENABLE_LOG=false
                shift
                ;;

            --restart-enabled)

                RESTART_ENABLED=true
                shift
                ;;

            --help|-h)

                show_help
                exit 0
                ;;

            *)

                printf 'ERROR: Unknown option: %s\n' "$1" >&2
                show_help
                exit 3
                ;;
        esac

    done
}


check_dependencies() {

    local commands=(
        systemctl
        journalctl
        hostname
        date
        sleep
    )

    local cmd
    local missing=0

    for cmd in "${commands[@]}"; do

        if ! command -v "$cmd" >/dev/null 2>&1; then

            printf 'ERROR: Required command missing: %s\n' \
                "$cmd" >&2

            missing=1
        fi

    done

    if (( missing != 0 )); then
        exit 3
    fi
}


check_systemd() {

    if [[ ! -d /run/systemd/system ]]; then

        printf 'ERROR: systemd does not appear to be active on this host.\n' \
            >&2

        exit 3
    fi
}


service_exists() {

    local service="$1"

    systemctl cat "${service}.service" \
        >/dev/null 2>&1
}


get_active_state() {

    local service="$1"
    local state

    state=$(systemctl is-active "$service" 2>/dev/null || true)

    if [[ -z "$state" ]]; then
        state="unknown"
    fi

    printf '%s' "$state"
}


get_enabled_state() {

    local service="$1"
    local state

    state=$(systemctl is-enabled "$service" 2>/dev/null || true)

    if [[ -z "$state" ]]; then
        state="unknown"
    fi

    printf '%s' "$state"
}


classify_service() {

    local service="$1"
    local active_state

    if ! service_exists "$service"; then
        printf 'MISSING'
        return
    fi

    active_state=$(get_active_state "$service")

    case "$active_state" in

        active)
            printf 'RUNNING'
            ;;

        failed)
            printf 'FAILED'
            ;;

        inactive)
            printf 'STOPPED'
            ;;

        activating)
            printf 'STARTING'
            ;;

        deactivating)
            printf 'STOPPING'
            ;;

        *)
            printf 'UNKNOWN'
            ;;
    esac
}


get_severity() {

    local result="$1"

    case "$result" in

        RUNNING)
            printf 'OK'
            ;;

        FAILED)
            printf 'CRITICAL'
            ;;

        STOPPED|STARTING|STOPPING|MISSING|UNKNOWN)
            printf 'WARNING'
            ;;

        *)
            printf 'WARNING'
            ;;
    esac
}


update_overall_status() {

    local severity="$1"

    if [[ "$severity" == "CRITICAL" ]]; then

        OVERALL_STATUS="CRITICAL"

    elif [[ "$severity" == "WARNING" &&
            "$OVERALL_STATUS" == "OK" ]]; then

        OVERALL_STATUS="WARNING"
    fi
}


count_result() {

    local result="$1"

    case "$result" in

        RUNNING)
            ((RUNNING_COUNT += 1))
            ;;

        STOPPED)
            ((STOPPED_COUNT += 1))
            ;;

        FAILED)
            ((FAILED_COUNT += 1))
            ;;

        MISSING)
            ((MISSING_COUNT += 1))
            ;;

        *)
            ((OTHER_COUNT += 1))
            ;;
    esac
}


write_log() {

    local service="$1"
    local active_state="$2"
    local enabled_state="$3"
    local result="$4"

    if [[ "$ENABLE_LOG" != true ]]; then
        return
    fi

    mkdir -p "$LOG_DIR"

    printf '[%s] host=%s service=%s active=%s enabled=%s result=%s\n' \
        "$TIMESTAMP" \
        "$HOSTNAME_VALUE" \
        "$service" \
        "$active_state" \
        "$enabled_state" \
        "$result" \
        >> "$LOG_FILE"
}


show_service_diagnostics() {

    local service="$1"

    printf '\nDiagnostics for %s\n' "$service"

    printf '%s\n' \
        "----------------------------------------------------------------------"

    printf '\nSystemd status:\n\n'

    systemctl status "$service" \
        --no-pager \
        --lines=10 \
        2>&1 || true

    printf '\nRecent journal entries:\n\n'

    journalctl \
        -u "$service" \
        -n 10 \
        --no-pager \
        2>&1 || true

    printf '%s\n' \
        "----------------------------------------------------------------------"
}


restart_allowed() {

    local requested_service="$1"
    local allowed

    for allowed in "${RESTART_ALLOWED_SERVICES[@]}"; do

        if [[ "$allowed" == "$requested_service" ]]; then
            return 0
        fi

    done

    return 1
}


attempt_recovery() {

    local service="$1"

    if [[ "$RESTART_ENABLED" != true ]]; then
        return
    fi

    if ! restart_allowed "$service"; then

        printf '\nRecovery skipped for %s: restart is not approved.\n' \
            "$service"

        return
    fi

    printf '\nAttempting approved restart for %s...\n' "$service"

    if sudo systemctl restart "$service"; then

        sleep 2

        if systemctl is-active --quiet "$service"; then

            printf 'Recovery successful: %s is active.\n' \
                "$service"

        else

            printf 'Recovery failed: %s remains unhealthy.\n' \
                "$service" >&2
        fi

    else

        printf 'ERROR: restart command failed for %s.\n' \
            "$service" >&2
    fi
}


monitor_services() {

    local service
    local active_state
    local enabled_state
    local result
    local severity

    printf '%-20s %-18s %-18s %-15s\n' \
        "Service" \
        "Active State" \
        "Enabled State" \
        "Result"

    printf '%s\n' \
        "----------------------------------------------------------------------"

    for service in "${SERVICES[@]}"; do

        if service_exists "$service"; then

            active_state=$(get_active_state "$service")
            enabled_state=$(get_enabled_state "$service")

        else

            active_state="not-found"
            enabled_state="not-found"
        fi

        result=$(classify_service "$service")
        severity=$(get_severity "$result")

        printf '%-20s %-18s %-18s %-15s\n' \
            "$service" \
            "$active_state" \
            "$enabled_state" \
            "$result"

        count_result "$result"

        update_overall_status "$severity"

        write_log \
            "$service" \
            "$active_state" \
            "$enabled_state" \
            "$result"

        if [[ "$result" != "RUNNING" &&
              "$result" != "MISSING" ]]; then

            if [[ "$SHOW_DIAGNOSTICS" == true ]]; then
                show_service_diagnostics "$service"
            fi

            if [[ "$result" == "FAILED" ||
                  "$result" == "STOPPED" ]]; then

                attempt_recovery "$service"
            fi
        fi

    done
}


print_summary() {

    printf '\n%s\n' \
        "----------------------------------------------------------------------"

    printf '%-16s %s\n' \
        "Running:" "$RUNNING_COUNT"

    printf '%-16s %s\n' \
        "Stopped:" "$STOPPED_COUNT"

    printf '%-16s %s\n' \
        "Failed:" "$FAILED_COUNT"

    printf '%-16s %s\n' \
        "Missing:" "$MISSING_COUNT"

    printf '%-16s %s\n' \
        "Other:" "$OTHER_COUNT"

    printf '\n%-16s %s\n' \
        "Overall Status:" "$OVERALL_STATUS"

    printf '%s\n' \
        "======================================================================"
}


return_status() {

    case "$OVERALL_STATUS" in

        OK)
            return 0
            ;;

        WARNING)
            return 1
            ;;

        CRITICAL)
            return 2
            ;;

        *)
            return 3
            ;;
    esac
}


main() {

    parse_arguments "$@"

    check_dependencies

    check_systemd

    TIMESTAMP=$(date '+%Y-%m-%d %H:%M:%S')
    HOSTNAME_VALUE=$(hostname)

    printf '%s\n' \
        "======================================================================"

    printf '%s\n' \
        "                       SERVICE STATUS REPORT"

    printf '%s\n' \
        "======================================================================"

    printf '%-17s %s\n' \
        "Timestamp:" "$TIMESTAMP"

    printf '%-17s %s\n' \
        "Hostname:" "$HOSTNAME_VALUE"

    printf '%-17s %s\n' \
        "Restart Mode:" "$RESTART_ENABLED"

    printf '\n'

    monitor_services

    print_summary

    return_status
}


main "$@"
exit $?
```

# 71. Automatic Restart Safety

The most dangerous design would be:

```text
if unhealthy
    restart automatically
```

without context.

Why?

Suppose the service repeatedly fails because:

```text
configuration is invalid
```

The monitor could enter:

```text
fail
restart
fail
restart
fail
restart
```

That is restart looping.

It creates noise and may make troubleshooting harder.

---

# 72. Restart Limits

A production recovery system should track:

```text
Last restart time
Number of restart attempts
Cooldown period
Maximum attempts
```

For example:

```text
Maximum automatic restarts: 2
Cooldown: 10 minutes
```

After that:

```text
Stop automatic recovery
Escalate to engineer
```

This avoids uncontrolled remediation loops.

---

# 73. Production Upgrade: Recovery Cooldown

Future logic:

```text
If failed:
    Check last recovery attempt

If last attempt < 10 minutes ago:
    Do not restart

Otherwise:
    Attempt approved restart
```

This is safer than immediate repeated recovery.

```bash
./service-health-checker.sh \
    --services veriqta-test \
    --restart-enabled
```

Unless:

```text
veriqta-test
```

has been added to:

```bash
RESTART_ALLOWED_SERVICES
```

the output should say:

```text
Recovery skipped for veriqta-test: restart is not approved.
```

That proves both controls are working.

# 110. What This Project Actually Taught You

This project was not simply:

```bash

```

You learned that Linux service health has several dimensions:

```text
Does the service exist?
        |
        v
Is it active?
        |
        v
Is it enabled?
        |
        v
Did it fail?
        |
        v
Why did it fail?
        |
        v
Is the application actually healthy?
        |
        v
Is recovery safe?
```

You also learned that:

```text
running
```

does not automatically mean:

```text
healthy
```

and:

```text
failed
```

does not automatically mean:

```text
restart it
```

A good engineer investigates cause before taking action.
