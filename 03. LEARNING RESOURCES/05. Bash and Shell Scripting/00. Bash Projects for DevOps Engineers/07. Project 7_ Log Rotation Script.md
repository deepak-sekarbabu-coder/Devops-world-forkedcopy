# Project 7: Log Rotation Script

Logs grow.

If nothing manages them, they can eventually consume an entire filesystem.

A log file may begin at:

```text
20 MB
```

then become:

```text
500 MB
```

then:

```text
5 GB
```

and eventually fill:

```text
/var
```

When that happens, the problem is no longer just logging.

It can affect:

* Applications
* Databases
* Package managers
* Monitoring agents
* SSH
* Temporary file creation
* System services
* CI/CD runners
* Containers
* Operating-system stability

In this project, we will build:

```text
log-rotator.sh
```

The script will:

* Check log-file size
* Decide whether rotation is required
* Rotate the active log
* Compress old logs
* Keep a defined number of archives
* Remove expired archives
* Log its own actions
* Detect failures
* Support scheduling

A finished directory might look like:

```text
application.log
application.log.1.gz
application.log.2.gz
application.log.3.gz
```

The workflow is:

```text
application.log
      |
      v
Check size
      |
      v
Threshold reached?
      |
   +--+--+
   |     |
   | No  | Yes
   |     |
   v     v
 Exit   Rotate
          |
          v
       Compress
          |
          v
    Enforce retention
          |
          v
       Log result
```

The most important lesson is:

```text
Renaming a log file does not automatically mean the application has started writing to a new log file.
```

That is where real production log rotation becomes more interesting.

# 1. Project Scenario

Imagine you support an application called VERIQTA.

The application writes to:

```text
/var/log/veriqta/application.log
```

You run:

```bash
du -h /var/log/veriqta/application.log
```

and see:

```text
8.7G    /var/log/veriqta/application.log
```

The `/var` filesystem is now:

```text
91% full
```

You could delete the file.

But that would be reckless.

You need to know:

* Is the application actively writing to it?
* Will deleting it actually free the space?
* Does the application reopen the file after rotation?
* Should the process receive a signal?
* Should the service be restarted?
* How many old logs should be kept?
* Should they be compressed?
* What happens if compression fails?

This project will build the core logic behind a simple log-rotation system.

Then we will compare it with Linux `logrotate`.


```bash

```

```bash

```

```bash

```

```text
application.log
application.log.1.gz
application.log.2.gz
application.log.3.gz
```

---

# 14. Rotate Old Archives Backwards

This is important.

If you rename:

```text
.1 -> .2
```

before:

```text
.2 -> .3
```

you may overwrite an existing archive.

So rotate from highest number downward.

Example with retention 3:

```text
.3 removed

.2 -> .3

.1 -> .2

current -> .1
```

---

# 15. Use a Backward Loop

For retention:

```bash
RETENTION_COUNT=3
```

we can loop:

```bash
for ((i=RETENTION_COUNT; i>=1; i--)); do
    echo "$i"
done
```

Output:

```text
3
2
1
```

That is the direction we need.

---

# 16. Handle the Oldest Archive

If retention is 3:

```text
application.log.3.gz
```

is the oldest allowed archive.

Before rotating:

```text
.2 -> .3
```

we should remove the old `.3`.

Only if it matches exactly what we expect.

Example:

```bash
rm -f -- "${LOG_FILE}.3.gz"
```

This is safer than deleting broad wildcard patterns.

---

# 17. Build the Archive-Rotation Function

Use:

```bash
rotate_archives() {

    local i
    local current
    local next

    rm -f -- "${LOG_FILE}.${RETENTION_COUNT}.gz"

    for ((i=RETENTION_COUNT-1; i>=1; i--)); do

        current="${LOG_FILE}.${i}.gz"
        next="${LOG_FILE}.$((i+1)).gz"

        if [[ -f "$current" ]]; then
            mv -- "$current" "$next"
        fi

    done
}
```

---

# 20. Permission Problem

Suppose original log is:

```text
-rw-r----- veriqta veriqta application.log
```

If root rotates it and creates a new file:

```text
-rw-r--r-- root root application.log
```

the application may no longer be able to write.

So a real rotation system must preserve or explicitly set ownership and permissions.

---

# 21. Capture Ownership and Mode

Before rotation:

```bash
LOG_UID=$(stat -c '%u' "$LOG_FILE")
LOG_GID=$(stat -c '%g' "$LOG_FILE")
LOG_MODE=$(stat -c '%a' "$LOG_FILE")
```

Then after creating the new log:

```bash
chown "$LOG_UID:$LOG_GID" "$LOG_FILE"
chmod "$LOG_MODE" "$LOG_FILE"
```

This may require elevated privileges.

# 23. The Open File Descriptor Problem

This is one of the most important lessons in the project.

Imagine an application process opens:

```text
application.log
```

and keeps the file descriptor open.

You rename it:

```bash
mv application.log application.log.1
```

The application may continue writing to:

```text
application.log.1
```

because the process still holds the same open file descriptor.

Creating a new:

```text
application.log
```

does not automatically make the application start writing to it.

---

# 24. Demonstrate the Problem

Open one terminal and run:

```bash
while true; do
    echo "$(date) VERIQTA log entry" >> lab/application.log
    sleep 1
done
```

This command reopens the file on each write, so it does not perfectly demonstrate a persistent file descriptor.

A real daemon often opens the file once and keeps it open.

You can still inspect real open files using:

```bash
lsof lab/application.log
```

if `lsof` is available.

---

# 25. Applications Need a Reopen Mechanism

After rotation, some applications support:

* SIGHUP
* USR1
* Dedicated reopen command
* Service reload
* Built-in log rotation

For example, some daemons reopen logs after receiving a signal.

The correct action depends on the application.

Do not blindly restart every service.

---

# 26. Why Blind Restart Is Dangerous

This would be bad design:

```bash
systemctl restart veriqta
```

after every rotation without configuration.

A restart may:

* Cause downtime
* Drop connections
* Interrupt transactions
* Hide the root cause of another problem
* Trigger cascading failures

Rotation should not automatically restart a service unless that behavior is explicitly configured and understood.

---

# 27. Add Optional Post-Rotation Command

We can support:

```bash
./log-rotator.sh \
    --post-rotate "systemctl reload veriqta"
```

But executing arbitrary shell strings introduces security concerns.

For a learning script, we will make the feature explicit and optional.

In production, a predefined command or controlled configuration is safer.

# 28. Compression

Why compress rotated logs?

Because text logs compress well.

Example:

```text
application.log.1      500 MB
application.log.1.gz    40 MB
```

The exact reduction depends on the data.

Use:

```bash
gzip application.log.1
```

---

# 29. Compression Failure

What if:

```bash
gzip
```

fails?

Possible causes:

* Disk full
* Permission denied
* Filesystem read-only
* Process interrupted

The script must detect this.

Use:

```bash
if gzip "${LOG_FILE}.1"; then
    echo "Compression successful"
else
    echo "Compression failed" >&2
fi
```

# 30. Retention by Count

For this project:

```text
keep 3 rotated logs
```

is simpler than date-based retention.

That gives:

```text
application.log.1.gz
application.log.2.gz
application.log.3.gz
```

When the next rotation happens:

```text
.3 deleted
.2 -> .3
.1 -> .2
current -> .1.gz
```

---

# 31. Retention by Age

Another strategy is:

```text
Delete archives older than 30 days.
```

Example:

```bash
find "$LOG_DIR" \
    -maxdepth 1 \
    -type f \
    -name 'application.log.*.gz' \
    -mtime +30 \
    -print
```

Always inspect first.

Then deletion can be introduced.

---

# 32. Why Count-Based and Age-Based Policies Differ

Count-based retention:

```text
Keep 7 archives
```

means retention depends on rotation frequency.

If logs rotate hourly:

```text
7 archives = only 7 hours
```

If logs rotate weekly:

```text
7 archives = 7 weeks
```

Age-based retention is often easier to reason about operationally.

# 39. Complete Working Script

Use:

```bash
#!/usr/bin/env bash

set -u
set -o pipefail

# ------------------------------------------------------------------
# Simple Log Rotation System
# ------------------------------------------------------------------
#
# Exit codes:
#   0 = No rotation needed or rotation successful
#   1 = Rotation completed with warning
#   2 = Rotation/compression failure
#   3 = Input/configuration error
#
# ------------------------------------------------------------------

MAX_SIZE_MIB=10
MAX_SIZE_BYTES=0

RETENTION_COUNT=3
DRY_RUN=false

LOG_FILE=""

POST_ROTATE_COMMAND=""

ROTATION_STATUS="NOT REQUIRED"

SCRIPT_DIR=$(
    cd -- "$(dirname -- "${BASH_SOURCE[0]}")" &&
    pwd
)

readonly SCRIPT_DIR

SCRIPT_LOG_DIR="$SCRIPT_DIR/logs"
SCRIPT_LOG_FILE="$SCRIPT_LOG_DIR/log-rotator.log"

ORIGINAL_UID=""
ORIGINAL_GID=""
ORIGINAL_MODE=""
FILE_SIZE=0


show_help() {

    cat <<EOF
Usage:
  $0 [options] LOG_FILE

Options:
  --size N            Rotate when log reaches N MiB
  --retention N       Number of compressed archives to keep
  --dry-run           Show actions without modifying files
  --post-rotate CMD   Optional command after successful rotation
  --help              Display this help

Examples:
  $0 lab/application.log

  $0 --size 100 /var/log/veriqta/application.log

  $0 --size 50 --retention 5 application.log

  $0 --dry-run application.log
EOF
}


is_integer() {
    [[ "$1" =~ ^[0-9]+$ ]]
}


parse_arguments() {

    while [[ $# -gt 0 ]]; do

        case "$1" in

            --size)

                if [[ $# -lt 2 ]]; then
                    printf 'ERROR: --size requires a value.\n' >&2
                    exit 3
                fi

                if ! is_integer "$2" || (( $2 < 1 )); then
                    printf 'ERROR: --size must be a positive integer.\n' >&2
                    exit 3
                fi

                MAX_SIZE_MIB="$2"
                shift 2
                ;;

            --retention)

                if [[ $# -lt 2 ]]; then
                    printf 'ERROR: --retention requires a value.\n' >&2
                    exit 3
                fi

                if ! is_integer "$2" ||
                   (( $2 < 1 || $2 > 100 )); then

                    printf 'ERROR: --retention must be between 1 and 100.\n' >&2
                    exit 3
                fi

                RETENTION_COUNT="$2"
                shift 2
                ;;

            --dry-run)

                DRY_RUN=true
                shift
                ;;

            --post-rotate)

                if [[ $# -lt 2 ]]; then
                    printf 'ERROR: --post-rotate requires a command.\n' >&2
                    exit 3
                fi

                POST_ROTATE_COMMAND="$2"
                shift 2
                ;;

            --help|-h)

                show_help
                exit 0
                ;;

            --*)

                printf 'ERROR: Unknown option: %s\n' "$1" >&2
                exit 3
                ;;

            *)

                if [[ -n "$LOG_FILE" ]]; then
                    printf 'ERROR: Only one log file may be supplied.\n' >&2
                    exit 3
                fi

                LOG_FILE="$1"
                shift
                ;;
        esac
    done

    MAX_SIZE_BYTES=$((MAX_SIZE_MIB * 1024 * 1024))
}


check_dependencies() {

    local commands=(
        stat
        mv
        gzip
        touch
        chmod
        chown
        mkdir
        date
        dirname
    )

    local cmd
    local missing=0

    for cmd in "${commands[@]}"; do

        if ! command -v "$cmd" >/dev/null 2>&1; then

            printf 'ERROR: Required command missing: %s\n' \
                "$cmd" >&2

            missing=1
        fi

    done

    if (( missing != 0 )); then
        exit 3
    fi
}


log_message() {

    local level="$1"
    local message="$2"

    mkdir -p "$SCRIPT_LOG_DIR"

    printf '[%s] [%s] %s\n' \
        "$(date '+%Y-%m-%d %H:%M:%S')" \
        "$level" \
        "$message" \
        >> "$SCRIPT_LOG_FILE"
}


validate_log_file() {

    local parent_dir

    if [[ -z "$LOG_FILE" ]]; then

        printf 'ERROR: Log file is required.\n\n' >&2
        show_help
        exit 3
    fi

    if [[ ! -f "$LOG_FILE" ]]; then

        printf 'ERROR: Log file does not exist: %s\n' \
            "$LOG_FILE" >&2

        exit 3
    fi

    if [[ ! -r "$LOG_FILE" ]]; then

        printf 'ERROR: Log file is not readable: %s\n' \
            "$LOG_FILE" >&2

        exit 3
    fi

    parent_dir=$(dirname "$LOG_FILE")

    if [[ ! -w "$parent_dir" ]]; then

        printf 'ERROR: Log directory is not writable: %s\n' \
            "$parent_dir" >&2

        exit 3
    fi
}


capture_metadata() {

    ORIGINAL_UID=$(stat -c '%u' "$LOG_FILE")
    ORIGINAL_GID=$(stat -c '%g' "$LOG_FILE")
    ORIGINAL_MODE=$(stat -c '%a' "$LOG_FILE")
}


get_file_size() {

    FILE_SIZE=$(stat -c '%s' "$LOG_FILE")
}


rotation_required() {

    if (( FILE_SIZE >= MAX_SIZE_BYTES )); then
        return 0
    fi

    return 1
}


remove_oldest_archive() {

    local oldest="${LOG_FILE}.${RETENTION_COUNT}.gz"

    if [[ ! -f "$oldest" ]]; then
        return
    fi

    if [[ "$DRY_RUN" == true ]]; then

        printf 'DRY RUN: Would remove %s\n' "$oldest"
        return
    fi

    if rm -f -- "$oldest"; then

        log_message \
            "INFO" \
            "Removed oldest archive: $oldest"

    else

        log_message \
            "ERROR" \
            "Unable to remove oldest archive: $oldest"

        printf 'ERROR: Unable to remove oldest archive.\n' >&2
        exit 2
    fi
}


shift_archives() {

    local i
    local current
    local next

    for ((i=RETENTION_COUNT-1; i>=1; i--)); do

        current="${LOG_FILE}.${i}.gz"
        next="${LOG_FILE}.$((i+1)).gz"

        if [[ ! -f "$current" ]]; then
            continue
        fi

        if [[ "$DRY_RUN" == true ]]; then

            printf 'DRY RUN: Would move %s -> %s\n' \
                "$current" \
                "$next"

            continue
        fi

        if mv -- "$current" "$next"; then

            log_message \
                "INFO" \
                "Shifted archive: $current -> $next"

        else

            log_message \
                "ERROR" \
                "Failed shifting archive: $current"

            printf 'ERROR: Unable to shift rotated archive.\n' >&2
            exit 2
        fi

    done
}


rotate_active_log() {

    local rotated="${LOG_FILE}.1"

    if [[ "$DRY_RUN" == true ]]; then

        printf 'DRY RUN: Would move %s -> %s\n' \
            "$LOG_FILE" \
            "$rotated"

        printf 'DRY RUN: Would create new %s\n' \
            "$LOG_FILE"

        printf 'DRY RUN: Would gzip %s\n' \
            "$rotated"

        return
    fi

    if ! mv -- "$LOG_FILE" "$rotated"; then

        log_message \
            "ERROR" \
            "Unable to rotate active log"

        printf 'ERROR: Unable to rotate active log.\n' >&2
        exit 2
    fi

    if ! touch "$LOG_FILE"; then

        printf 'ERROR: Unable to create new active log.\n' >&2
        exit 2
    fi

    if ! chmod "$ORIGINAL_MODE" "$LOG_FILE"; then

        log_message \
            "WARNING" \
            "Unable to restore original mode on new log"
    fi

    if ! chown "$ORIGINAL_UID:$ORIGINAL_GID" "$LOG_FILE" 2>/dev/null; then

        log_message \
            "WARNING" \
            "Unable to restore original ownership on new log"
    fi

    if gzip "$rotated"; then

        log_message \
            "INFO" \
            "Compressed rotated log: ${rotated}.gz"

    else

        log_message \
            "ERROR" \
            "Compression failed: $rotated"

        printf 'ERROR: Compression failed.\n' >&2
        exit 2
    fi
}


run_post_rotate() {

    if [[ -z "$POST_ROTATE_COMMAND" ]]; then
        return
    fi

    if [[ "$DRY_RUN" == true ]]; then

        printf 'DRY RUN: Would run post-rotate command: %s\n' \
            "$POST_ROTATE_COMMAND"

        return
    fi

    printf 'Running configured post-rotation command...\n'

    if bash -c "$POST_ROTATE_COMMAND"; then

        log_message \
            "INFO" \
            "Post-rotation command completed"

    else

        log_message \
            "WARNING" \
            "Post-rotation command failed"

        ROTATION_STATUS="WARNING"
    fi
}


print_report() {

    printf '\n%s\n' \
        "=========================================================================="

    printf '%s\n' \
        "                       LOG ROTATION REPORT"

    printf '%s\n' \
        "=========================================================================="

    printf '%-24s %s\n' \
        "Log File:" "$LOG_FILE"

    printf '%-24s %s bytes\n' \
        "Current Size:" "$FILE_SIZE"

    printf '%-24s %s MiB\n' \
        "Rotation Threshold:" "$MAX_SIZE_MIB"

    printf '%-24s %s\n' \
        "Retention Count:" "$RETENTION_COUNT"

    printf '%-24s %s\n' \
        "Dry Run:" "$DRY_RUN"

    printf '%-24s %s\n' \
        "Rotation Status:" "$ROTATION_STATUS"

    printf '%s\n' \
        "=========================================================================="
}


main() {

    parse_arguments "$@"

    check_dependencies

    validate_log_file

    capture_metadata

    get_file_size

    log_message \
        "INFO" \
        "Checked log=$LOG_FILE size=$FILE_SIZE threshold=$MAX_SIZE_BYTES"

    if ! rotation_required; then

        ROTATION_STATUS="NOT REQUIRED"

        printf 'Log size is below the rotation threshold.\n'

        print_report
        return 0
    fi

    ROTATION_STATUS="SUCCESS"

    printf 'Rotation threshold reached.\n'

    remove_oldest_archive

    shift_archives

    rotate_active_log

    run_post_rotate

    print_report

    log_message \
        "INFO" \
        "Rotation completed with status=$ROTATION_STATUS"

    if [[ "$ROTATION_STATUS" == "WARNING" ]]; then
        return 1
    fi

    return 0
}


main "$@"
exit $?
```

# 54. Why `copytruncate` Exists

Some applications cannot reopen their log files.

A different strategy is:

```text
Copy current log
      |
      v
Compress copy
      |
      v
Truncate original log to zero bytes
```

The application keeps the same file descriptor because the original file remains.

This pattern is known as:

```text
copytruncate
```

Linux `logrotate` supports it.

---

# 56. Why `copytruncate` Is Not Perfect

There is a race.

Between:

```text
copy
```

and:

```text
truncate
```

the application may write additional log lines.

Those lines can be:

* Lost
* Duplicated

depending on timing.

So `copytruncate` is a compromise.

It is often used when the application cannot reopen logs cleanly.

```text
Rename active log
      |
      v
Signal application
      |
      v
Application reopens new log
```

is generally cleaner.

But only if the application supports it correctly.

# 58. Detect Open Deleted Files


```text

```

The process is still holding the storage.

---

# 59. Why Deleted Logs Can Still Consume Space

Linux separates:

```text
filename
```

from:

```text
open file descriptor
```

A process may continue accessing the inode even after the directory entry is removed.

Disk blocks are finally reclaimed when the last reference closes.

This is why random deletion is not a proper rotation strategy.

# 131. Final Test

Check syntax:

```bash
bash -n log-rotator.sh
```

Create test data:

```bash
yes "VERIQTA application test entry" |
head -n 50000 \
    >> lab/application.log
```

Dry run:

```bash
./log-rotator.sh \
    --size 1 \
    --dry-run \
    lab/application.log
```

Perform real rotation:

```bash
./log-rotator.sh \
    --size 1 \
    --retention 3 \
    lab/application.log
```

Inspect:

```bash
ls -lh lab/
```

Verify compression:

```bash
gzip -t lab/application.log.1.gz
```

Inspect contents:

```bash
zcat lab/application.log.1.gz |
head
```

Check script logs:

```bash
tail -n 20 logs/log-rotator.log
```

Repeat until retention behavior is proven.

Then build and debug the equivalent `logrotate` configuration:

```bash
logrotate -d logrotate-lab.conf
```

If the script correctly detects size, rotates safely, compresses old files, enforces retention, avoids destructive broad deletion, supports dry run, and you understand how open file descriptors affect real applications, the project is complete.
