# Project 20: Incident Diagnostics Collector

## Capstone Project: Build a Production Incident Evidence Collection Tool

This is the major project of the Bash Projects for DevOps Engineers curriculum.

An application becomes unavailable.

Users report:

```text
The website is down.
```

Monitoring reports:

```text
HTTP 503
```

You SSH into the affected Linux server.

Without an incident collector, you may start manually running:

```bash
uptime
free -h
df -h
df -i
ps aux
ss -lntup
ip addr
ip route
systemctl --failed
journalctl
dmesg
docker ps
docker system df
kubectl get nodes
kubectl get pods -A
```

Then you copy commands into Slack.

You forget some output.

The system changes while you investigate.

A service restarts.

A pod disappears.

Logs rotate.

The evidence you needed is gone.

Instead, we are going to build:

```text
incident-collector.sh
```

An engineer runs:

```bash
sudo ./incident-collector.sh
```

and receives:

```text
incident-web01-20260911-020533.tar.gz
```

containing a structured snapshot of the system at the time of investigation.

Example:

```text
incident-web01-20260911-020533/
|
|-- README.txt
|-- manifest.sha256
|-- collection-status.txt
|
|-- system.txt
|-- cpu.txt
|-- memory.txt
|-- disk.txt
|-- network.txt
|-- services.txt
|
|-- logs/
|   |-- journal.txt
|   |-- kernel.txt
|   `-- application/
|
|-- docker/
|   |-- docker.txt
|   `-- container-logs/
|
`-- kubernetes/
    `-- kubernetes.txt
```

The central engineering principle is:

```text
COLLECT FIRST.
ANALYZE SECOND.
REMEDIATE THIRD.
```

During an incident, evidence can disappear.

Preserve the evidence before making changes whenever operational conditions allow it.

# 3. What This Tool Is Not

This is not:

```text
an auto-remediation tool
```

It must not automatically run:

```bash
systemctl restart
systemctl stop
kill
kill -9
reboot
shutdown
rm
docker restart
docker stop
docker system prune
docker rm
kubectl delete
kubectl rollout restart
kubectl scale
kubectl drain
kubectl cordon
```

The collector observes.

It does not repair.

That separation is intentional.

---

# 4. Why Read-Only Matters

Suppose CPU is 100%.

A weak script might decide:

```text
kill highest CPU process
```

But that process could be:

```text
database
payment service
security agent
backup process
critical worker
```

Suppose a Kubernetes pod is unhealthy.

Automatically deleting it may destroy evidence.

Suppose Docker storage is full.

Automatically running:

```bash
docker system prune -af
```

may remove rollback images.

The collector should tell you:

```text
what is happening
```

not decide:

```text
what should be destroyed.
```

# 6. Security Requirement

The most important constraint is:

```text
THE INCIDENT BUNDLE MUST NOT BECOME A SECRET-DUMPING TOOL.
```

Do not intentionally collect:

```text
passwords
API keys
access tokens
refresh tokens
private SSH keys
cloud credentials
Kubernetes Secrets
Docker registry credentials
environment variables
application secret files
database passwords
service-account tokens
```

This means we deliberately avoid commands such as:

```bash
env
printenv
cat /proc/*/environ
docker inspect
kubectl get secrets
kubectl describe secret
aws configure export-credentials
cat ~/.aws/credentials
cat ~/.ssh/id_rsa
```

even though they might contain useful debugging information.

Security boundaries matter during incidents too.

# 7. Incident Bundle Permissions

Before collecting anything:

```bash
umask 077
```

The working directory and archive should be readable only by the owner unless intentionally shared.

Expected:

```text
-rw------- incident-web01-20260911-020533.tar.gz
```

Incident bundles frequently contain sensitive operational information even after secrets are excluded.

# 8. Information We Will Collect

The collector has eight major domains:

```text
1. System
2. CPU
3. Memory
4. Disk
5. Network
6. Services
7. Logs
8. Container / Kubernetes context
```

Each domain gets its own output.

# 9. System Information

Collect:

```text
hostname
UTC date
local date
uptime
kernel
architecture
OS version
boot ID
current user
effective user
```

Commands include:

```bash
hostname
date
uptime
uname
cat /etc/os-release
```

This establishes:

```text
Where did this evidence come from?
When was it collected?
What system was running?
How long had it been running?
```

---

# 10. CPU Diagnostics

Collect:

```text
logical CPU count
CPU model
CPU utilization sample
load average
top CPU-consuming processes
```

Commands:

```bash
nproc
lscpu
uptime
ps
```

We will also sample:

```text
/proc/stat
```

to calculate CPU utilization.

Do not confuse:

```text
CPU utilization
```

with:

```text
load average.
```

Linux load average represents runnable tasks plus tasks in certain uninterruptible states, including work waiting for I/O.

Therefore:

```text
high load != automatically high CPU
```

A system with severe disk I/O pressure can have high load without CPUs being fully utilized.

---

# 11. Memory Diagnostics

Collect:

```text
total memory
available memory
memory usage
swap usage
top memory-consuming processes
```

Commands:

```bash
free -h
free -b
ps
```

Also preserve:

```text
/proc/meminfo
```

because it provides deeper context.

Do not interpret:

```text
low free memory
```

alone as:

```text
memory exhausted.
```

Linux intentionally uses memory for caching.

`MemAvailable` is generally more useful when estimating memory pressure.

---

# 12. Disk Diagnostics

Collect:

```text
filesystem usage
inode usage
mount information
largest directories
```

Commands:

```bash
df -hP
df -iP
findmnt
du
```

Why inodes?

A filesystem can report:

```text
Disk Usage: 45%
```

and still fail to create files because:

```text
Inodes: 100%
```

That can cause:

```text
application failures
log failures
package failures
container failures
temporary-file failures
```

---

# 13. Largest Directories

Running:

```bash
du -xhd1 /
```

across a large production server can be expensive.

Therefore this collector does not blindly recursively scan the entire filesystem.

Instead, large-directory inspection is:

```text
optional
bounded
configurable
```

Example:

```bash
sudo ./incident-collector.sh \
    --largest /var
```

or:

```bash
sudo ./incident-collector.sh \
    --largest /var/log
```

This is safer than an uncontrolled filesystem crawl during an incident.

# 15. DNS Configuration

Collect:

```text
/etc/resolv.conf
```

but be careful.

Resolver configuration can expose internal:

```text
DNS servers

```

That is acceptable for a protected incident bundle but reinforces why the archive must not be public.

If `resolvectl` exists, collect:

```bash
resolvectl status
```

as additional resolver context.

# 16. Services

Collect:

```text
failed systemd units
failed services
service status
```

Commands:

```bash
systemctl --failed
systemctl --failed --type=service
```

For failed services, capture:

```bash
systemctl status SERVICE
```

and recent journal entries.

This connects directly to Project 18.

# 17. Logs

Logs are essential but dangerous.

We want:

```text
recent relevant evidence
```

not:

```text
every log ever generated.
```

Default collection window:

```text
30 minutes
```

Configurable:

```bash
sudo ./incident-collector.sh \
    --since "60 minutes ago"
```

Collect:

```text
system journal
kernel journal
selected application logs
```

# 18. Journal Collection

Example:

```bash
journalctl \
    --since "30 minutes ago" \
    --no-pager
```

Kernel:

```bash
journalctl \
    -k \
    --since "30 minutes ago" \
    --no-pager
```

Failed service:

```bash
journalctl \
    -u nginx.service \
    --since "30 minutes ago" \
    --no-pager
```

Bound the collection.

Do not collect months of logs during an outage unless you actually need them.

---

# 19. `dmesg`

Kernel evidence can reveal:

```text
OOM kills
disk errors
filesystem errors
NIC problems
driver failures
kernel warnings
```

Collect:

```bash
dmesg \
    --ctime
```

where supported.

If permissions deny access:

```text
record the collection failure
```

rather than pretending the check succeeded.

---

# 20. Application Logs

Application logs cannot safely be discovered automatically.

Why?

Because blindly searching:

```text
/var
/opt
/home
```

could collect:

```text
credentials
customer data
large files
private application data
```

Instead, application log paths must be explicitly supplied.

Example:

```bash
sudo ./incident-collector.sh \
    --app-log /var/log/veriqta/payments-api.log
```

Multiple:

```bash
sudo ./incident-collector.sh \
    --app-log /var/log/veriqta/payments-api.log \
    --app-log /var/log/nginx/error.log
```

The collector takes only the last configured number of lines.

Default:

```text
500 lines
```

# 21. Docker Diagnostics

```bash
command -v docker
```

succeeds and the daemon is accessible, collect:

```text
Docker version
Docker system information summary
containers
container state
container health
Docker disk usage
bounded logs for selected containers
```

Use:

```bash
docker ps -a

```

Do not use:

```bash
docker inspect
```

by default because inspection output can include environment variables and other configuration that may contain secrets.

---

# 22. Docker Logs

Do not run:

```bash
docker logs container
```

without limits.

A long-running container may produce enormous output.

Instead:

```bash
docker logs \
    --since 30m \
    --tail 500 \
    container
```

The collector should focus on:

```text
running
restarting
unhealthy
recently exited
```

containers.

Still, Docker logs themselves can contain secrets if the application improperly logs them.

Therefore they must pass through our redaction layer before being packaged.

---

# 23. Kubernetes Diagnostics

If:

```bash
kubectl
```

exists, that does not automatically mean Kubernetes should be queried.

First determine:

```text
Is a context configured?
Can the API be reached?
```

Collect read-only resource summaries:

```bash
kubectl get nodes -o wide
kubectl get pods -A -o wide
kubectl get deployments -A
kubectl get events -A
```

Do not collect:

```bash
kubectl get secrets
```

Do not run:

```bash
kubectl get pods -A -o yaml
```

by default.

Full YAML can expose environment references, annotations, configuration, and operational details that we do not need for the first diagnostic snapshot.

---

# 24. Kubernetes Scope

Cluster-wide access may not be permitted.

Therefore support:

```bash
sudo ./incident-collector.sh \
    --k8s-namespace production
```

Then collect namespace resources from:

```text
production
```

Nodes remain cluster-scoped and may return:

```text
Forbidden
```

under namespace-only RBAC.

That is not the same as:

```text
cluster has zero nodes.
```

Collection failures must be explicitly recorded.

---

# 25. Kubernetes Context Safety

Before collection, record:

```bash
kubectl config current-context
```

Do not automatically switch contexts.

For production use, support:

```bash
--k8s-context
```

Example:

```bash
sudo ./incident-collector.sh \
    --k8s-context production-cluster \
    --k8s-namespace payments
```

Every Kubernetes command then uses that explicit context.

This prevents a diagnostic command from accidentally querying the wrong cluster.

---

# 26. Root and `sudo`

The user scenario is:

```bash
sudo ./incident-collector.sh
```

Root access can improve visibility into:

```text
system logs
kernel logs
systemd
ports
application logs
Docker
```

But root creates a new problem.

If Kubernetes credentials belong to the normal engineer account, running:

```bash
sudo kubectl ...
```

may use:

```text
/root/.kube/config
```

instead of the engineer's kubeconfig.

Therefore the script should not assume root's Kubernetes configuration represents the intended cluster.

Use an explicit:

```text
--kubeconfig
```

or run Kubernetes collection separately when necessary.

---

# 27. Collection Failures Must Not Be Hidden

Suppose:

```bash
journalctl
```

fails.

A bad collector creates:

```text
logs/journal.txt
```

with zero bytes.

An engineer may assume:

```text
There were no logs.
```

That is dangerous.

Instead record:

```text
COLLECTION ERROR

Command: journalctl
Status: FAILED
Exit Code: 1
```

We will maintain:

```text
collection-status.txt
```

containing every section's result.

# 29. Exit Codes

Use:

```text
0 = collection completed successfully

1 = collection completed with warnings or optional sections unavailable

2 = important diagnostic collection failed but bundle was still created

3 = invalid arguments, dependency failure, or unsafe configuration

4 = packaging/integrity failure
```

A production incident collector should attempt to preserve partial evidence when possible.

One failed optional command should not destroy everything already collected.

# 31. Basic Version First

Before building the capstone version, create a simple collector:

```bash
#!/usr/bin/env bash

set -u
set -o pipefail

umask 077

HOSTNAME="$(hostname -s)"
TIMESTAMP="$(date -u '+%Y%m%d-%H%M%S')"

INCIDENT_DIR="incident-${HOSTNAME}-${TIMESTAMP}"

mkdir -p \
    "$INCIDENT_DIR/logs"


{
    echo "HOSTNAME"
    hostname

    echo
    echo "DATE"
    date -u

    echo
    echo "UPTIME"
    uptime

    echo
    echo "KERNEL"
    uname -a

    echo
    echo "OS"
    cat /etc/os-release

} > "$INCIDENT_DIR/system.txt"


{
    echo "LOAD"
    uptime

    echo
    echo "TOP CPU PROCESSES"

    ps \
        -eo pid,user,comm,%cpu,%mem \
        --sort=-%cpu |
    head -n 20

} > "$INCIDENT_DIR/cpu.txt"


{
    echo "MEMORY"
    free -h

    echo
    echo "TOP MEMORY PROCESSES"

    ps \
        -eo pid,user,comm,%mem,%cpu \
        --sort=-%mem |
    head -n 20

} > "$INCIDENT_DIR/memory.txt"


{
    echo "DISK"
    df -hP

    echo
    echo "INODES"
    df -iP

} > "$INCIDENT_DIR/disk.txt"


{
    echo "IP ADDRESSES"
    ip addr

    echo
    echo "ROUTES"
    ip route

    echo
    echo "LISTENING PORTS"
    ss -lntup

} > "$INCIDENT_DIR/network.txt"


systemctl \
    --failed \
    > "$INCIDENT_DIR/services.txt"


journalctl \
    --since "30 minutes ago" \
    --no-pager \
    > "$INCIDENT_DIR/logs/journal.txt"


tar \
    -czf "${INCIDENT_DIR}.tar.gz" \
    "$INCIDENT_DIR"


printf 'Incident bundle: %s.tar.gz\n' \
    "$INCIDENT_DIR"
```

Run:

```bash
sudo ./incident-collector.sh
```

That is already useful.

But it is not yet production-ready.

Now we build the real capstone.

# 33. Complete Production-Oriented Script

```bash
#!/usr/bin/env bash

set -u
set -o pipefail

umask 077


# ==================================================================
# Incident Diagnostics Collector
# ==================================================================
#
# Read-only evidence collector for Linux production incidents.
#
# Exit codes:
#
#   0 = successful collection
#   1 = completed with warnings / optional sections unavailable
#   2 = important diagnostic collection failure
#   3 = argument / configuration / dependency error
#   4 = packaging / integrity failure
#
# SECURITY:
#
#   This script deliberately avoids:
#
#   - environment-variable dumps
#   - Docker inspect
#   - Kubernetes Secrets
#   - SSH private keys
#   - cloud credential files
#   - arbitrary home-directory collection
#
# ==================================================================


# ------------------------------------------------------------------
# Defaults
# ------------------------------------------------------------------

OUTPUT_DIR="."

TOP_COUNT=15

LARGEST_DEPTH=1

ENABLE_DOCKER_LOGS=false

ENABLE_REDACTION=true

K8S_CONTEXT=""

K8S_NAMESPACE=""

KUBECONFIG_PATH=""

declare -a APP_LOGS=()

declare -a LARGEST_PATHS=()

# ------------------------------------------------------------------
# Runtime state
# ------------------------------------------------------------------

HOST_SHORT=""

INCIDENT_ID=""

WORK_DIR=""

README_FILE=""

MANIFEST_FILE=""

TMP_DIR=""

# ------------------------------------------------------------------
# Exit severity
# ------------------------------------------------------------------
#
# 0 = success
# 1 = warning
# 2 = collection failure
# 3 = configuration error
# 4 = packaging failure

# ------------------------------------------------------------------
# Utility functions
# ------------------------------------------------------------------

is_positive_integer() {

    [[ "$1" =~ ^[1-9][0-9]*$ ]]
}


sanitize_filename() {

    printf '%s' "$1" |
    tr -c 'A-Za-z0-9._-' '_'
}


section_header() {

    local title="$1"

    printf '\n'
    printf '%s\n' \
        "========================================================================"

    printf '%s\n' \
        "$title"

    printf '%s\n' \
        "========================================================================"

    printf '\n'
}


update_level() {

    local new_level="$1"

    if (( new_level > OVERALL_LEVEL )); then
        OVERALL_LEVEL="$new_level"
    fi
}


record_status() {

    local component="$1"
    local status="$2"
    local detail="${3:-}"

    printf '%-24s %-10s %s\n' \
        "$component" \
        "$status" \
        "$detail" \
        >> "$STATUS_FILE"


    case "$status" in

        OK)

            printf '[OK] %s\n' \
                "$component"
            ;;

        SKIPPED)

            printf '[SKIP] %s%s\n' \
                "$component" \
                "${detail:+ - $detail}"

            update_level 1
            ;;

        WARNING)

            printf '[WARN] %s%s\n' \
                "$component" \
                "${detail:+ - $detail}"

            update_level 1
            ;;

        FAILED)

            printf '[FAILED] %s%s\n' \
                "$component" \
                "${detail:+ - $detail}"

            update_level 2
            ;;
    esac
}


command_exists() {

    command -v "$1" \
        >/dev/null 2>&1
}


write_command() {

    local output_file="$1"
    local title="$2"

    shift 2


    {
        section_header "$title"

        printf 'Command:'

        printf ' %q' "$@"

        printf '\n\n'

    } >> "$output_file"


    "$@" \
        >> "$output_file" \
        2>&1

    local rc=$?


    {
        printf '\n'
        printf 'Exit Code: %s\n' \
            "$rc"
    } >> "$output_file"


    return "$rc"
}


write_shell_pipeline() {

    local output_file="$1"
    local title="$2"
    local command_text="$3"


    {
        section_header "$title"

        printf 'Diagnostic Pipeline:\n%s\n\n' \
            "$command_text"

    } >> "$output_file"


    bash \
        -o pipefail \
        -c "$command_text" \
        >> "$output_file" \
        2>&1

    local rc=$?


    printf '\nExit Code: %s\n' \
        "$rc" \
        >> "$output_file"


    return "$rc"
}

# ------------------------------------------------------------------
# Arguments
# ------------------------------------------------------------------

parse_arguments() {

    while [[ $# -gt 0 ]]; do

        case "$1" in

            --output-dir)

                [[ $# -ge 2 ]] || {
                    printf 'ERROR: --output-dir requires a value.\n' >&2
                    exit 3
                }

                OUTPUT_DIR="$2"

                shift 2
                ;;


            --since)

                [[ $# -ge 2 ]] || {
                    printf 'ERROR: --since requires a value.\n' >&2
                    exit 3
                }

                SINCE="$2"

                shift 2
                ;;


            --top)

                [[ $# -ge 2 ]] || {
                    printf 'ERROR: --top requires a value.\n' >&2
                    exit 3
                }

                TOP_COUNT="$2"

                shift 2
                ;;


            --app-log)

                [[ $# -ge 2 ]] || {
                    printf 'ERROR: --app-log requires a path.\n' >&2
                    exit 3
                }

                APP_LOGS+=("$2")

                shift 2
                ;;


            --largest)

                [[ $# -ge 2 ]] || {
                    printf 'ERROR: --largest requires a path.\n' >&2
                    exit 3
                }

                LARGEST_PATHS+=("$2")

                shift 2
                ;;


            --largest-depth)

                [[ $# -ge 2 ]] || {
                    printf 'ERROR: --largest-depth requires a number.\n' >&2
                    exit 3
                }

                LARGEST_DEPTH="$2"

                shift 2
                ;;


            --docker-logs)

                ENABLE_DOCKER_LOGS=true

                shift
                ;;


            --docker-container)

                [[ $# -ge 2 ]] || {
                    printf 'ERROR: --docker-container requires a name.\n' >&2
                    exit 3
                }

                DOCKER_CONTAINERS+=("$2")

                ENABLE_DOCKER_LOGS=true

                shift 2
                ;;


            --kubernetes)

                ENABLE_KUBERNETES=true

                shift
                ;;


            --no-kubernetes)

                ENABLE_KUBERNETES=false

                shift
                ;;


            --k8s-context)

                [[ $# -ge 2 ]] || {
                    printf 'ERROR: --k8s-context requires a value.\n' >&2
                    exit 3
                }

                K8S_CONTEXT="$2"

                shift 2
                ;;


            --k8s-namespace)

                [[ $# -ge 2 ]] || {
                    printf 'ERROR: --k8s-namespace requires a value.\n' >&2
                    exit 3
                }

                K8S_NAMESPACE="$2"

                shift 2
                ;;


            --kubeconfig)

                [[ $# -ge 2 ]] || {
                    printf 'ERROR: --kubeconfig requires a path.\n' >&2
                    exit 3
                }

                KUBECONFIG_PATH="$2"

                shift 2
                ;;


            --redact)

                ENABLE_REDACTION=true

                shift
                ;;


            --no-redact)

                ENABLE_REDACTION=false

                shift
                ;;


            --keep-directory)

                KEEP_DIRECTORY=true

                shift
                ;;


            --help|-h)

                show_help

                exit 0
                ;;


            *)

                printf 'ERROR: Unknown option: %s\n' \
                    "$1" >&2

                exit 3
                ;;
        esac
    done
}


validate_arguments() {

    if ! is_positive_integer "$TOP_COUNT"; then

        printf 'ERROR: --top must be a positive integer.\n' >&2

        exit 3
    fi


    if ! is_positive_integer "$LARGEST_DEPTH"; then

        printf 'ERROR: --largest-depth must be a positive integer.\n' >&2

        exit 3
    fi


    if [[ -n "$KUBECONFIG_PATH" &&
          ! -r "$KUBECONFIG_PATH" ]]; then

        printf 'ERROR: kubeconfig is not readable: %s\n' \
            "$KUBECONFIG_PATH" >&2

        exit 3
    fi


    local path

    for path in "${LARGEST_PATHS[@]}"; do

        if [[ ! -d "$path" ]]; then

            printf 'ERROR: --largest path is not a directory: %s\n' \
                "$path" >&2

            exit 3
        fi
    done
}

# ------------------------------------------------------------------
# CPU collection
# ------------------------------------------------------------------

calculate_cpu_usage() {

    local cpu1
    local cpu2

    cpu1="$(
        awk '/^cpu / {print}' /proc/stat
    )"

    sleep 1

    cpu2="$(
        awk '/^cpu / {print}' /proc/stat
    )"


    awk \
        -v first="$cpu1" \
        -v second="$cpu2" '
        BEGIN {

            split(first, a, " ")
            split(second, b, " ")

            idle1 = a[5] + a[6]
            idle2 = b[5] + b[6]

            total1 = 0
            total2 = 0

            for (i = 2; i <= length(a); i++) {
                total1 += a[i]
            }

            for (i = 2; i <= length(b); i++) {
                total2 += b[i]
            }

            total_delta = total2 - total1
            idle_delta = idle2 - idle1

            if (total_delta <= 0) {
                print "Unavailable"
                exit
            }

            usage = 100 * (total_delta - idle_delta) / total_delta

            printf "%.2f%%\n", usage
        }
    '
}


collect_cpu() {

    local output="$WORK_DIR/cpu.txt"

    : > "$output"


    {
        section_header \
            "CPU DIAGNOSTICS"

        printf 'CPU Utilization Sample:\n'

        if [[ -r /proc/stat ]]; then

            calculate_cpu_usage

        else

            printf 'Unavailable: /proc/stat cannot be read\n'
        fi


        printf '\nLOAD AVERAGE\n'

        uptime


        if [[ -r /proc/loadavg ]]; then

            printf '\n/proc/loadavg\n'

            cat \
                /proc/loadavg
        fi


        if command_exists nproc; then

            printf '\nLOGICAL CPUs\n'

            nproc
        fi


        if command_exists lscpu; then

            printf '\nCPU DETAILS\n'

            lscpu
        fi


        printf '\nTOP CPU PROCESSES\n'

        ps \
            -eo pid,ppid,user,stat,etime,comm,%cpu,%mem \
            --sort=-%cpu |
        head -n "$((TOP_COUNT + 1))"

    } >> "$output" 2>&1


    record_status \
        "cpu" \
        "OK"
}

        fi

            lsblk

                -x \
                -h \
                --max-depth="$LARGEST_DEPTH" \
                "$path" \
                2>&1 |
            sort -hr |
            head -n 30

        } >> "$output"
    done


    record_status \
        "disk" \
        "OK"
}

collect_services() {

    local output="$WORK_DIR/services.txt"

    : > "$output"


    if ! command_exists systemctl; then

        printf 'systemctl is not installed.\n' \
            > "$output"

        record_status \
            "services" \
            "SKIPPED" \
            "systemctl unavailable"

        return
    fi


    {
        section_header \
            "SYSTEMD SERVICE DIAGNOSTICS"

        printf 'FAILED UNITS\n\n'

        systemctl \
            --failed \
            --no-pager

        printf '\nFAILED SERVICES\n\n'

        systemctl \
            --failed \
            --type=service \
            --no-pager

    } >> "$output" 2>&1


    local failed_services=()


    mapfile -t failed_services < <(
        systemctl \
            --failed \
            --type=service \
            --no-legend \
            --plain \
            2>/dev/null |
        awk '{print $1}'
    )


    local service


    for service in "${failed_services[@]}"; do

        [[ -n "$service" ]] || continue


        {
            section_header \
                "FAILED SERVICE: $service"

            printf 'STATUS\n\n'

            systemctl \
                status \
                "$service" \
                --no-pager \
                -l \
                2>&1 \
                || true


            if command_exists journalctl; then

                printf '\nRECENT JOURNAL\n\n'

                journalctl \
                    -u "$service" \
                    --since "$SINCE" \
                    --no-pager \
                    2>&1 \
                    || true
            fi

        } >> "$output"
    done


    record_status \
        "services" \
        "OK"
}

    : > "$output"

    local collected=false


    if command_exists journalctl; then

        {
            section_header \
                "KERNEL JOURNAL"

            journalctl \
                -k \
                --since "$SINCE" \
                --no-pager

        } >> "$output" 2>&1 && collected=true
    fi


    if command_exists dmesg; then

        {
            section_header \
                "DMESG"

            if ! dmesg \
                --ctime \
                2>&1; then

                printf '\nFalling back to plain dmesg:\n\n'

                dmesg \
                    2>&1 \
                    || true
            fi

        } >> "$output"

        collected=true
    fi


    if [[ "$collected" == true ]]; then

        record_status \
            "kernel" \
            "OK"

    else

        record_status \
            "kernel" \
            "SKIPPED" \
            "no kernel log command available"
    fi
}


# ------------------------------------------------------------------
# Application logs
# ------------------------------------------------------------------

collect_application_logs() {

    if (( ${#APP_LOGS[@]} == 0 )); then

        record_status \
            "application-logs" \
            "SKIPPED" \
            "no approved paths supplied"

        return
    fi


    local warnings=0
    local path


    for path in "${APP_LOGS[@]}"; do

        if [[ ! -f "$path" ]]; then

            ((warnings+=1))

            continue
        fi


        if [[ ! -r "$path" ]]; then

            ((warnings+=1))

            continue
        fi


        local safe_name

        safe_name="$(
            sanitize_filename \
                "$path"
        )"


        {
            printf 'Source: %s\n' \
                "$path"

            printf 'Collected: %s\n' \
                "$(date -u '+%Y-%m-%d %H:%M:%S UTC')"

            printf 'Lines: last %s\n\n' \
                "$APP_LOG_LINES"

            tail \
                -n "$APP_LOG_LINES" \
                "$path"

        } > "$WORK_DIR/logs/application/$safe_name.txt" \
            2>&1
    done


    if (( warnings > 0 )); then

        record_status \
            "application-logs" \
            "WARNING" \
            "$warnings path(s) unavailable"

    else

        record_status \
            "application-logs" \
            "OK"
    fi
}

collect_docker() {

    local output="$WORK_DIR/docker/docker.txt"

    : > "$output"


    if ! command_exists docker; then

        printf 'Docker CLI not installed.\n' \
            > "$output"

        record_status \
            "docker" \
            "SKIPPED" \
            "docker unavailable"

        return
    fi


    if ! docker info \
        >/dev/null 2>&1; then

        printf '%s\n' \
            "Docker CLI exists, but the daemon is unavailable or access is denied." \
            > "$output"

        record_status \
            "docker" \
            "WARNING" \
            "daemon unavailable or access denied"

        return
    fi


    {
        section_header \
            "DOCKER DIAGNOSTICS"

        printf 'DOCKER VERSION\n\n'

        docker version


        printf '\nCONTAINERS\n\n'

        docker ps \
            -a \
            --no-trunc


        printf '\nCONTAINER SUMMARY\n\n'

        docker ps \
            -a \
            --format \
            'table {{.ID}}\t{{.Names}}\t{{.Image}}\t{{.State}}\t{{.Status}}\t{{.Ports}}'


        printf '\nDOCKER DISK USAGE\n\n'

        docker system df

    } >> "$output" 2>&1


    if [[ "$ENABLE_DOCKER_LOGS" == true ]]; then

        collect_docker_logs
    fi


    record_status \
        "docker" \
        "OK"
}


collect_docker_logs() {

    local selected=()


    if (( ${#DOCKER_CONTAINERS[@]} > 0 )); then

        selected=(
            "${DOCKER_CONTAINERS[@]}"
        )

    else

        mapfile -t selected < <(
            docker ps \
                -a \
                --format '{{.Names}} {{.State}} {{.Status}}' |
            awk '
                /restarting/ ||
                /exited/ ||
                /unhealthy/ {
                    print $1
                }
            '
        )
    fi


    local container


    for container in "${selected[@]}"; do

        [[ -n "$container" ]] || continue


        if ! docker container inspect \
            "$container" \
            --format '{{.Name}}' \
            >/dev/null 2>&1; then

            continue
        fi


        local safe_name

        safe_name="$(
            sanitize_filename \
                "$container"
        )"


        {
            printf 'Container: %s\n' \
                "$container"

            printf 'Collection Window: %s\n\n' \
                "$SINCE"


            # We deliberately do not use --details because additional
            # log attributes may contain data we do not need.

            docker logs \
                --since "$SINCE" \
                --tail "$APP_LOG_LINES" \
                --timestamps \
                "$container"

        } > "$WORK_DIR/docker/container-logs/$safe_name.log" \
            2>&1 \
            || true
    done
}

build_kubectl_base() {

    KUBECTL_BASE=(
        kubectl
    )


    if [[ -n "$K8S_CONTEXT" ]]; then

        KUBECTL_BASE+=(
            --context "$K8S_CONTEXT"
        )
    fi


    if [[ -n "$KUBECONFIG_PATH" ]]; then

        KUBECTL_BASE+=(
            --kubeconfig "$KUBECONFIG_PATH"
        )
    fi
}


# ------------------------------------------------------------------
# Kubernetes
# ------------------------------------------------------------------

collect_kubernetes() {

    local output="$WORK_DIR/kubernetes/kubernetes.txt"

    : > "$output"


    if [[ "$ENABLE_KUBERNETES" != true ]]; then

        printf 'Kubernetes collection disabled.\n' \
            > "$output"

        record_status \
            "kubernetes" \
            "SKIPPED" \
            "disabled"

        return
    fi


    if ! command_exists kubectl; then

        printf 'kubectl is not installed.\n' \
            > "$output"

        record_status \
            "kubernetes" \
            "SKIPPED" \
            "kubectl unavailable"

        return
    fi


    build_kubectl_base


    {
        section_header \
            "KUBERNETES DIAGNOSTICS"

        printf 'CURRENT CONTEXT\n\n'

        "${KUBECTL_BASE[@]}" \
            config current-context \
            2>&1 \
            || true

    } >> "$output"


    local namespace_args=()


    if [[ -n "$K8S_NAMESPACE" ]]; then

        namespace_args=(
            -n "$K8S_NAMESPACE"
        )

    else

        namespace_args=(
            -A
        )
    fi


    local success=0
    local failure=0


    {
        section_header \
            "NODES"

        if "${KUBECTL_BASE[@]}" \
            get nodes \
            -o wide; then

            ((success+=1))

        else

            ((failure+=1))
        fi

    } >> "$output" 2>&1


    {
        section_header \
            "PODS"

        if "${KUBECTL_BASE[@]}" \
            get pods \
            "${namespace_args[@]}" \
            -o wide; then

            ((success+=1))

        else

            ((failure+=1))
        fi

    } >> "$output" 2>&1


    {
        section_header \
            "DEPLOYMENTS"

        if "${KUBECTL_BASE[@]}" \
            get deployments \
            "${namespace_args[@]}" \
            -o wide; then

            ((success+=1))

        else

            ((failure+=1))
        fi

    } >> "$output" 2>&1


    {
        section_header \
            "EVENTS"

        if "${KUBECTL_BASE[@]}" \
            get events \
            "${namespace_args[@]}" \
            --sort-by=.metadata.creationTimestamp; then

            ((success+=1))

        else

            ((failure+=1))
        fi

    } >> "$output" 2>&1


    if (( success == 0 )); then

        record_status \
            "kubernetes" \
            "WARNING" \
            "kubectl exists but resource collection failed"

    elif (( failure > 0 )); then

        record_status \
            "kubernetes" \
            "WARNING" \
            "$failure Kubernetes check(s) unavailable"

    else

        record_status \
            "kubernetes" \
            "OK"
    fi
}

redact_file() {

    local file="$1"

    [[ -f "$file" ]] || return 0


    local temp="$TMP_DIR/redacted-$RANDOM-$RANDOM"


    sed \
        -E \
        \
        -e 's/([Pp][Aa][Ss][Ss][Ww][Oo][Rr][Dd][[:space:]]*[:=][[:space:]]*)[^[:space:]]+/\1[REDACTED]/g' \
        \
        -e 's/([Aa][Pp][Ii][_-]?[Kk][Ee][Yy][[:space:]]*[:=][[:space:]]*)[^[:space:]]+/\1[REDACTED]/g' \
        \
        -e 's/([Aa][Cc][Cc][Ee][Ss][Ss][_-]?[Tt][Oo][Kk][Ee][Nn][[:space:]]*[:=][[:space:]]*)[^[:space:]]+/\1[REDACTED]/g' \
        \
        -e 's/([Ss][Ee][Cc][Rr][Ee][Tt][[:space:]]*[:=][[:space:]]*)[^[:space:]]+/\1[REDACTED]/g' \
        \
        -e 's/(Authorization:[[:space:]]*[Bb]earer[[:space:]]+)[^[:space:]]+/\1[REDACTED]/g' \
        \
        "$file" \
        > "$temp"


    mv \
        "$temp" \
        "$file"
}


run_redaction() {

    if [[ "$ENABLE_REDACTION" != true ]]; then

        record_status \
            "redaction" \
            "WARNING" \
            "disabled by user"

        return
    fi


    while IFS= read -r -d '' file; do

        redact_file \
            "$file"

    done < <(
        find \
            "$WORK_DIR" \
            -type f \
            ! -name 'manifest.sha256' \
            -print0
    )


    record_status \
        "redaction" \
        "OK"
}

check_for_forbidden_files() {

    local findings="$TMP_DIR/forbidden-files.txt"


    find \
        "$WORK_DIR" \
        -type f \
        \( \
            -name 'id_rsa' \
            -o \
            -name 'id_ed25519' \
            -o \
            -name '*.pem' \
            -o \
            -name '*.key' \

    fi


    return 0
}

# ------------------------------------------------------------------
# Manifest
# ------------------------------------------------------------------

create_manifest() {

    if ! command_exists sha256sum; then

        record_status \
            "manifest" \
            "WARNING" \
            "sha256sum unavailable"

        return
    fi


    : > "$MANIFEST_FILE"


    (
        cd "$WORK_DIR" ||
        exit 1


        find \
            . \
            -type f \
            ! -name 'manifest.sha256' \
            -print0 |
        sort -z |
        while IFS= read -r -d '' file; do

            sha256sum \
                "$file"

        done

    ) > "$MANIFEST_FILE"


    if [[ $? -eq 0 ]]; then

        record_status \
            "manifest" \
            "OK"

    else

        record_status \
            "manifest" \
            "FAILED" \
            "checksum generation failed"
    fi
}


# ------------------------------------------------------------------
# Packaging
# ------------------------------------------------------------------

package_bundle() {

    local parent
    local base


    parent="$(
        dirname \
            "$WORK_DIR"
    )"

    base="$(
        basename \
            "$WORK_DIR"
    )"


    if ! tar \
        -C "$parent" \
        -czf "$ARCHIVE" \
        "$base"; then

        printf 'ERROR: Failed to create incident archive.\n' >&2

        return 1
    fi


    chmod \
        600 \
        "$ARCHIVE" \
        2>/dev/null \
        || true


    if ! tar \
        -tzf "$ARCHIVE" \
        >/dev/null; then

        printf 'ERROR: Incident archive validation failed.\n' >&2

        return 1
    fi


    return 0
}


# ------------------------------------------------------------------
# Optional persistent unpacked directory
# ------------------------------------------------------------------

persist_working_directory() {

    [[ "$KEEP_DIRECTORY" == true ]] || return


    local destination="$OUTPUT_DIR/incident-$INCIDENT_ID"


    if [[ -e "$destination" ]]; then

        printf 'WARNING: Working-directory destination already exists: %s\n' \
            "$destination" >&2

        return
    fi


    cp \
        -a \
        "$WORK_DIR" \
        "$destination"
}

print_summary() {
```

# 35. Why We Do Not Use `set -e`

Many Bash tutorials begin with:

```bash
set -euo pipefail
```

For this collector we deliberately use:

```bash
set -u
set -o pipefail
```

but not global:

```bash
set -e
```

Why?

Imagine:

```text
Docker collection fails
```

because Docker is not installed.

Should that destroy:

```text
system evidence
CPU evidence
memory evidence
disk evidence
network evidence
journal evidence
```

No.

Incident collection is a **best-effort evidence workflow**.

Individual collectors must handle their own errors explicitly.

That is different from a deployment script, where stopping immediately may be exactly what you want.

---

# 36. Best-Effort Does Not Mean Ignore Errors

Do not confuse:

```text
continue collecting
```

with:

```text
pretend everything succeeded.
```

Every failed collection must appear in:

```text
collection-status.txt
```

Example:

```text
system                   OK
cpu                      OK
memory                   OK
disk                     OK
network                  OK
services                 OK
journal                  WARNING    access denied
docker                   SKIPPED    docker unavailable
kubernetes               WARNING    API unreachable
```

Now the next engineer understands the evidence boundary.

# 37. CPU Investigation

```text

4
```

and:

```text
payments-api   320%
```

That does not mean Bash calculated something incorrectly.

A multithreaded process can consume more than 100% CPU across multiple logical CPUs depending on the reporting tool.

Your hypothesis becomes:

```text
payments-api may be CPU saturated.
```

Not yet:

```text
payments-api is definitely the root cause.
```

# 51. Redaction Is Defense in Depth

The script contains a redaction stage.

It looks for patterns such as:

```text
password=
api_key=
access_token=
secret=
Authorization: Bearer
```

and replaces detected values with:

```text
[REDACTED]
```

But this is not perfect.

A secret could appear as:

```text
credentialValue
auth
tokenValue
custom application format
base64 text
```

that the generic redactor does not recognize.

Therefore:

```text
redaction is not permission to collect dangerous sources.
```

The first security control is:

```text
do not collect them.
```

Redaction is the second control.

---

# 52. Never Trust Regex Redaction Completely

A production incident archive should still be classified as:

```text
CONFIDENTIAL
```

even after automated redaction.

Before sending it outside your trusted engineering environment:

```text

```

# 58. Manifest Does Not Prove Authenticity

SHA-256 tells you:

```text
the file matches the recorded checksum.
```

If an attacker can modify both:

```text
file
manifest
```

the checksum alone does not prove authenticity.

A more advanced incident system could:

```text
digitally sign the manifest.
```

That belongs in an advanced security implementation.

```text
unlimited Docker logs

continuous commands

core dumps
full process memory dumps
```

The tool should have:

```text

bounded output
bounded time
```

# 120. Final Bash Engineering Standards

By the end of this curriculum, your Bash projects should follow these standards.

## Interpreter

Use:

```bash
#!/usr/bin/env bash
```

when Bash is required.

---

## Strictness

Understand rather than blindly copy:

```bash
set -u
set -o pipefail
```

Use:

```bash
set -e
```

only when its failure semantics fit the application.

A deployment helper and an incident collector do not necessarily need identical error behavior.

---

## Functions

Break meaningful operations into functions.

Prefer:

```bash
collect_cpu
collect_memory
collect_disk
collect_network
```

over one 800-line `main`.

---

## Variables

Quote variable expansions:

```bash
"$variable"
```

unless you deliberately require word splitting or globbing and understand why.

---

## Local Variables

Inside functions:

```bash
local output
local status
local path
```

where appropriate.

Avoid accidental global state.

---

## Arrays

Use Bash arrays for collections such as:

```bash
APP_LOGS=()
LARGEST_PATHS=()
DOCKER_CONTAINERS=()
```

Do not build unsafe space-separated pseudo-lists when filenames may contain spaces.

---

## Input Validation

Never assume input is valid.

Validate:

```text
numbers
paths
required arguments
mutually exclusive options
permissions
dependencies
configuration
```

before performing important operations.

---

## Dependencies

Check commands before relying on them.

Differentiate:

```text
required dependency
```

from:

```text
optional integration.
```

For this project:

```text
ip
ss
ps
free
df
tar
```

are core.

Docker and kubectl are optional.

---

## Exit Codes

Exit codes are part of your program's interface.

Do not always return:

```text
0
```

regardless of outcome.

Use documented meanings.

---

## Logging

Logs should answer:

```text
What happened?
When?
Which component?
Did it succeed?
What failed?
```

But never deliberately log:

```text
passwords
tokens
private keys
credentials
```

---

## Timestamps

For machine-generated operational evidence, UTC is usually easier to correlate:

```bash
date -u
```

especially when systems exist in multiple time zones.

---

## Temporary Files

Use:

```bash
mktemp
```

rather than predictable:

```text
/tmp/myfile
```

names.

Clean temporary resources using:

```bash
trap
```

---

## File Permissions

For sensitive operational artifacts:

```bash
umask 077
```

is a strong default.

Do not create incident archives world-readable.

---

## Destructive Operations

Treat commands such as:

```bash
rm
find -delete
userdel
chmod
chown
systemctl restart
docker system prune
kubectl delete
aws ... delete ...
```

as explicit risk boundaries.

Validate before executing them.

Prefer:

```text
dry-run
preview
confirmation
allowlists
target validation
```

where appropriate.

---

## Read-Only Diagnostics

A diagnostic script should generally not become a remediation script.

Keep:

```text
observe
```

and:

```text
change
```

separate unless the design explicitly requires both and provides strong controls.

---

## Bounded Collection

Never assume more data is better.

Bound:

```text
log lines
time windows
filesystem depth
command duration
archive size
API scope
```

A diagnostic tool that overloads an unhealthy server is badly designed.

---

## Security

Before collecting information ask:

```text
Could this expose a secret?
```

Before logging:

```text
Could this expose a secret?
```

Before packaging:

```text
Could this expose a secret?
```

Before uploading:

```text
Who can access this?
```

Security is part of operations.

---

## Failure Handling

Do not hide failures.

Distinguish:

```text
zero results
```

from:

```text
collection failed.
```

Examples:

```text
0 failed services
```

is different from:

```text
systemctl permission denied.
```

And:

```text
0 Kubernetes pods
```

is different from:

```text
Kubernetes API unreachable.
```

---

## Output Design

Output should be understandable by someone other than the script author.

Prefer:

```text
FAILED SERVICES
---------------

payments-api.service
State: failed
```

over cryptic raw values without context.

---

## Portability

Know your target.

A script written for:

```text
Linux + systemd + GNU utilities
```

should say so.

Do not claim universal Unix portability when you depend on:

```text
/proc
systemctl
journalctl
GNU stat
GNU du options
```

Explicit platform assumptions are better engineering than fake portability.

Every project should include:

```text
failure test
invalid-input test
permission test
missing-dependency test
syntax test
ShellCheck
```

Before execution:

```bash
bash -n script.sh
```

Especially before copying a script into:

```text
production
CI/CD
cron
systemd
```

## Documentation

Every production-oriented script should document:

```text
purpose
requirements
usage
arguments
examples
exit codes
security implications

failure behavior
```
