# Project 8: User Creation Script

Creating one Linux user manually is simple.

Creating dozens of users consistently, securely, and without mistakes is a different problem.

A real provisioning workflow must answer questions such as:

* Does the script have sufficient privileges?
* Does the user already exist?
* Does the requested group exist?
* Is the shell valid?
* Is the home directory safe?
* Should the account be locked initially?
* Should SSH keys be installed?
* Should the user receive sudo access?
* What should be logged?
* What must never be logged?

In this project, we will build:

```text
user-provisioner.sh
```

The script will accept:

```text
username
group
shell
home directory
```

and provision a Linux user safely.

A successful run might look like:

```text
==========================================================================
                       USER PROVISIONING REPORT
==========================================================================
Username:             veriqta
Primary Group:        developers
Shell:                /bin/bash
Home Directory:       /home/veriqta

User Created:         YES
Home Created:         YES
Group Membership:     VERIFIED
Shell Validation:     PASSED
Account Status:       LOCKED
Password Logged:      NEVER

Overall Status:       SUCCESS
==========================================================================
```

The most important security rule in this project is:

```text
Credentials must never appear in source code, command history, logs, or plaintext files.
```

Imagine you support a Linux environment where new engineers need accounts.

A request arrives:

```text
Create a Linux account for VERIQTA.

Username: veriqta
```

A manual process might be:


Another engineer creates the home directory manually with the wrong permissions.

Another one accidentally assigns `/bin/sh` instead of `/bin/bash`.

Another engineer logs a temporary password in a ticket.

That is exactly the kind of repetitive administrative work that benefits from automation.

# 4. Linux User Basics

Before automating account creation, understand what a Linux user actually has.

A Linux account commonly includes:

```text
Username
UID
Primary GID
Supplementary groups
Home directory
Login shell
Password/account state
```

Check an existing user:

```bash
id veriqta
```

Example:

```text
uid=1002(veriqta) gid=1002(veriqta) groups=1002(veriqta),998(docker)
```

---

# 5. `/etc/passwd`

Inspect:

```bash
grep '^veriqta:' /etc/passwd
```

Example:

```text
veriqta:x:1002:1002::/home/veriqta:/bin/bash
```

Fields include:

```text
username
password placeholder
UID
GID
comment
home directory
shell
```

Passwords are not stored directly in `/etc/passwd` on modern Linux systems.

---

# 6. `/etc/shadow`

Password hashes are typically stored in:

```text
/etc/shadow
```

This file is highly sensitive.

Do not:

```text
copy it into a project
commit it to Git
print it into logs
email it
```

It normally requires root privileges to read.

---

# 7. `/etc/group`

Group definitions are stored in:

```text
/etc/group
```

Inspect:

```bash
getent group developers
```

Example:

```text
developers:x:1005:
```

`getent` is preferable to manually parsing `/etc/group` because it can work with system account databases beyond local files.

# 8. Root Privilege Detection

Creating Linux users normally requires elevated privileges.

Check your effective UID:

```bash
id -u
```

For root:

```text
0
```

In Bash:

```bash
if (( EUID != 0 )); then
    echo "This script must run as root."
    exit 3
fi
```

---

# 9. Why Use `EUID`

Bash provides:

```text
EUID
```

which represents the effective user ID.

Example:

```bash
echo "$EUID"
```

A root process normally returns:

```text
0
```

This is clearer than checking whether:

```text
whoami == root
```

---

# 10. Do Not Automatically Escalate Privileges

Avoid silently doing:

```bash
sudo "$0" "$@"
```

inside the script.

It is better to fail clearly:

```text
ERROR: Root privileges are required.
```

Then the engineer explicitly decides how to rerun it.

Privilege escalation should be intentional.

# 19. Why Duplicate Detection Matters

Running `useradd` against an existing account may fail.

But more importantly, your script should distinguish:

```text
New account request
```

from:

```text
Existing account modification
```

Those are different administrative actions.

Do not silently modify existing users unless explicitly designed to do so.

# 20. Group Validation

Check:

```bash

```

If it does not exist, decide whether the script should:

```text
fail
```

or:



```text
developres
```


```text
/etc/shells
```

```bash
cat /etc/shells
```

Example:

```text
/bin/sh
```

---

# 23. Validate the Shell

Use:

```bash
validate_shell() {

    local shell="$1"

    if [[ ! -x "$shell" ]]; then
        printf 'ERROR: Shell does not exist or is not executable: %s\n' \
            "$shell" >&2
        return 1
    fi

    if [[ -f /etc/shells ]] &&
       ! grep -Fxq "$shell" /etc/shells; then

        printf 'ERROR: Shell is not listed in /etc/shells: %s\n' \
            "$shell" >&2
        return 1
    fi
}
```

# 24. Home Directory Validation

A user-supplied path is powerful.

Do not blindly accept arbitrary paths.

This would be dangerous:

```text
--home /
```

or:

```text
--home /etc
```

Our simple policy:

```text
Home must live under /home/
```

unless your environment intentionally uses another approved prefix.

---

# 25. Validate the Home Path

Use:

```bash
validate_home() {

    local home="$1"

    if [[ "$home" != /home/* ]]; then

        printf 'ERROR: Home directory must be under /home/: %s\n' \
            "$home" >&2

        return 1
    fi
}
```

---

# 26. Prevent Home Directory Collisions

Suppose:

```text
/home/veriqta
```

already belongs to someone else.

Do not simply assign it.

Check:

```bash
getent passwd |
awk -F: -v home="$HOME_DIR" '$6 == home {print $1}'
```

If another username already uses that directory, stop.

# 27. `useradd`

A common Linux user creation command is:

```bash
useradd \
    -m \
    -d /home/veriqta \
    -s /bin/bash \
    -g developers \
    veriqta
```

Options:

```text
-m   create home directory
-d   set home directory
-s   set login shell
-g   set primary group
```

# 28. Primary Group vs Supplementary Groups

A user has one primary group.

Example:

```text
developers
```

and can also belong to supplementary groups such as:

```text
docker
monitoring
platform
```

Check:

```bash
id veriqta
```

---

# 29. `usermod`

Add an existing user to another group:

```bash
usermod -aG docker veriqta
```

Important:

```text
-a
```

means append.

Without `-a`, modifying supplementary groups can unintentionally remove existing memberships.

This is a classic Linux administration mistake.

---

# 30. Dangerous Group Modification

Avoid:

```bash
usermod -G docker veriqta
```

unless you intentionally want the supplementary group list to become exactly:

```text
docker
```

Prefer:

```bash
usermod -aG docker veriqta
```

when adding membership.

# 31. Password Handling

This project has strict rules.

Never:

```text
Hardcode passwords
Print passwords
Write plaintext passwords into logs
Store them in CSV
Commit them to Git
```

This is unacceptable:

```bash
PASSWORD="Veriqta123!"
```

Do not do it.

---

# 32. Initial Account State

A strong provisioning pattern is:

```text
Create account
      |
      v
Lock password authentication
      |
      v
Install SSH key or hand off to identity workflow
```

This avoids inventing insecure temporary passwords.

---

# 33. Lock the Password

Use:

```bash
passwd -l veriqta
```

This locks password-based authentication for the account.

Verify:

```bash
passwd -S veriqta
```

Output varies by distribution.

You may see a locked state marker.

---

# 34. Important Locking Limitation

Locking the password does not necessarily disable every way the account can authenticate.

For example, SSH public-key authentication may still work.

This is often exactly what you want.

Understand the difference between:

```text
password locked
```

and:

```text
account completely disabled
```

---

# 35. Avoid `passwd` Automation With Plaintext

Do not do:

```bash
echo "veriqta:Password123" | chpasswd
```

for this project.

While tools such as `chpasswd` have legitimate administrative uses, piping plaintext credentials through scripts creates unnecessary exposure.

We are deliberately avoiding that design.

---

# 36. SSH Key Provisioning

A production enhancement may install a public key.

A public key is not a password.

Example location:

```text
/home/veriqta/.ssh/authorized_keys
```

Required permissions commonly include:

```text
~/.ssh              700
authorized_keys     600
```

Ownership must belong to the user.

---

# 37. Create `.ssh` Safely

Example:

```bash
install \
    -d \
    -m 700 \
    -o veriqta \
    -g developers \
    /home/veriqta/.ssh
```

Then place an approved public key in:

```text
authorized_keys
```

Never generate a private key on the server and expose it casually.

---

# 38. Public vs Private SSH Keys

Safe to place on the server:

```text
public key
```

Must remain private:

```text
private key
```

Do not:

```text
email private keys
commit private keys
log private keys
store private keys in CSV
```

# 50. Complete Working Script

Use:

```bash
#!/usr/bin/env bash

set -u
set -o pipefail

umask 077

# ------------------------------------------------------------------
# Linux User Provisioner
# ------------------------------------------------------------------
#
# Exit codes:
#   0 = SUCCESS
#   1 = SUCCESS with warning
#   2 = User creation/configuration failure
#   3 = Input/configuration/privilege error
#
# ------------------------------------------------------------------

USERNAME=""
PRIMARY_GROUP=""
LOGIN_SHELL="/bin/bash"
HOME_DIR=""

SUPPLEMENTARY_GROUPS=""

CREATE_GROUP=false
DRY_RUN=false

OVERALL_STATUS="SUCCESS"

SCRIPT_DIR=$(
    cd -- "$(dirname -- "${BASH_SOURCE[0]}")" &&
    pwd
)

readonly SCRIPT_DIR

LOG_DIR="$SCRIPT_DIR/logs"
LOG_FILE="$LOG_DIR/user-provisioner.log"


show_help() {

    cat <<EOF
Usage:
  $0 [options]

Required:
  --username NAME       Username to create
  --group GROUP         Primary group
  --home PATH           Home directory

Optional:
  --shell PATH          Login shell
                        Default: /bin/bash

  --supplementary LIST  Comma-separated supplementary groups

  --create-group        Create missing primary group

  --dry-run             Validate and display actions only

  --help                Display this help

Examples:
  $0 \
    --username veriqta \
    --group developers \
    --shell /bin/bash \
    --home /home/veriqta

  $0 \
    --username veriqta \
    --group developers \
    --home /home/veriqta \
    --supplementary docker,monitoring

  $0 \
    --dry-run \
    --username veriqta \
    --group developers \
    --home /home/veriqta
EOF
}


parse_arguments() {

    while [[ $# -gt 0 ]]; do

        case "$1" in

            --username)

                [[ $# -ge 2 ]] || {
                    printf 'ERROR: --username requires a value.\n' >&2
                    exit 3
                }

                USERNAME="$2"
                shift 2
                ;;

            --group)

                [[ $# -ge 2 ]] || {
                    printf 'ERROR: --group requires a value.\n' >&2
                    exit 3
                }

                PRIMARY_GROUP="$2"
                shift 2
                ;;

            --shell)

                [[ $# -ge 2 ]] || {
                    printf 'ERROR: --shell requires a value.\n' >&2
                    exit 3
                }

                LOGIN_SHELL="$2"
                shift 2
                ;;

            --home)

                [[ $# -ge 2 ]] || {
                    printf 'ERROR: --home requires a value.\n' >&2
                    exit 3
                }

                HOME_DIR="$2"
                shift 2
                ;;

            --supplementary)

                [[ $# -ge 2 ]] || {
                    printf 'ERROR: --supplementary requires a value.\n' >&2
                    exit 3
                }

                SUPPLEMENTARY_GROUPS="$2"
                shift 2
                ;;

            --create-group)

                CREATE_GROUP=true
                shift
                ;;

            --dry-run)

                DRY_RUN=true
                shift
                ;;

            --help|-h)

                show_help
                exit 0
                ;;

            *)

                printf 'ERROR: Unknown option: %s\n' "$1" >&2
                show_help
                exit 3
                ;;
        esac

    done
}


log_message() {

    local level="$1"
    local message="$2"

    mkdir -p "$LOG_DIR"

    printf '[%s] [%s] %s\n' \
        "$(date '+%Y-%m-%d %H:%M:%S')" \
        "$level" \
        "$message" \
        >> "$LOG_FILE"
}


check_dependencies() {

    local commands=(
        useradd
        usermod
        groupadd
        passwd
        id
        getent
        grep
        mkdir
        date
    )

    local cmd

    for cmd in "${commands[@]}"; do

        if ! command -v "$cmd" >/dev/null 2>&1; then

            printf 'ERROR: Required command missing: %s\n' \
                "$cmd" >&2

            exit 3
        fi

    done
}


require_root() {

    if [[ "$DRY_RUN" == true ]]; then
        return
    fi

    if (( EUID != 0 )); then

        printf 'ERROR: Root privileges are required.\n' >&2

        exit 3
    fi
}


validate_required_inputs() {

    if [[ -z "$USERNAME" ]]; then
        printf 'ERROR: --username is required.\n' >&2
        exit 3
    fi

    if [[ -z "$PRIMARY_GROUP" ]]; then
        printf 'ERROR: --group is required.\n' >&2
        exit 3
    fi

    if [[ -z "$HOME_DIR" ]]; then
        printf 'ERROR: --home is required.\n' >&2
        exit 3
    fi
}


validate_username() {

    if [[ ! "$USERNAME" =~ ^[a-z_][a-z0-9_-]*$ ]]; then

        printf 'ERROR: Invalid username: %s\n' \
            "$USERNAME" >&2

        exit 3
    fi
}


ensure_user_absent() {

    if getent passwd "$USERNAME" >/dev/null; then

        printf 'ERROR: User already exists: %s\n' \
            "$USERNAME" >&2

        exit 3
    fi
}


validate_shell() {

    if [[ ! -x "$LOGIN_SHELL" ]]; then

        printf 'ERROR: Shell does not exist or is not executable: %s\n' \
            "$LOGIN_SHELL" >&2

        exit 3
    fi

    if [[ -f /etc/shells ]] &&
       ! grep -Fxq "$LOGIN_SHELL" /etc/shells; then

        printf 'ERROR: Shell is not listed in /etc/shells: %s\n' \
            "$LOGIN_SHELL" >&2

        exit 3
    fi
}


validate_home() {

    local existing_owner

    if [[ "$HOME_DIR" != /home/* ]]; then

        printf 'ERROR: Home directory must be under /home/: %s\n' \
            "$HOME_DIR" >&2

        exit 3
    fi

    existing_owner=$(
        getent passwd |
        awk -F: -v home="$HOME_DIR" \
            '$6 == home {print $1; exit}'
    )

    if [[ -n "$existing_owner" ]]; then

        printf 'ERROR: Home directory already assigned to user: %s\n' \
            "$existing_owner" >&2

        exit 3
    fi
}


ensure_primary_group() {

    if getent group "$PRIMARY_GROUP" >/dev/null; then
        return
    fi

    if [[ "$CREATE_GROUP" != true ]]; then

        printf 'ERROR: Primary group does not exist: %s\n' \
            "$PRIMARY_GROUP" >&2

        printf 'Use --create-group only if group creation is intended.\n' \
            >&2

        exit 3
    fi

    if [[ "$DRY_RUN" == true ]]; then

        printf 'DRY RUN: Would create group %s\n' \
            "$PRIMARY_GROUP"

        return
    fi

    if groupadd "$PRIMARY_GROUP"; then

        log_message \
            "INFO" \
            "Created group=$PRIMARY_GROUP"

    else

        log_message \
            "ERROR" \
            "Unable to create group=$PRIMARY_GROUP"

        exit 2
    fi
}


validate_supplementary_groups() {

    local group
    local -a groups=()

    if [[ -z "$SUPPLEMENTARY_GROUPS" ]]; then
        return
    fi

    IFS=',' read -r -a groups \
        <<< "$SUPPLEMENTARY_GROUPS"

    for group in "${groups[@]}"; do

        if ! getent group "$group" >/dev/null; then

            printf 'ERROR: Supplementary group does not exist: %s\n' \
                "$group" >&2

            exit 3
        fi
    done
}


create_user() {

    if [[ "$DRY_RUN" == true ]]; then

        printf 'DRY RUN: Would create user %s\n' \
            "$USERNAME"

        printf 'DRY RUN: Primary group: %s\n' \
            "$PRIMARY_GROUP"

        printf 'DRY RUN: Shell: %s\n' \
            "$LOGIN_SHELL"

        printf 'DRY RUN: Home: %s\n' \
            "$HOME_DIR"

        printf 'DRY RUN: Would lock password authentication\n'

        return
    fi

    log_message \
        "INFO" \
        "Provisioning started username=$USERNAME group=$PRIMARY_GROUP home=$HOME_DIR shell=$LOGIN_SHELL"

    if useradd \
        -m \
        -d "$HOME_DIR" \
        -s "$LOGIN_SHELL" \
        -g "$PRIMARY_GROUP" \
        "$USERNAME"; then

        log_message \
            "INFO" \
            "User created username=$USERNAME"

    else

        log_message \
            "ERROR" \
            "User creation failed username=$USERNAME"

        printf 'ERROR: useradd failed.\n' >&2
        exit 2
    fi
}


configure_supplementary_groups() {

    if [[ -z "$SUPPLEMENTARY_GROUPS" ]]; then
        return
    fi

    if [[ "$DRY_RUN" == true ]]; then

        printf 'DRY RUN: Would add %s to groups: %s\n' \
            "$USERNAME" \
            "$SUPPLEMENTARY_GROUPS"

        return
    fi

    if usermod \
        -aG "$SUPPLEMENTARY_GROUPS" \
        "$USERNAME"; then

        log_message \
            "INFO" \
            "Supplementary groups configured username=$USERNAME groups=$SUPPLEMENTARY_GROUPS"

    else

        log_message \
            "ERROR" \
            "Unable to configure supplementary groups username=$USERNAME"

        printf 'ERROR: usermod failed.\n' >&2
        exit 2
    fi
}


lock_password() {

    if [[ "$DRY_RUN" == true ]]; then
        return
    fi

    if passwd -l "$USERNAME" >/dev/null 2>&1; then

        log_message \
            "INFO" \
            "Password authentication locked username=$USERNAME"

    else

        log_message \
            "WARNING" \
            "Unable to lock password username=$USERNAME"

        OVERALL_STATUS="WARNING"
    fi
}


verify_user() {

    if [[ "$DRY_RUN" == true ]]; then
        return
    fi

    if ! id "$USERNAME" >/dev/null 2>&1; then

        log_message \
            "ERROR" \
            "Verification failed user missing username=$USERNAME"

        printf 'ERROR: User verification failed.\n' >&2

        exit 2
    fi
}


verify_home() {

    if [[ "$DRY_RUN" == true ]]; then
        return
    fi

    if [[ ! -d "$HOME_DIR" ]]; then

        log_message \
            "ERROR" \
            "Home directory missing username=$USERNAME home=$HOME_DIR"

        printf 'ERROR: Home directory was not created.\n' >&2

        exit 2
    fi
}


verify_primary_group() {

    local actual_group

    if [[ "$DRY_RUN" == true ]]; then
        return
    fi

    actual_group=$(
        id -gn "$USERNAME"
    )

    if [[ "$actual_group" != "$PRIMARY_GROUP" ]]; then

        log_message \
            "ERROR" \
            "Primary group mismatch username=$USERNAME expected=$PRIMARY_GROUP actual=$actual_group"

        printf 'ERROR: Primary group verification failed.\n' >&2

        exit 2
    fi
}


verify_shell() {

    local actual_shell

    if [[ "$DRY_RUN" == true ]]; then
        return
    fi

    actual_shell=$(
        getent passwd "$USERNAME" |
        awk -F: '{print $7}'
    )

    if [[ "$actual_shell" != "$LOGIN_SHELL" ]]; then

        log_message \
            "ERROR" \
            "Shell verification failed username=$USERNAME expected=$LOGIN_SHELL actual=$actual_shell"

        printf 'ERROR: Shell verification failed.\n' >&2

        exit 2
    fi
}


print_report() {

    printf '\n%s\n' \
        "=========================================================================="

    printf '%s\n' \
        "                       USER PROVISIONING REPORT"

    printf '%s\n' \
        "=========================================================================="

    printf '%-24s %s\n' \
        "Username:" "$USERNAME"

    printf '%-24s %s\n' \
        "Primary Group:" "$PRIMARY_GROUP"

    printf '%-24s %s\n' \
        "Shell:" "$LOGIN_SHELL"

    printf '%-24s %s\n' \
        "Home Directory:" "$HOME_DIR"

    if [[ -n "$SUPPLEMENTARY_GROUPS" ]]; then

        printf '%-24s %s\n' \
            "Supplementary Groups:" "$SUPPLEMENTARY_GROUPS"
    fi

    printf '%-24s %s\n' \
        "Dry Run:" "$DRY_RUN"

    if [[ "$DRY_RUN" == true ]]; then

        printf '%-24s %s\n' \
            "User Created:" "NO - DRY RUN"

    else

        printf '%-24s %s\n' \
            "User Created:" "YES"

        printf '%-24s %s\n' \
            "Home Created:" "YES"

        printf '%-24s %s\n' \
            "Password Status:" "LOCKED"
    fi

    printf '%-24s %s\n' \
        "Password Logged:" "NEVER"

    printf '\n%s\n' \
        "--------------------------------------------------------------------------"

    printf '%-24s %s\n' \
        "Overall Status:" "$OVERALL_STATUS"

    printf '%s\n' \
        "=========================================================================="
}


return_status() {

    case "$OVERALL_STATUS" in

        SUCCESS)
            return 0
            ;;

        WARNING)
            return 1
            ;;

        *)
            return 2
            ;;
    esac
}


main() {

    parse_arguments "$@"

    check_dependencies

    validate_required_inputs

    validate_username

    validate_shell

    validate_home

    ensure_user_absent

    ensure_primary_group

    validate_supplementary_groups

    require_root

    create_user

    configure_supplementary_groups

    lock_password

    verify_user

    verify_home

    verify_primary_group

    verify_shell

    print_report

    if [[ "$DRY_RUN" != true ]]; then

        log_message \
            "INFO" \
            "Provisioning completed username=$USERNAME status=$OVERALL_STATUS"
    fi

    return_status
}


main "$@"
exit $?
```

# 79. Why UID Matters

Linux permissions fundamentally use numeric IDs.

If two systems disagree about which username owns UID:


network filesystems and restored backups can show confusing ownership.

* NFS
* Shared storage
* LDAP
* Active Directory integration
* Containers
* Backup restoration
