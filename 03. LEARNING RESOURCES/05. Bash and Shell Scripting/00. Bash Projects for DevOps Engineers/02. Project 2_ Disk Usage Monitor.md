# Project 2: Disk Usage Monitor

Disk problems are among the most common Linux incidents.

A server can appear healthy and still fail because one filesystem reaches 100 percent utilization.

When that happens, you may see:

* Applications unable to write logs
* Databases failing to write data
* Package installations failing
* Docker builds failing
* CI/CD jobs failing
* Temporary files failing to create
* SSH sessions behaving strangely
* Services crashing
* Kubernetes nodes developing disk pressure
* Log collectors stopping
* Monitoring agents becoming unreliable

This project builds a Bash monitoring script that checks mounted filesystems and classifies them as:

```text
OK
WARNING
CRITICAL
```

The script will also help us answer the next question engineers usually ask:

What is consuming all the disk space?

We will build a tool called:

```text
disk-usage-monitor.sh
```

A finished run might look like:

```text
============================================================
                  DISK USAGE REPORT
============================================================
Timestamp: 2026-09-11 10:14:27
Hostname:  app-server-01

Filesystem                    Mount Point      Usage   Status
------------------------------------------------------------
/dev/xvda1                    /                 58%    OK
/dev/xvda2                    /var              82%    WARNING
/dev/xvdb1                    /data             94%    CRITICAL

------------------------------------------------------------
Highest Usage: 94%
Highest Mount: /data
Overall Status: CRITICAL
============================================================
```

If a filesystem crosses a configured threshold, our script will also be capable of identifying the largest directories beneath that mount point.

# 1. Project Scenario

Imagine you are supporting a Linux application server.

Monitoring reports:

```text
Disk usage critical on /var
```

You connect to the server and run:

```bash
df -h
```

You see:

```text
Filesystem      Size  Used Avail Use% Mounted on
/dev/xvda1       30G   14G   16G  47% /
/dev/xvda2       20G   18G  2.0G  90% /var
/dev/xvdb1      100G   61G   39G  61% /data
```

Now you know `/var` is the problem.

But that creates a second question:

What inside `/var` is consuming the space?

You investigate:

```bash
sudo du -xhd1 /var | sort -h
```

and discover:

```text
512M    /var/cache
1.4G    /var/lib
15G     /var/log
18G     /var
```

You then inspect:

```bash
sudo du -xhd1 /var/log | sort -h
```

and find an application log growing uncontrollably.

That is a common production troubleshooting flow.

This project will automate the first part of that investigation.

```text
       Usage Percentage
             |
     +-------+--------+
     |       |        |
     v       v        v
    OK    WARNING   CRITICAL
                     |
                     v
             Investigate largest
               directories
```

We will use these default thresholds:

```text
Below 80%       OK
80% to 89%      WARNING
90% or higher   CRITICAL
```

These are reasonable lab values.

They are not universal production standards.

A 95 percent-full 10 TB data filesystem may still have hundreds of gigabytes available, while 80 percent usage on a tiny root filesystem could already require attention.

Monitoring thresholds must reflect the environment.

# 4. Why Disk Usage Matters in Production

A full filesystem can cause failures far beyond storage.

Suppose `/var` becomes full.

That can affect:

```text
/var/log
/var/lib
/var/cache
/var/tmp
```

Depending on the server, `/var` may contain:

* Application logs
* Package caches
* Docker data
* Database files
* Runtime state
* Monitoring data
* Container layers
* Package manager metadata

A filesystem reaching 100 percent can cause errors such as:

```text
No space left on device
```

But that message does not always mean the server has no physical storage left.

It may mean:

* One mounted filesystem is full
* Inodes are exhausted
* A quota was reached
* Reserved blocks are unavailable to the current user
* A deleted file is still held open by a process

We will discuss each of these.

# 8. Why We Will Use `df -P`

For scripts, human-readable output is not always ideal.

Instead of:

```bash
df -h
```

we will often use:

```bash
df -P
```

`-P` requests POSIX-style output.

This tends to give a more predictable one-filesystem-per-line format.

Example:

```text
Filesystem     1024-blocks     Used Available Capacity Mounted on
/dev/xvda1        30720000 14336000  16384000      47% /
/dev/xvda2        20480000 18432000   2048000      90% /var
```

Predictable output is easier to parse.

# 9. Extract Usage With `awk`

Try:

```bash
df -P /
```

You might see:

```text
Filesystem     1024-blocks     Used Available Capacity Mounted on
/dev/xvda1        30720000 14336000  16384000      47% /
```

Extract the usage:

```bash
df -P / | awk 'NR==2 {print $5}'
```

Output:

```text
47%
```

Remove `%`:

```bash
df -P / | awk 'NR==2 {gsub("%","",$5); print $5}'
```

Output:

```text
47
```

Now Bash can compare the value numerically.

# 11. Understanding Numeric Comparisons

Inside:

```bash
(( ... ))
```

we can compare integers directly.

Example:

```bash
if (( USAGE >= 90 )); then
```

Common operators include:

```text
>     greater than
<     less than
>=    greater than or equal
<=    less than or equal
==    equal
!=    not equal
```

We use:

```text
90 and above     CRITICAL
80 to 89         WARNING
below 80         OK
```

Order matters.

We check CRITICAL first.

If we checked:

```bash
if (( USAGE >= 80 ))
```

first, then a value of `95` would match WARNING before Bash ever reached CRITICAL.

# 12. Monitor Specific Mount Points

The project requirements include:

```text
/
/var
/home
```

But these paths are not necessarily separate filesystems.

For example:

```bash
df -P /
df -P /var
df -P /home
```

might all show the same filesystem:

```text
/dev/xvda1
```

That means `/var` and `/home` are directories inside `/`, not separate mounted filesystems.

This is important.

Do not assume every directory is independently mounted.

Check:

```bash
findmnt /
findmnt /var
findmnt /home
```

Or:

```bash
df -P /
df -P /var
df -P /home
```

# 13. Why Duplicate Filesystems Matter

Suppose:

```text
/       /dev/xvda1
/var    /dev/xvda1
/home   /dev/xvda1
```

If we blindly monitor all three separately, we might report:

```text
/       85% WARNING
/var    85% WARNING
/home   85% WARNING
```

That looks like three storage incidents.

It is actually one filesystem.

A good monitoring script should monitor actual mounted filesystems rather than arbitrary directories.

# 15. Build a Filesystem Loop

Run:

```bash
df -P -x tmpfs -x devtmpfs | awk 'NR>1'
```

Now we want to process every line.

A safe pattern is:

```bash
while read -r filesystem blocks used available capacity mountpoint; do
    echo "$filesystem $mountpoint $capacity"
done < <(
    df -P -x tmpfs -x devtmpfs | awk 'NR>1'
)
```

This introduces process substitution:

```text
< <(...)
```

The command inside generates input for the loop.

# 22. Build the Basic Monitor

At this stage, your script can look like:

```bash
#!/usr/bin/env bash

WARNING_THRESHOLD=80
CRITICAL_THRESHOLD=90

OVERALL_STATUS="OK"
HIGHEST_USAGE=0
HIGHEST_MOUNT=""

get_status() {
    local usage="$1"

    if (( usage >= CRITICAL_THRESHOLD )); then
        printf 'CRITICAL'
    elif (( usage >= WARNING_THRESHOLD )); then
        printf 'WARNING'
    else
        printf 'OK'
    fi
}

update_overall_status() {
    local status="$1"

    if [[ "$status" == "CRITICAL" ]]; then
        OVERALL_STATUS="CRITICAL"

    elif [[ "$status" == "WARNING" &&
            "$OVERALL_STATUS" == "OK" ]]; then

        OVERALL_STATUS="WARNING"
    fi
}

printf '%-30s %-20s %-8s %-10s\n' \
    "Filesystem" "Mount Point" "Usage" "Status"

printf '%s\n' \
    "---------------------------------------------------------------------"

while read -r filesystem blocks used available capacity mountpoint; do

    usage=${capacity%\%}

    status=$(get_status "$usage")

    update_overall_status "$status"

    if (( usage > HIGHEST_USAGE )); then
        HIGHEST_USAGE=$usage
        HIGHEST_MOUNT=$mountpoint
    fi

    printf '%-30s %-20s %-8s %-10s\n' \
        "$filesystem" "$mountpoint" "${usage}%" "$status"

done < <(
    df -P -x tmpfs -x devtmpfs | awk 'NR>1'
)

printf '\nOverall Status: %s\n' "$OVERALL_STATUS"
```

Run:

```bash
./disk-usage-monitor.sh
```

# 24. Understanding `du`

`df` tells us how much space a filesystem reports as used.

`du` tells us how much disk space files and directories consume.

Example:

```bash
du -sh /var
```

Output:

```text
18G    /var
```

To inspect the first level:

```bash
sudo du -xhd1 /var
```

Example:

```text
512M    /var/cache
1.4G    /var/lib
15G     /var/log
18G     /var
```

Sort:

```bash
sudo du -xhd1 /var | sort -h
```

Largest entries appear near the bottom.

For largest first:

```bash
sudo du -xhd1 /var | sort -hr
```

---

# 25. Why We Use `-x`

Consider:

```bash
du -hd1 /
```

If other filesystems are mounted beneath `/`, `du` could cross into them.

Using:

```bash
du -x
```

keeps the scan on one filesystem.

That is important when investigating disk usage.

You do not want a `/` filesystem investigation accidentally scanning:

```text
/mnt/network-share
/data
/proc
```

or another separately mounted filesystem.

# 26. Find the Largest Directories

We will add a function:

```bash
show_largest_directories() {
    local mountpoint="$1"

    printf '\nLargest directories under %s:\n' "$mountpoint"

    du -x -d 1 "$mountpoint" 2>/dev/null |
        sort -nr |
        head -n 10
}
```

However, raw `du` output is not very readable.

Use:

```bash
du -x -h -d 1 "$mountpoint"
```

then:

```bash
sort -hr
```

Full version:

```bash
du -xhd1 "$mountpoint" 2>/dev/null |
    sort -hr |
    head -n 10
```

# 28. Permission Problems During `du`

If you run:

```bash
du -xhd1 /
```

you may see:

```text
du: cannot read directory '/root': Permission denied
```

That does not necessarily mean the command failed completely.

It means your current user cannot inspect every path.

You have several choices:

* Run with sufficient privileges
* Accept partial results
* Suppress permission errors
* Log permission errors separately

For our monitor:

```bash
2>/dev/null
```

keeps the report clean.

But remember what that means.

You may hide useful diagnostic information.

In production tooling, sometimes it is better to capture errors rather than discard them.

---

# 29. Add Largest-Directory Detection Only When Needed

Running:

```bash
du
```

against large filesystems can be expensive.

It may:

* Consume disk I/O
* Take a long time
* Traverse millions of files
* Increase load
* Affect production applications

So we should not automatically run a deep `du` scan every time.

Better behavior:

```text
If status == OK
    Do not run du

If status == WARNING
    Optional investigation

If status == CRITICAL
    Run largest-directory analysis if enabled
```

That is safer and more efficient.

# 31. Add Configurable Thresholds

We want:

```bash
./disk-usage-monitor.sh \
    --warning 75 \
    --critical 90
```

This means:

```text
75 to 89    WARNING
90+         CRITICAL
```

We need argument parsing.

Start:

```bash
while [[ $# -gt 0 ]]; do
    case "$1" in

        --warning)
            WARNING_THRESHOLD="$2"
            shift 2
            ;;

        --critical)
            CRITICAL_THRESHOLD="$2"
            shift 2
            ;;

        --largest)
            SHOW_LARGEST=true
            shift
            ;;

        *)
            printf 'Unknown option: %s\n' "$1" >&2
            exit 3
            ;;
    esac
done
```

# 32. Validate Thresholds

Do not trust user input.

Someone may run:

```bash
./disk-usage-monitor.sh --warning hello
```

We need validation.

Create:

```bash
is_integer() {
    [[ "$1" =~ ^[0-9]+$ ]]
}
```

Then:

```bash
validate_thresholds() {

    if ! is_integer "$WARNING_THRESHOLD"; then
        printf 'ERROR: Warning threshold must be an integer.\n' >&2
        exit 3
    fi

    if ! is_integer "$CRITICAL_THRESHOLD"; then
        printf 'ERROR: Critical threshold must be an integer.\n' >&2
        exit 3
    fi

    if (( WARNING_THRESHOLD < 1 ||
          WARNING_THRESHOLD > 100 )); then

        printf 'ERROR: Warning threshold must be between 1 and 100.\n' >&2
        exit 3
    fi

    if (( CRITICAL_THRESHOLD < 1 ||
          CRITICAL_THRESHOLD > 100 )); then

        printf 'ERROR: Critical threshold must be between 1 and 100.\n' >&2
        exit 3
    fi

    if (( WARNING_THRESHOLD >= CRITICAL_THRESHOLD )); then

        printf 'ERROR: Warning threshold must be lower than critical threshold.\n' >&2
        exit 3
    fi
}
```

This prevents nonsensical configuration.

# 39. Complete Working Script

Now replace your file with this version:

```bash
#!/usr/bin/env bash

set -u
set -o pipefail

# ------------------------------------------------------------
# Disk Usage Monitor
# ------------------------------------------------------------
#
# Exit codes:
#   0 = OK
#   1 = WARNING
#   2 = CRITICAL
#   3 = Script/configuration error
#
# ------------------------------------------------------------

WARNING_THRESHOLD=80
CRITICAL_THRESHOLD=90

SHOW_LARGEST=false
ENABLE_LOG=true

OVERALL_STATUS="OK"

HIGHEST_USAGE=0
HIGHEST_MOUNT=""

SCRIPT_DIR=$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")" && pwd)
readonly SCRIPT_DIR

LOG_DIR="$SCRIPT_DIR/logs"
LOG_FILE="$LOG_DIR/disk-monitor.log"

TIMESTAMP=""
HOSTNAME_VALUE=""


show_help() {
    cat <<EOF
Usage:
  $0 [options]

Options:
  --warning N      Warning threshold percentage
  --critical N     Critical threshold percentage
  --largest        Show largest directories for unhealthy filesystems
  --no-log         Disable log output
  --help           Display this help

Examples:
  $0
  $0 --warning 75 --critical 90
  $0 --largest
  $0 --warning 70 --critical 85 --largest
EOF
}


is_integer() {
    [[ "$1" =~ ^[0-9]+$ ]]
}


parse_arguments() {

    while [[ $# -gt 0 ]]; do

        case "$1" in

            --warning)

                if [[ $# -lt 2 ]]; then
                    printf 'ERROR: --warning requires a value.\n' >&2
                    exit 3
                fi

                WARNING_THRESHOLD="$2"
                shift 2
                ;;

            --critical)

                if [[ $# -lt 2 ]]; then
                    printf 'ERROR: --critical requires a value.\n' >&2
                    exit 3
                fi

                CRITICAL_THRESHOLD="$2"
                shift 2
                ;;

            --largest)

                SHOW_LARGEST=true
                shift
                ;;

            --no-log)

                ENABLE_LOG=false
                shift
                ;;

            --help|-h)

                show_help
                exit 0
                ;;

            *)

                printf 'ERROR: Unknown option: %s\n' "$1" >&2
                show_help
                exit 3
                ;;
        esac
    done
}


validate_thresholds() {

    if ! is_integer "$WARNING_THRESHOLD"; then
        printf 'ERROR: Warning threshold must be an integer.\n' >&2
        exit 3
    fi

    if ! is_integer "$CRITICAL_THRESHOLD"; then
        printf 'ERROR: Critical threshold must be an integer.\n' >&2
        exit 3
    fi

    if (( WARNING_THRESHOLD < 1 ||
          WARNING_THRESHOLD > 100 )); then

        printf 'ERROR: Warning threshold must be between 1 and 100.\n' >&2
        exit 3
    fi

    if (( CRITICAL_THRESHOLD < 1 ||
          CRITICAL_THRESHOLD > 100 )); then

        printf 'ERROR: Critical threshold must be between 1 and 100.\n' >&2
        exit 3
    fi

    if (( WARNING_THRESHOLD >= CRITICAL_THRESHOLD )); then

        printf 'ERROR: Warning threshold must be lower than critical threshold.\n' >&2
        exit 3
    fi
}


check_dependencies() {

    local commands=(
        df
        du
        awk
        sort
        head
        hostname
        date
    )

    local cmd
    local missing=0

    for cmd in "${commands[@]}"; do

        if ! command -v "$cmd" >/dev/null 2>&1; then
            printf 'ERROR: Required command not found: %s\n' "$cmd" >&2
            missing=1
        fi

    done

    if (( missing != 0 )); then
        exit 3
    fi
}


get_status() {

    local usage="$1"

    if (( usage >= CRITICAL_THRESHOLD )); then
        printf 'CRITICAL'

    elif (( usage >= WARNING_THRESHOLD )); then
        printf 'WARNING'

    else
        printf 'OK'
    fi
}


update_overall_status() {

    local status="$1"

    if [[ "$status" == "CRITICAL" ]]; then

        OVERALL_STATUS="CRITICAL"

    elif [[ "$status" == "WARNING" &&
            "$OVERALL_STATUS" == "OK" ]]; then

        OVERALL_STATUS="WARNING"
    fi
}


write_log() {

    local mountpoint="$1"
    local usage="$2"
    local status="$3"

    if [[ "$ENABLE_LOG" != true ]]; then
        return
    fi

    mkdir -p "$LOG_DIR"

    printf '[%s] host=%s mount=%s usage=%s%% status=%s\n' \
        "$TIMESTAMP" \
        "$HOSTNAME_VALUE" \
        "$mountpoint" \
        "$usage" \
        "$status" >> "$LOG_FILE"
}


send_alert() {

    local mountpoint="$1"
    local usage="$2"
    local status="$3"

    printf 'ALERT: filesystem %s is %s%% full. Status: %s\n' \
        "$mountpoint" \
        "$usage" \
        "$status" >&2

    # Production extension example:
    #
    # curl -X POST \
    #   -H 'Content-Type: application/json' \
    #   -d "{\"mount\":\"$mountpoint\",\"usage\":$usage,\"status\":\"$status\"}" \
    #   "$ALERT_WEBHOOK_URL"
    #
    # Never hardcode real webhook secrets in this script.
}


show_largest_directories() {

    local mountpoint="$1"

    printf '\nLargest directories under %s:\n' "$mountpoint"

    if [[ ! -r "$mountpoint" ]]; then
        printf 'Unable to read %s with current permissions.\n' "$mountpoint"
        return
    fi

    du -xhd1 "$mountpoint" 2>/dev/null |
        sort -hr |
        head -n 10
}


monitor_filesystems() {

    local filesystem
    local blocks
    local used
    local available
    local capacity
    local mountpoint
    local usage
    local status

    printf '%-30s %-20s %-8s %-10s\n' \
        "Filesystem" \
        "Mount Point" \
        "Usage" \
        "Status"

    printf '%s\n' \
        "--------------------------------------------------------------------------"

    while read -r filesystem blocks used available capacity mountpoint; do

        usage=${capacity%\%}

        if ! is_integer "$usage"; then
            continue
        fi

        status=$(get_status "$usage")

        update_overall_status "$status"

        if (( usage > HIGHEST_USAGE )); then
            HIGHEST_USAGE=$usage
            HIGHEST_MOUNT=$mountpoint
        fi

        printf '%-30s %-20s %-8s %-10s\n' \
            "$filesystem" \
            "$mountpoint" \
            "${usage}%" \
            "$status"

        write_log "$mountpoint" "$usage" "$status"

        if [[ "$status" != "OK" ]]; then
            send_alert "$mountpoint" "$usage" "$status"

            if [[ "$SHOW_LARGEST" == true ]]; then
                show_largest_directories "$mountpoint"
            fi
        fi

    done < <(
        df -P \
            -x tmpfs \
            -x devtmpfs \
            2>/dev/null |
        awk 'NR>1'
    )
}


print_summary() {

    printf '\n%s\n' \
        "--------------------------------------------------------------------------"

    printf '%-20s %s%%\n' \
        "Highest Usage:" \
        "$HIGHEST_USAGE"

    printf '%-20s %s\n' \
        "Highest Mount:" \
        "${HIGHEST_MOUNT:-Unknown}"

    printf '%-20s %s\n' \
        "Overall Status:" \
        "$OVERALL_STATUS"

    printf '%s\n' \
        "=========================================================================="
}


return_status() {

    case "$OVERALL_STATUS" in

        OK)
            return 0
            ;;

        WARNING)
            return 1
            ;;

        CRITICAL)
            return 2
            ;;

        *)
            return 3
            ;;
    esac
}


main() {

    parse_arguments "$@"

    validate_thresholds

    check_dependencies

    TIMESTAMP=$(date '+%Y-%m-%d %H:%M:%S')
    HOSTNAME_VALUE=$(hostname)

    printf '%s\n' \
        "=========================================================================="

    printf '%s\n' \
        "                         DISK USAGE REPORT"

    printf '%s\n' \
        "=========================================================================="

    printf '%-20s %s\n' "Timestamp:" "$TIMESTAMP"
    printf '%-20s %s\n' "Hostname:" "$HOSTNAME_VALUE"
    printf '%-20s %s%%\n' "Warning Threshold:" "$WARNING_THRESHOLD"
    printf '%-20s %s%%\n' "Critical Threshold:" "$CRITICAL_THRESHOLD"

    printf '\n'

    monitor_filesystems

    print_summary

    return_status
}


main "$@"
exit $?
```

# 48. Why `df` and `du` Can Disagree

This is a real production troubleshooting issue.

Suppose:

```bash
df -h /
```

says:

```text
95% used
```

but:

```bash
sudo du -xsh /
```

only finds:

```text
65% worth of files
```

Why?

One common reason is a deleted file still held open by a running process.

Imagine a log file grows to 20 GB.

Someone runs:

```bash
rm application.log
```

The filename disappears.

But the application still has the file descriptor open.

The filesystem blocks remain allocated until that process releases the file.

`du` may no longer see the deleted file.

`df` still sees the blocks as used.

Check:

```bash
sudo lsof +L1
```

You may find output such as:

```text
java  4217  app  7w  REG  202,1  21474836480  0  /var/log/application.log (deleted)
```

The correct fix might involve restarting or signaling the application so it releases the deleted file.

Do not blindly reboot a production server without understanding the impact.

# 49. Inode Exhaustion

Disk capacity is not the only filesystem limit.

Run:

```bash
df -i
```

Example:

```text
Filesystem      Inodes  IUsed   IFree IUse% Mounted on
/dev/xvda1      655360  643210  12150   99% /
```

The filesystem may still have free gigabytes but be unable to create new files because nearly all inodes are consumed.

Applications may still report:

```text
No space left on device
```

This is why professional disk monitoring should check both:

```text
Capacity
Inodes
```

* Hostnames
* Mount points
* Storage layout
* Filesystem paths
* Capacity information

```text

Who owns it?

```

A disk incident does not justify random cleanup.
