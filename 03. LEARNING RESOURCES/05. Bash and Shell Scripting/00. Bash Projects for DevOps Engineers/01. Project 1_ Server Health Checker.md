# Project 1: Server Health Checker

When you manage Linux servers, one of the first questions you need to answer is simple:

Is this server healthy?

During an incident, you usually do not want to spend several minutes manually running commands such as:

```bash
uptime
free -h
df -h
who
ip addr
systemctl --failed
```

You want a quick summary that tells you what machine you are connected to, how long it has been running, how heavily loaded it is, how much memory is being consumed, whether the disks are filling up, and whether anything immediately looks unhealthy.

That is what we are going to build.

We will create a Bash script called:

```text
server-health-check.sh
```

By the end of the project, running:

```bash
./server-health-check.sh
```

will produce a report similar to:

```text
============================================================
                 SERVER HEALTH REPORT
============================================================
Timestamp:        2026-09-11 09:32:14
Hostname:         web-01
Operating System: Ubuntu 24.04.3 LTS
Kernel:           6.8.0-79-generic
Uptime:           17 days, 4 hours, 21 minutes
IP Address:       10.0.1.25

------------------------ CPU -------------------------------
CPU Model:         Intel(R) Xeon(R) Platinum 8259CL CPU
CPU Cores:         2
Load Average:      0.25 0.31 0.29
CPU Load Status:   OK

----------------------- MEMORY -----------------------------
Memory Usage:      61%
Memory Status:     OK

------------------------ DISK ------------------------------
Highest Disk Use:  52%
Disk Status:       OK

------------------------ USERS -----------------------------
Logged-in Users:   2

------------------------------------------------------------
Overall Status:    HEALTHY
============================================================
```

More importantly, we are not going to copy a finished script and call the project complete.

We are going to build it, understand it, test it, deliberately break parts of it, and improve it.

---

# 1. Project Scenario

Imagine you are a junior DevOps engineer supporting several Linux application servers.

A developer reports:

> The application feels slow. Can you check the server?

You SSH into the machine.

Before investigating the application itself, you want to answer several infrastructure questions:

* Am I connected to the correct server?
* Which operating system is running?
* What kernel is running?
* How long has the server been up?
* Is CPU load unusually high?
* Is the server running out of memory?
* Is a filesystem almost full?
* How many users are currently logged in?
* Which IP addresses belong to the server?

You could check each one manually.

But if you perform this type of check repeatedly across tens or hundreds of servers, automation makes much more sense.

Our Bash script will provide that first-level health assessment.

# 13. Collect System Uptime

Try:

```bash
uptime
```

Example:

```text
09:45:27 up 17 days, 4:21, 2 users, load average: 0.25, 0.31, 0.29
```

That contains useful information, but we do not need all of it.

Modern Linux systems commonly support:

```bash
uptime -p
```

Example:

```text
up 17 days, 4 hours, 21 minutes
```

We can remove the leading word `up`.

```bash
uptime -p | sed 's/^up //'
```

Example:

```text
17 days, 4 hours, 21 minutes
```

Store it:

```bash
UPTIME_VALUE=$(uptime -p 2>/dev/null | sed 's/^up //')
```

The:

```bash
2>/dev/null
```

redirects error output if the command fails.

We should still provide a fallback:

```bash
if UPTIME_VALUE=$(uptime -p 2>/dev/null); then
    UPTIME_VALUE=${UPTIME_VALUE#up }
else
    UPTIME_VALUE="Unable to determine"
fi
```

`${UPTIME_VALUE#up }` removes `up ` from the beginning of the value.

# 15. Get the Server IP Address

Run:

```bash
ip -brief address
```

You may see several interfaces:

```text
lo        UNKNOWN        127.0.0.1/8 ::1/128
eth0      UP             10.0.1.25/24
docker0   DOWN           172.17.0.1/16
```

We usually do not want the loopback address `127.0.0.1`.

For a basic server health script, this is useful:

```bash
hostname -I
```

Example:

```text
10.0.1.25 172.17.0.1
```

But a machine may contain multiple IP addresses.

That is not necessarily an error.

We can collect all non-loopback IPv4 addresses from `ip`:

```bash
ip -o -4 addr show scope global
```

Example:

```text
2: eth0    inet 10.0.1.25/24 brd 10.0.1.255 scope global eth0
```

Extract the address:

```bash
ip -o -4 addr show scope global | awk '{print $4}'
```

That may return:

```text
10.0.1.25/24
```

Remove the CIDR suffix:

```bash
ip -o -4 addr show scope global | awk '{split($4,a,"/"); print a[1]}'
```

For multiple addresses, we can join them:

```bash
IP_ADDRESSES=$(ip -o -4 addr show scope global 2>/dev/null |
    awk '{split($4,a,"/"); print a[1]}' |
    paste -sd ',' -)
```

If no global IPv4 address is found:

```bash
if [[ -z "$IP_ADDRESSES" ]]; then
    IP_ADDRESSES="Not detected"
fi
```

# 17. Understand Linux Load Average

Run:

```bash
uptime
```

You may see:

```text
load average: 0.25, 0.31, 0.29
```

These values represent approximately the system load over:

```text
1 minute
5 minutes
15 minutes
```

You can retrieve them directly from:

```bash
cat /proc/loadavg
```

Example:

```text
0.25 0.31 0.29 1/231 18744
```

Extract the first three values:

```bash
awk '{print $1, $2, $3}' /proc/loadavg
```

Store them:

```bash
read -r LOAD_1 LOAD_5 LOAD_15 < /proc/loadavg
```

Now Bash creates three variables:

```text
LOAD_1
LOAD_5
LOAD_15
```

A load average of `4.0` means something very different on a 2-CPU system than on a 32-CPU system.

For this project, we will compare the one-minute load against the number of logical CPUs.

A simple interpretation is:

```text
Load below CPU count              Normal
Load around CPU count             Busy
Load consistently above CPU count Possible contention
```

Do not treat load average as the same thing as CPU utilization.

Linux load average also includes tasks waiting for certain types of uninterruptible I/O.

That distinction matters in production troubleshooting.

# 18. Create a CPU Load Percentage for Our Report

We can estimate the relationship between the one-minute load and available CPUs:

```text
load / CPUs × 100
```

For example:

```text
1-minute load = 1.5
CPU count = 2

1.5 / 2 × 100 = 75%
```

Bash itself does not handle floating-point arithmetic conveniently, so we can use `awk`.

```bash
CPU_LOAD_PERCENT=$(awk -v load="$LOAD_1" -v cpu="$CPU_CORES" \
    'BEGIN {printf "%.0f", (load/cpu)*100}')
```

We will use:

```text
Below 80%        OK
80 to 99%        WARNING
100% or greater  CRITICAL
```

Again, this is a simple operational signal for the lab, not a universal definition of CPU health.

# 19. Check Memory Usage

Run:

```bash
free -h
```

Example:

```text
               total        used        free      shared  buff/cache   available
Mem:           7.7Gi       3.2Gi       1.1Gi       122Mi       3.4Gi       4.1Gi
Swap:          2.0Gi       0.0Gi       2.0Gi
```

`-h` gives human-readable numbers.

For calculations, use:

```bash
free
```

Example:

```text
               total        used        free      shared  buff/cache   available
Mem:         8062712     3345460     1170620      125116     3546632     4267252
```

We can calculate memory pressure using total and available memory.

Why available memory?

Linux deliberately uses unused RAM for caches. Looking only at the `used` field can therefore make a healthy Linux server appear more memory-constrained than it really is.

Get total memory:

```bash
free | awk '/^Mem:/ {print $2}'
```

Get available memory:

```bash
free | awk '/^Mem:/ {print $7}'
```

Calculate used percentage:

```bash
MEMORY_USAGE=$(free | awk '/^Mem:/ {
    if ($2 > 0)
        printf "%.0f", (($2-$7)/$2)*100
    else
        print 0
}')
```

If the server has:

```text
Total:     8 GB
Available: 3 GB
```

approximately 5 GB is under memory pressure:

```text
5 / 8 × 100 = 62.5%
```

Our script would report approximately:

```text
Memory Usage: 63%
```

# 20. Check Disk Usage

Run:

```bash
df -h
```

Example:

```text
Filesystem      Size  Used Avail Use% Mounted on
/dev/xvda1       20G   11G  9.0G  55% /
tmpfs           3.9G     0  3.9G   0% /dev/shm
```

For monitoring we care about the percentage.

A simple root-filesystem check would be:

```bash
df -P / | awk 'NR==2 {gsub("%","",$5); print $5}'
```

But production servers may have important filesystems mounted separately:

```text
/
/var
/home
/data
/opt
```

Checking only `/` could miss `/var` being 98% full.

So we will inspect real local filesystems and find the highest utilization.

Use:

```bash
df -P -x tmpfs -x devtmpfs
```

Example:

```text
Filesystem     1024-blocks     Used Available Capacity Mounted on
/dev/xvda1        20509264 10957240   9532024      54% /
/dev/xvdb1       103081248 84193680  13628288      87% /data
```

Extract percentages:

```bash
df -P -x tmpfs -x devtmpfs |
awk 'NR>1 {gsub("%","",$5); print $5}'
```

Find the highest:

```bash
DISK_USAGE=$(df -P -x tmpfs -x devtmpfs 2>/dev/null |
    awk 'NR>1 {
        gsub("%","",$5)
        if (($5 + 0) > max) max=$5 + 0
    }
    END {print max + 0}')
```

If `/` is 54% and `/data` is 87%, we want:

```text
Highest Disk Use: 87%
```

That makes the health report much more useful.

# 22. Track the Overall Health

Our script needs one final answer:

```text
HEALTHY
WARNING
CRITICAL
```

We will track health internally.

Start with:

```bash
OVERALL_STATUS="HEALTHY"
```

If something reaches warning level:

```bash
OVERALL_STATUS="WARNING"
```

If anything reaches critical level:

```bash
OVERALL_STATUS="CRITICAL"
```

We must make sure WARNING never overwrites an existing CRITICAL status.

Create this function:

```bash
update_status() {
    local new_status="$1"

    if [[ "$new_status" == "CRITICAL" ]]; then
        OVERALL_STATUS="CRITICAL"
    elif [[ "$new_status" == "WARNING" && "$OVERALL_STATUS" == "HEALTHY" ]]; then
        OVERALL_STATUS="WARNING"
    fi
}
```

Now different checks can call:

```bash
update_status "WARNING"
```

or:

```bash
update_status "CRITICAL"
```

without accidentally lowering the severity.

# 24. Build the Memory Check

Create:

```bash
check_memory() {
    MEMORY_USAGE=$(free | awk '/^Mem:/ {
        if ($2 > 0)
            printf "%.0f", (($2-$7)/$2)*100
        else
            print 0
    }')

    if (( MEMORY_USAGE >= MEMORY_CRITICAL )); then
        MEMORY_STATUS="CRITICAL"
    elif (( MEMORY_USAGE >= MEMORY_WARNING )); then
        MEMORY_STATUS="WARNING"
    else
        MEMORY_STATUS="OK"
    fi

    update_status "$MEMORY_STATUS"
}
```

Notice:

```bash
(( ... ))
```

is used for integer arithmetic comparisons in Bash.

# 26. Build the CPU Check

Create:

```bash
check_cpu() {
    CPU_CORES=$(nproc)
    read -r LOAD_1 LOAD_5 LOAD_15 < /proc/loadavg

    CPU_LOAD_PERCENT=$(awk -v load="$LOAD_1" -v cpu="$CPU_CORES" \
        'BEGIN {
            if (cpu > 0)
                printf "%.0f", (load/cpu)*100
            else
                print 0
        }')

        CPU_STATUS="CRITICAL"
    elif (( CPU_LOAD_PERCENT >= CPU_WARNING )); then
        CPU_STATUS="WARNING"
    else
        CPU_STATUS="OK"
    fi

    update_status "$CPU_STATUS"
}
```

# 27. Check Dependencies Before Running

A useful script should fail clearly when something it requires is missing.

Create:

```bash
check_dependencies() {
    local commands=(
        hostname
        uname
        uptime
        who
        free
        df
        ip
        lscpu
        nproc
        awk
        date
    )

    local missing=0

    for cmd in "${commands[@]}"; do
        if ! command -v "$cmd" >/dev/null 2>&1; then
            printf 'ERROR: Required command not found: %s\n' "$cmd" >&2
            missing=1
        fi
    done

    if (( missing != 0 )); then
        exit 3
    fi
}
```

This introduces an array:

```bash
local commands=(...)
```

and a loop:

```bash
for cmd in "${commands[@]}"
```

For each command, Bash checks:

```bash
command -v "$cmd"
```

If any dependency is missing, the script exits.

collect_system_info() {

# 29. Format the Report With printf

`echo` is useful, but `printf` gives us better formatting control.

For example:

```bash
printf "%-18s %s\n" "Hostname:" "$HOSTNAME_VALUE"
```

`%-18s` means:

* Print a string.
* Left-align it.
* Use a field width of 18 characters.

This makes output line up cleanly.

```bash
#!/usr/bin/env bash

set -u
set -o pipefail

# ------------------------------------------------------------
# Server Health Checker
# ------------------------------------------------------------
# Provides a quick operational overview of a Linux server.
#
# Exit codes:
#   0 = Healthy
#   1 = Warning
#   2 = Critical
#   3 = Script/dependency error
# ------------------------------------------------------------

readonly MEMORY_WARNING=80
readonly MEMORY_CRITICAL=90

readonly DISK_WARNING=80
readonly DISK_CRITICAL=90

readonly CPU_WARNING=80
readonly CPU_CRITICAL=100

SCRIPT_DIR=$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")" && pwd)
readonly SCRIPT_DIR

readonly LOG_DIR="$SCRIPT_DIR/logs"
readonly LOG_FILE="$LOG_DIR/server-health.log"

OVERALL_STATUS="HEALTHY"

HOSTNAME_VALUE=""
OS_NAME=""
KERNEL_VERSION=""
UPTIME_VALUE=""
TIMESTAMP=""
IP_ADDRESSES=""
LOGGED_USERS=""

CPU_MODEL=""
CPU_CORES=0
LOAD_1="0"
LOAD_5="0"
LOAD_15="0"
CPU_LOAD_PERCENT=0
CPU_STATUS="UNKNOWN"

MEMORY_USAGE=0
MEMORY_STATUS="UNKNOWN"

DISK_USAGE=0
DISK_STATUS="UNKNOWN"


check_dependencies() {
    local commands=(
        hostname
        uname
        uptime
        who
        wc
        free
        df
        ip
        lscpu
        nproc
        awk
        paste
        date
    )

    local cmd
    local missing=0

    for cmd in "${commands[@]}"; do
        if ! command -v "$cmd" >/dev/null 2>&1; then
            printf 'ERROR: Required command not found: %s\n' "$cmd" >&2
            missing=1
        fi
    done

    if (( missing != 0 )); then
        exit 3
    fi
}


update_status() {
    local new_status="$1"

    if [[ "$new_status" == "CRITICAL" ]]; then
        OVERALL_STATUS="CRITICAL"

    elif [[ "$new_status" == "WARNING" &&
            "$OVERALL_STATUS" == "HEALTHY" ]]; then

        OVERALL_STATUS="WARNING"
    fi
}


collect_system_info() {
    HOSTNAME_VALUE=$(hostname)
    KERNEL_VERSION=$(uname -r)
    TIMESTAMP=$(date '+%Y-%m-%d %H:%M:%S')

    if [[ -r /etc/os-release ]]; then
        # shellcheck disable=SC1091
        . /etc/os-release
        OS_NAME=${PRETTY_NAME:-Unknown}
    else
        OS_NAME="Unknown"
    fi

    local uptime_raw

    if uptime_raw=$(uptime -p 2>/dev/null); then
        UPTIME_VALUE=${uptime_raw#up }
    else
        UPTIME_VALUE="Unable to determine"
    fi

    LOGGED_USERS=$(who | wc -l | awk '{print $1}')

    IP_ADDRESSES=$(
        ip -o -4 addr show scope global 2>/dev/null |
        awk '{split($4,a,"/"); print a[1]}' |
        paste -sd ',' -
    )

    if [[ -z "$IP_ADDRESSES" ]]; then
        IP_ADDRESSES="Not detected"
    fi

    CPU_MODEL=$(
        lscpu |
        awk -F: '/Model name/ {
            gsub(/^[ \t]+/, "", $2)
            print $2
            exit
        }'
    )

    if [[ -z "$CPU_MODEL" ]]; then
        CPU_MODEL="Unknown"
    fi
}


check_cpu() {
    CPU_CORES=$(nproc)

    read -r LOAD_1 LOAD_5 LOAD_15 < /proc/loadavg

    CPU_LOAD_PERCENT=$(
        awk -v load="$LOAD_1" -v cpu="$CPU_CORES" \
        'BEGIN {
            if (cpu > 0)
                printf "%.0f", (load/cpu)*100
            else
                print 0
        }'
    )

    if (( CPU_LOAD_PERCENT >= CPU_CRITICAL )); then
        CPU_STATUS="CRITICAL"

    elif (( CPU_LOAD_PERCENT >= CPU_WARNING )); then
        CPU_STATUS="WARNING"

    else
        CPU_STATUS="OK"
    fi

    update_status "$CPU_STATUS"
}


check_memory() {
    MEMORY_USAGE=$(
        free |
        awk '/^Mem:/ {
            if ($2 > 0)
                printf "%.0f", (($2-$7)/$2)*100
            else
                print 0
        }'
    )

    if (( MEMORY_USAGE >= MEMORY_CRITICAL )); then
        MEMORY_STATUS="CRITICAL"

    elif (( MEMORY_USAGE >= MEMORY_WARNING )); then
        MEMORY_STATUS="WARNING"

    else
        MEMORY_STATUS="OK"
    fi

    update_status "$MEMORY_STATUS"
}


check_disk() {
    DISK_USAGE=$(
        df -P -x tmpfs -x devtmpfs 2>/dev/null |
        awk 'NR>1 {
            gsub("%","",$5)

            if (($5 + 0) > max)
                max=$5 + 0
        }

        END {
            print max + 0
        }'
    )

    if (( DISK_USAGE >= DISK_CRITICAL )); then
        DISK_STATUS="CRITICAL"

    elif (( DISK_USAGE >= DISK_WARNING )); then
        DISK_STATUS="WARNING"

    else
        DISK_STATUS="OK"
    fi

    update_status "$DISK_STATUS"
}


generate_report() {
    printf '%s\n' \
        "============================================================"
    printf '%s\n' \
        "                 SERVER HEALTH REPORT"
    printf '%s\n' \
        "============================================================"

    printf '%-19s %s\n' "Timestamp:" "$TIMESTAMP"
    printf '%-19s %s\n' "Hostname:" "$HOSTNAME_VALUE"
    printf '%-19s %s\n' "Operating System:" "$OS_NAME"
    printf '%-19s %s\n' "Kernel:" "$KERNEL_VERSION"
    printf '%-19s %s\n' "Uptime:" "$UPTIME_VALUE"
    printf '%-19s %s\n' "IP Address(es):" "$IP_ADDRESSES"

    printf '\n%s\n' \
        "------------------------ CPU -------------------------------"

    printf '%-19s %s\n' "CPU Model:" "$CPU_MODEL"
    printf '%-19s %s\n' "Logical CPUs:" "$CPU_CORES"
    printf '%-19s %s %s %s\n' \
        "Load Average:" "$LOAD_1" "$LOAD_5" "$LOAD_15"
    printf '%-19s %s%%\n' \
        "Load/CPU Ratio:" "$CPU_LOAD_PERCENT"
    printf '%-19s %s\n' \
        "CPU Load Status:" "$CPU_STATUS"

    printf '\n%s\n' \
        "----------------------- MEMORY -----------------------------"

    printf '%-19s %s%%\n' \
        "Memory Usage:" "$MEMORY_USAGE"
    printf '%-19s %s\n' \
        "Memory Status:" "$MEMORY_STATUS"

    printf '\n%s\n' \
        "------------------------ DISK ------------------------------"

    printf '%-19s %s%%\n' \
        "Highest Disk Use:" "$DISK_USAGE"
    printf '%-19s %s\n' \
        "Disk Status:" "$DISK_STATUS"

    printf '\n%s\n' \
        "------------------------ USERS -----------------------------"

    printf '%-19s %s\n' \
        "Logged-in Users:" "$LOGGED_USERS"

    printf '\n%s\n' \
        "------------------------------------------------------------"

    printf '%-19s %s\n' \
        "Overall Status:" "$OVERALL_STATUS"

    printf '%s\n' \
        "============================================================"
}


write_log() {
    mkdir -p "$LOG_DIR"

    {
        printf '[%s] ' "$TIMESTAMP"
        printf 'host=%s ' "$HOSTNAME_VALUE"
        printf 'cpu=%s%% ' "$CPU_LOAD_PERCENT"
        printf 'memory=%s%% ' "$MEMORY_USAGE"
        printf 'disk=%s%% ' "$DISK_USAGE"
        printf 'status=%s\n' "$OVERALL_STATUS"
    } >> "$LOG_FILE"
}


return_health_status() {
    case "$OVERALL_STATUS" in

        HEALTHY)
            return 0
            ;;

        WARNING)
            return 1
            ;;

        CRITICAL)
            return 2
            ;;

        *)
            return 3
            ;;
    esac
}


main() {
    check_dependencies
    collect_system_info
    check_cpu
    check_memory
    check_disk

    generate_report
    write_log

    return_health_status
}


main "$@"
exit $?
```

# 48. Troubleshooting: High Load but CPU Does Not Look Busy

Suppose the script reports:

```text
Load/CPU Ratio: 150%
CPU Load Status: CRITICAL
```

but `top` does not show CPUs at 100%.

That can happen.

Linux load average is not simply CPU utilization.

Processes waiting in certain uninterruptible states, often related to storage or I/O, can contribute to load.

Investigate:

```bash
top
```

Then:

```bash
vmstat 1
```

You may also inspect process states:

```bash
ps -eo pid,stat,comm,%cpu,%mem --sort=-%cpu | head
```

High load can therefore indicate:

* CPU contention
* Storage latency
* I/O waits
* Blocked processes
* Other resource contention

Do not diagnose solely from one metric.

# 49. Troubleshooting: Memory Appears Almost Full

Linux memory frequently confuses new engineers.

You might run:

```bash
free -h
```

and see very little memory under `free`.

That does not automatically mean the server is running out of RAM.

Linux intentionally uses available memory for cache.

Pay attention to:

```text
available
```

as well as:

* Swap activity
* Memory pressure
* Application behavior
* OOM events
* Sustained trends

Check:

```bash
free -h
```

Then:

```bash
vmstat 1
```

Look for swap activity.

You can also check for out-of-memory events:

```bash
journalctl -k | grep -i -E 'out of memory|oom'
```

Our project uses available memory when calculating its simple memory-health signal.

# 52. Why We Did Not Automatically Restart Anything

Notice that our script reports health but does not execute actions such as:

```bash
systemctl restart nginx
```

or:

```bash
reboot
```

A health checker and a remediation tool are different things.

Automatic remediation can be useful, but it introduces risk.

Imagine a script sees high memory usage and automatically restarts an application.

The memory usage might actually be caused by:

* A legitimate traffic spike
* A database problem
* A downstream outage
* A memory leak
* A scheduled batch process

Blindly restarting the service could:

* Interrupt customers
* Hide evidence
* Make diagnosis harder
* Trigger cascading failures

Observe first.

Remediate intentionally.
