# Project 13: Docker Cleanup Script

Docker hosts accumulate resources over time.

You may find:

* Stopped containers
* Dangling images
* Old unused images
* Unused networks
* Build cache
* Old anonymous volumes
* Layers left behind by repeated CI/CD builds

Eventually:

```text
/var/lib/docker
```

can consume a significant amount of disk space.

But Docker cleanup is not the place for careless automation.

A stopped container may contain useful forensic evidence.

An unused image may be required for an emergency rollback.

A network may belong to an application that is temporarily stopped.

A volume that appears unused may contain irreplaceable application data.

That means:

```text
Unused does not automatically mean safe to delete.
```

In this project, we will build:

```text
docker-cleanup.sh
```

The script will:

* Check Docker disk consumption
* Detect stopped containers
* Detect dangling images
* Report unused images
* Detect unused networks
* Inspect build cache
* Display cleanup candidates
* Support age-based filtering
* Support `--dry-run`
* Require explicit approval before deletion
* Avoid automatic volume deletion
* Report reclaimed space
* Return meaningful exit codes

Docker provides individual `prune` commands for containers, images, networks, volumes, and build cache. `docker system prune` combines several cleanup operations. Docker intentionally does not remove these objects automatically because unused resources may still matter operationally.

The most important rule for this entire project is:

```text
Inspect first.
Delete second.
```

# 1. Real-World Scenario

Imagine a Linux Docker host begins generating alerts:

```text
Filesystem /var is 92% full
```

You SSH to the server and run:

```bash
df -h
```

Example:

```text
Filesystem      Size  Used Avail Use%
/dev/xvda1       50G   46G  4.0G  92%
```

You already completed a disk investigation in Project 2.

You discover:

```text
/var/lib/docker
```

is consuming most of the space.

You run:

```bash
docker system df
```

and see:

```text
TYPE            TOTAL     ACTIVE    SIZE      RECLAIMABLE
Images          34        6         18.4GB    12.1GB
Containers      21        4         3.8GB     2.7GB
Local Volumes   12        8         6.2GB     900MB
Build Cache     86        0         14.7GB    14.7GB
```

There appears to be significant reclaimable space.

The dangerous response would be:

```bash
docker system prune -af --volumes
```

without investigation.

Instead, a production-minded engineer asks:

```text
Which containers are stopped?

How old are they?

Why were they stopped?

Which images are dangling?

Which tagged images are unused?

Could those images be needed for rollback?

Which networks are unused?

How much build cache exists?

Are any volumes storing persistent data?

What does the cleanup policy allow us to remove?
```

That is what this project teaches.

# 4. Docker Resource Lifecycle

When you run:

```bash
docker run nginx
```

Docker may create:

```text
Image
Container
Network attachment
Writable container layer
Logs
```

When the container stops, Docker does not automatically delete all those resources.

That is intentional.

Docker generally takes a conservative approach to garbage collection and only removes unused resources when explicitly instructed.

# 10. Docker Image Size Can Be Misleading

Run:

```bash
docker images
```

You may see:

```text
REPOSITORY        TAG        IMAGE ID       SIZE
veriqta-api       latest     abc123         900MB
veriqta-api       v1.2.0     def456         890MB
```

Docker images share layers.

The displayed image sizes are not always equivalent to unique disk consumption because multiple images can reuse the same layers. Docker's documentation notes that image sizes can include shared parent layers.

Use:

```bash
docker system df
```

for a more useful Docker-wide disk view.

# 14. Why Stopped Containers May Matter

Suppose:

```text
veriqta-api-old
```

is stopped.

Before deleting it, ask:

```text
Was it intentionally preserved?

Does someone need docker logs from it?

Was it part of a failed deployment?

Does its writable layer contain temporary forensic evidence?

Is it referenced in an incident investigation?
```

`docker container prune` removes stopped containers, so it should never be used casually on an incident host. Docker supports filters such as `until` and labels to narrow cleanup scope.

# 17. Dangling Images

Run:

```bash
docker image ls \
    --filter dangling=true
```

Example:

```text
REPOSITORY    TAG       IMAGE ID       SIZE
<none>        <none>    abc123         480MB
<none>        <none>    def456         510MB
```

A dangling image is untagged and not referenced by a container. Docker's default `docker image prune` targets dangling images.

---

# 18. Dangling Does Not Mean Corrupted

A dangling image is not necessarily broken.

It may be left behind after:

* Rebuilding an image
* Retagging
* Replacing an image tag
* CI/CD builds

These images are frequently good cleanup candidates, but still inspect your environment.

---

# 19. Remove Dangling Images Manually

Docker provides:

```bash
docker image prune
```

It prompts before removal unless forced.

For this project, we will not execute it automatically until candidates are displayed.

---

# 20. Unused Tagged Images

This is more dangerous.

An image may be:

```text
veriqta-api:v1.9
```

and not currently referenced by a container.

But it may exist specifically for rollback.

Docker:

```bash
docker image prune -a
```

removes all images not referenced by a container, not merely dangling ones.

That makes:

```text
-a
```

a much more destructive option.

---

# 21. Rollback Risk

Imagine:

```text
Current version: v2.0
Previous version: v1.9
```

You deploy:

```text
v2.0
```

The old container is removed.

The image:

```text
veriqta-api:v1.9
```

is now technically unused.

Then cleanup runs:

```bash
docker image prune -a
```

and removes it.

Minutes later, v2.0 fails.

Your emergency rollback now requires pulling or rebuilding v1.9 instead of starting immediately.

That is why cleanup policy must consider rollback strategy.

---

# 22. Age Filters

Docker prune commands support filters.

Example:

```bash
docker image prune \
    --filter "until=24h"
```

or for all unused images:

```bash
docker image prune \
    -a \
    --filter "until=240h"
```

Docker documents `until` filtering for images and other prune commands.

Age filters reduce risk.

They do not eliminate it.

---

# 23. Why Age Alone Is Not Enough

An image can be:

```text
90 days old
```

but still be your approved rollback artifact.

A stopped container can be:

```text
14 days old
```

but preserved for investigation.

Good cleanup combines:

```text
age
resource state
labels
operational policy
```

rather than one condition.

```bash

```

```text

```

---

# 29. Why Build Cache Matters

Build cache speeds future builds.

Removing it may:

```text
free disk space
```

but also:

```text
make future builds slower
increase dependency downloads
increase registry traffic
```

So cleanup has a performance tradeoff.

---

# 30. `--keep-storage`

For build cache, Docker supports:

```bash
docker builder prune \
    --keep-storage 5GB
```

This can be more intelligent than deleting every eligible cache object.

# 32. Why Volumes Are Excluded

Docker's `docker system prune` does not remove volumes by default. Its volume behavior must be explicitly requested, reflecting the higher risk of deleting persistent data.

Our script will follow an even stricter rule:

```text
Volume deletion is outside automatic cleanup.
```

Docker has:


For this project:

```text
REPORT volumes.

```

Docker provides:

```bash

```

It can remove:

* Stopped containers
* Unused networks
* Dangling images
* Unused build cache

# 35. Why We Will Not Start With `docker system prune`

The command combines several resource categories.

Our teaching goal is:

```text
Understand each resource type before deleting anything.
```

So our script performs targeted cleanup:

```text
containers
images
networks
build cache
```

separately.

This makes the impact easier to understand and audit.

# 36. Safety Rules

Our script will follow these rules:

```text
1. Dry-run by default.

2. Display candidates first.

3. Never delete running containers.

4. Never automatically delete volumes.

5. Do not use image prune -a by default.

6. Use age filters.

7. Require --execute before deletion.

8. Require explicit confirmation.

9. Log what cleanup categories were requested.

10. Show Docker disk usage before and after.
```

# 38. Beginner Version

The beginner version will:


Create:

```bash

```

Add:

```bash
#!/usr/bin/env bash

set -u
set -o pipefail

printf '%s\n' \
    "============================================================"

printf '%s\n' \
    "              DOCKER CLEANUP INSPECTION"

printf '%s\n' \
    "============================================================"


if ! command -v docker >/dev/null 2>&1; then

    printf 'ERROR: Docker CLI not found.\n' >&2
    exit 3
fi


if ! docker info >/dev/null 2>&1; then

    printf 'ERROR: Cannot communicate with Docker daemon.\n' >&2
    exit 3
fi


printf '\nDocker Disk Usage:\n'
docker system df


printf '\nStopped Containers:\n'

docker ps \
    -a \
    --filter status=exited \
    --format 'table {{.ID}}\t{{.Image}}\t{{.Status}}\t{{.Names}}'


printf '\nDangling Images:\n'

docker image ls \
    --filter dangling=true \
    --format 'table {{.ID}}\t{{.Repository}}\t{{.Tag}}\t{{.Size}}'


printf '\nDocker Networks:\n'

docker network ls


printf '\nBuild Cache:\n'

docker system df |
grep 'Build Cache' || true


printf '\n%s\n' \
    "DRY RUN COMPLETE"

printf '%s\n' \
    "Nothing was deleted."
```

# 43. Dry Run Is Not Docker's Prune Prompt

Docker prune commands normally show a warning prompt unless forced.

But that is not the same as a proper dry run.

For example, Docker notes that the image prune confirmation prompt does not provide a complete candidate list.

Our script's dry run will explicitly display resource candidates before any prune command is executed.

# 45. Container Age Filter

Production cleanup should avoid immediately deleting a container that stopped five seconds ago.

Example policy:

```text
Only stopped containers older than 24 hours.
```

Prune command:

```bash
docker container prune \
    --filter "until=24h"
```

Docker officially supports `until` filtering for container prune.

---

# 46. Container Labels

Imagine important containers use:

```text
cleanup.protect=true
```

Labels can help define cleanup policy.

Example:

```bash
docker ps \
    -a \
    --filter label=cleanup.protect=true
```

A mature environment can use resource labels to protect or identify disposable resources.

---

# 47. Avoid Negative-Filter Assumptions

Be careful with label filtering.

Docker prune supports both positive and negative label conditions in some resource types, but preview capabilities are not always symmetrical. Docker specifically warns that negative image filters cannot always be predicted with `docker image ls`.

For automation safety:

```text
Prefer clearly labelled cleanup candidates
```

over complex exclusion logic when possible.

```text

```



# 58. Production-Oriented Script

Use:

```bash
#!/usr/bin/env bash

set -u
set -o pipefail

umask 077

# ------------------------------------------------------------------
# Docker Cleanup Script
# ------------------------------------------------------------------
#
# SAFETY:
#   Dry-run is the default.
#   No resources are removed unless --execute is supplied.
#   Volumes are never deleted by this script.
#
# Exit codes:
#   0 = Successful inspection / cleanup
#   1 = Cleanup completed with warnings
#   2 = Docker cleanup operation failed
#   3 = Input/configuration/preflight error
#
# ------------------------------------------------------------------

MODE="DRY_RUN"

CLEAN_CONTAINERS=false
CLEAN_DANGLING_IMAGES=false
CLEAN_ALL_IMAGES=false
CLEAN_NETWORKS=false
CLEAN_BUILD_CACHE=false

ACK_IMAGE_RISK=false

OLDER_THAN="168h"

OVERALL_STATUS="SUCCESS"

SCRIPT_DIR=$(
    cd -- "$(dirname -- "${BASH_SOURCE[0]}")" &&
    pwd
)

readonly SCRIPT_DIR

LOG_DIR="$SCRIPT_DIR/logs"
LOG_FILE="$LOG_DIR/docker-cleanup.log"


show_help() {

    cat <<EOF
Usage:
  $0 [options]

Safety:
  Dry-run is the default.
  No Docker resources are deleted unless --execute is supplied.
  Volumes are never deleted by this script.

Options:

  --dry-run
      Inspect cleanup candidates only.
      This is the default.

  --execute
      Allow selected cleanup actions.

  --containers
      Clean stopped containers matching the age filter.

  --dangling-images
      Clean dangling images matching the age filter.

  --all-unused-images
      Clean all unused images matching the age filter.
      HIGHER RISK.

  --acknowledge-image-risk
      Required with --all-unused-images.

  --networks
      Clean unused networks matching the age filter.

  --build-cache
      Clean build cache matching the age filter.

  --all-safe
      Select:
        stopped containers
        dangling images
        unused networks
        build cache

      Does NOT select:
        all unused tagged images
        volumes

  --older-than DURATION
      Docker until filter.
      Default: 168h

      Examples:
        24h
        72h
        168h
        240h

  --help
      Show this help.

Examples:

  $0 --dry-run

  $0 \
    --dry-run \
    --containers \
    --dangling-images

  $0 \
    --execute \
    --containers \
    --dangling-images \
    --older-than 168h

  $0 \
    --execute \
    --all-safe \
    --older-than 240h

  $0 \
    --execute \
    --all-unused-images \
    --acknowledge-image-risk \
    --older-than 720h
EOF
}


parse_arguments() {

    while [[ $# -gt 0 ]]; do

        case "$1" in

            --dry-run)

                MODE="DRY_RUN"
                shift
                ;;

            --execute)

                MODE="EXECUTE"
                shift
                ;;

            --containers)

                CLEAN_CONTAINERS=true
                shift
                ;;

            --dangling-images)

                CLEAN_DANGLING_IMAGES=true
                shift
                ;;

            --all-unused-images)

                CLEAN_ALL_IMAGES=true
                shift
                ;;

            --acknowledge-image-risk)

                ACK_IMAGE_RISK=true
                shift
                ;;

            --networks)

                CLEAN_NETWORKS=true
                shift
                ;;

            --build-cache)

                CLEAN_BUILD_CACHE=true
                shift
                ;;

            --all-safe)

                CLEAN_CONTAINERS=true
                CLEAN_DANGLING_IMAGES=true
                CLEAN_NETWORKS=true
                CLEAN_BUILD_CACHE=true

                shift
                ;;

            --older-than)

                [[ $# -ge 2 ]] || {
                    printf 'ERROR: --older-than requires a value.\n' >&2
                    exit 3
                }

                OLDER_THAN="$2"
                shift 2
                ;;

            --help|-h)

                show_help
                exit 0
                ;;

            *)

                printf 'ERROR: Unknown option: %s\n' \
                    "$1" >&2

                exit 3
                ;;
        esac

    done
}


check_dependencies() {

    local commands=(
        docker
        date
        mkdir
    )

    local cmd

    for cmd in "${commands[@]}"; do

        if ! command -v "$cmd" >/dev/null 2>&1; then

            printf 'ERROR: Required command missing: %s\n' \
                "$cmd" >&2

            exit 3
        fi
    done
}


validate_age_filter() {

    if [[ ! "$OLDER_THAN" =~ ^[0-9]+(s|m|h)$ ]]; then

        printf 'ERROR: Unsupported --older-than format: %s\n' \
            "$OLDER_THAN" >&2

        printf 'Use values such as 24h, 72h, or 168h.\n' >&2

        exit 3
    fi
}


check_docker_daemon() {

    if ! docker info >/dev/null 2>&1; then

        printf 'ERROR: Cannot communicate with Docker daemon.\n' \
            >&2

        printf 'Check Docker status, context, and permissions.\n' \
            >&2

        exit 3
    fi
}


validate_options() {

    if [[ "$CLEAN_ALL_IMAGES" == true &&
          "$CLEAN_DANGLING_IMAGES" == true ]]; then

        printf '%s\n' \
            'ERROR: Choose --dangling-images or --all-unused-images, not both.' \
            >&2

        exit 3
    fi


    if [[ "$CLEAN_ALL_IMAGES" == true &&
          "$ACK_IMAGE_RISK" != true ]]; then

        printf '%s\n' \
            'ERROR: --all-unused-images requires --acknowledge-image-risk.' \
            >&2

        printf '%s\n' \
            'Unused tagged images may be required for rollback.' \
            >&2

        exit 3
    fi
}


select_default_inspection() {

    if [[ "$CLEAN_CONTAINERS" == false &&
          "$CLEAN_DANGLING_IMAGES" == false &&
          "$CLEAN_ALL_IMAGES" == false &&
          "$CLEAN_NETWORKS" == false &&
          "$CLEAN_BUILD_CACHE" == false ]]; then

        CLEAN_CONTAINERS=true
        CLEAN_DANGLING_IMAGES=true
        CLEAN_NETWORKS=true
        CLEAN_BUILD_CACHE=true
    fi
}


log_message() {

    local level="$1"
    local message="$2"

    mkdir -p "$LOG_DIR"

    printf '[%s] [%s] %s\n' \
        "$(date '+%Y-%m-%d %H:%M:%S')" \
        "$level" \
        "$message" \
        >> "$LOG_FILE"
}


print_banner() {

    printf '%s\n' \
        "=========================================================================="

    printf '%s\n' \
        "                         DOCKER CLEANUP REPORT"

    printf '%s\n' \
        "=========================================================================="

    printf '\n%-24s %s\n' \
        "Mode:" "$MODE"

    printf '%-24s %s\n' \
        "Age Filter:" "$OLDER_THAN"

    printf '%-24s %s\n' \
        "Volumes:" "REPORT ONLY - NEVER DELETED"

    printf '\n'
}


show_disk_usage() {

    printf '%s\n' \
        "------------------------- DOCKER DISK USAGE ------------------------------"

    docker system df

    printf '\n'
}


show_running_containers() {

    printf '%s\n' \
        "------------------------- RUNNING CONTAINERS -----------------------------"

    docker ps \
        --format 'table {{.ID}}\t{{.Image}}\t{{.Status}}\t{{.Names}}'

    printf '\n'
}


show_stopped_containers() {

    [[ "$CLEAN_CONTAINERS" == true ]] || return


    printf '%s\n' \
        "-------------------- STOPPED CONTAINER CANDIDATES ------------------------"

    docker ps \
        -a \
        --filter status=exited \
        --filter "until=$OLDER_THAN" \
        --format 'table {{.ID}}\t{{.Image}}\t{{.CreatedAt}}\t{{.Status}}\t{{.Names}}'

    printf '\n'
}


show_dangling_images() {

    [[ "$CLEAN_DANGLING_IMAGES" == true ]] || return


    printf '%s\n' \
        "----------------------- DANGLING IMAGE CANDIDATES ------------------------"

        --format 'table {{.ID}}\t{{.CreatedAt}}\t{{.Size}}'

    printf '%s\n' \

    printf '\n'
}


show_all_images_warning() {

    [[ "$CLEAN_ALL_IMAGES" == true ]] || return

    docker image ls \

    printf '%s\n' \
        "Docker may remove tagged images not referenced by any container."

    printf '%s\n' \
        "Those images may include rollback versions."

    printf '\n'
}

    [[ "$CLEAN_NETWORKS" == true ]] || return


    printf '%s\n' \

    printf '\n'

    printf '%s\n' \
        "Only networks Docker considers unused will be eligible for pruning."

    printf '\n'
}

    [[ "$CLEAN_BUILD_CACHE" == true ]] || return


    printf '%s\n' \
        "----------------------------- BUILD CACHE --------------------------------"

    docker system df |
        grep 'Build Cache' || true

    printf '\n'
}

    printf '%s\n' \
        "--------------------------- VOLUME INVENTORY -----------------------------"

    printf '\n'

    printf '%s\n' \
        "SAFETY: This script does not delete Docker volumes."

    printf '\n'
}


show_plan() {

    printf '%s\n' \
        "----------------------------- CLEANUP PLAN -------------------------------"


    if [[ "$CLEAN_CONTAINERS" == true ]]; then

        printf '%-28s %s\n' \
            "Stopped containers:" \
            "SELECTED"
    fi


    if [[ "$CLEAN_DANGLING_IMAGES" == true ]]; then

        printf '%-28s %s\n' \
            "Dangling images:" \
            "SELECTED"
    fi


    if [[ "$CLEAN_ALL_IMAGES" == true ]]; then

        printf '%-28s %s\n' \
            "All unused images:" \
            "SELECTED - HIGHER RISK"
    fi


    if [[ "$CLEAN_NETWORKS" == true ]]; then

        printf '%-28s %s\n' \
            "Unused networks:" \
            "SELECTED"
    fi


    if [[ "$CLEAN_BUILD_CACHE" == true ]]; then

        printf '%-28s %s\n' \
            "Build cache:" \
            "SELECTED"
    fi


    printf '%-28s %s\n' \
        "Volumes:" \
        "NEVER DELETED"

    printf '\n'
}


confirm_cleanup() {

    local answer

    if [[ "$MODE" != "EXECUTE" ]]; then
        return
    fi


    printf '%s\n' \
        "=========================================================================="

    printf '%s\n' \
        "DESTRUCTIVE ACTION REQUESTED"

    printf '%s\n' \
        "Review the resources above before continuing."

    printf '%s\n' \
        "Type DELETE to execute the selected Docker cleanup actions."

    printf '%s\n' \
        "Anything else cancels."

    printf '%s\n' \
        "=========================================================================="

    printf 'Confirmation: '

    read -r answer


    if [[ "$answer" != "DELETE" ]]; then

        printf '\nCleanup cancelled.\n'

        log_message \
            "INFO" \
            "cleanup_cancelled"

        exit 0
    fi
}


cleanup_containers() {

    [[ "$CLEAN_CONTAINERS" == true ]] || return


    printf '\nCleaning stopped containers older than %s...\n' \
        "$OLDER_THAN"


    if docker container prune \
        --force \
        --filter "until=$OLDER_THAN"; then

        log_message \
            "INFO" \
            "container_prune success older_than=$OLDER_THAN"

    else

        OVERALL_STATUS="FAILURE"

        log_message \
            "ERROR" \
            "container_prune failed"

        return 1
    fi
}


cleanup_dangling_images() {

    [[ "$CLEAN_DANGLING_IMAGES" == true ]] || return


    printf '\nCleaning dangling images older than %s...\n' \
        "$OLDER_THAN"


    if docker image prune \
        --force \
        --filter "until=$OLDER_THAN"; then

        log_message \
            "INFO" \
            "dangling_image_prune success older_than=$OLDER_THAN"

    else

        OVERALL_STATUS="FAILURE"

        log_message \
            "ERROR" \
            "dangling_image_prune failed"

        return 1
    fi
}


cleanup_all_unused_images() {

    [[ "$CLEAN_ALL_IMAGES" == true ]] || return


    printf '\nCleaning ALL unused images older than %s...\n' \
        "$OLDER_THAN"


    if docker image prune \
        --all \
        --force \
        --filter "until=$OLDER_THAN"; then

        log_message \
            "WARNING" \
            "all_unused_image_prune success older_than=$OLDER_THAN"

    else

        OVERALL_STATUS="FAILURE"

        log_message \
            "ERROR" \
            "all_unused_image_prune failed"

        return 1
    fi
}


cleanup_networks() {

    [[ "$CLEAN_NETWORKS" == true ]] || return


    printf '\nCleaning unused networks older than %s...\n' \
        "$OLDER_THAN"


    if docker network prune \
        --force \
        --filter "until=$OLDER_THAN"; then

        log_message \
            "INFO" \
            "network_prune success older_than=$OLDER_THAN"

    else

        OVERALL_STATUS="FAILURE"

        log_message \
            "ERROR" \
            "network_prune failed"

        return 1
    fi
}


cleanup_build_cache() {

    [[ "$CLEAN_BUILD_CACHE" == true ]] || return


    printf '\nCleaning build cache older than %s...\n' \
        "$OLDER_THAN"


    if docker builder prune \
        --force \
        --filter "until=$OLDER_THAN"; then

        log_message \
            "INFO" \
            "builder_prune success older_than=$OLDER_THAN"

    else

        OVERALL_STATUS="FAILURE"

        log_message \
            "ERROR" \
            "builder_prune failed"

        return 1
    fi
}


perform_cleanup() {

    [[ "$MODE" == "EXECUTE" ]] || return


    cleanup_containers || true

    cleanup_dangling_images || true

    cleanup_all_unused_images || true

    cleanup_networks || true

    cleanup_build_cache || true
}


print_final_status() {

    printf '\n%s\n' \
        "--------------------------- FINAL DOCKER STATE ---------------------------"

    docker system df

    printf '\n'


    if [[ "$MODE" == "DRY_RUN" ]]; then

        printf '%s\n' \
            "DRY RUN COMPLETE"

        printf '%s\n' \
            "No Docker resources were deleted."

    else

        printf 'Cleanup Status: %s\n' \
            "$OVERALL_STATUS"
    fi


    printf '%s\n' \
        "=========================================================================="
}


return_status() {

    case "$OVERALL_STATUS" in

        SUCCESS)
            return 0
            ;;

        WARNING)
            return 1
            ;;

        FAILURE)
            return 2
            ;;

        *)
            return 3
            ;;
    esac
}


main() {

    parse_arguments "$@"

    check_dependencies

    validate_age_filter

    check_docker_daemon

    validate_options

    select_default_inspection


    log_message \
        "INFO" \
        "run_started mode=$MODE older_than=$OLDER_THAN containers=$CLEAN_CONTAINERS dangling_images=$CLEAN_DANGLING_IMAGES all_images=$CLEAN_ALL_IMAGES networks=$CLEAN_NETWORKS build_cache=$CLEAN_BUILD_CACHE"


    print_banner

    show_disk_usage

    show_running_containers

    show_stopped_containers

    show_dangling_images

    show_all_images_warning

    show_networks

    show_build_cache

    show_volumes

    show_plan


    if [[ "$MODE" == "DRY_RUN" ]]; then

        print_final_status

        log_message \
            "INFO" \
            "dry_run_complete"

        return 0
    fi


    confirm_cleanup

    perform_cleanup

    print_final_status


    log_message \
        "INFO" \
        "run_complete status=$OVERALL_STATUS"


    return_status
}


main "$@"
exit $?
```

```text

commit-b
commit-c
commit-d
```

```text
recent cache
recent release images
approved rollback images
```

# 92. Registry vs Local Images

Removing an image locally is safer if:

```text
the exact immutable image still exists in the registry
```

For example:

```text
registry.example.com/veriqta-api@sha256:...
```

But do not assume:

```text
we can always pull it again
```

without verifying:

* Registry retention
* Credentials
* Network availability
* Immutable tag/digest
* Artifact lifecycle

# 93. Tags Are Not Always Immutable

Suppose:

```text
veriqta-api:latest
```

changes over time.

Deleting an older local image and pulling:

```text
latest
```

later may fetch a completely different build.

Production deployments should prefer immutable references such as:

```text
version tags
digests
```

where appropriate.

Before aggressive image cleanup, know:

```text
How many releases must remain locally?

Can rollback pull from registry?

Are images immutable?

How fast must rollback occur?

What happens if registry is unavailable?
```

Cleanup is tied to deployment design.


Maybe:

* Active containers
* Active volumes


still reports:

Investigate:

Deleted-but-open files can still consume filesystem blocks.

# 110. Troubleshooting: Deleted Image Needed Later

If cleanup removed an image required for deployment:

```text
pull from registry
```

if available.

But the deeper root cause is:

```text
cleanup policy removed a required artifact
```

Fix the policy rather than relying on emergency re-pulls.

# 111. Troubleshooting: Build Became Slow


Investigate build-cache policy.

Use:

```text

```

or:

```text
--keep-storage
```

rather than deleting all useful cache.

Docker supports `--keep-storage` for builder cache management.

# 112. Troubleshooting: Network Missing

Well-defined Compose or infrastructure configuration should recreate required networks when the stack starts.

If not, your environment may be relying on manually created infrastructure.

Document that dependency.

* Generated files

# 117. Security: Cleanup Requires Authority

A script capable of removing Docker objects should be restricted.

Do not make it world-writable.

# 118. Production Upgrade: Locking

Two cleanup processes running simultaneously can create confusing behavior.

Add:

```bash

```

to ensure only one cleanup process runs at a time.


Or implement locking inside the script.

# 119. Production Upgrade: Signals

Use:

```bash
trap
```

for:

```text

INT

```

so the script can:

* Clean temporary files
* Release locks
* Log interruption

Do not try to rollback every prune operation.

Deleted Docker objects generally cannot simply be recreated from the cleanup script.

---

# 120. Cleanup Is Often Irreversible

If you delete:

```text
stopped container writable layer
```

the script cannot magically restore it.

If you remove:

```text
locally unique image
```

it may be gone.

Therefore:

```text
prevention is more important than rollback
```

for destructive cleanup.

---

# 121. Production Upgrade: Maintenance Window

On sensitive Docker hosts, cleanup may only be allowed during:

```text
maintenance windows
```

because disk activity, cache loss, or operator mistakes can affect production.

Automation should respect operational policy.

---

# 122. Production Upgrade: Alert Instead of Delete

A mature workflow might be:

```text

        |

        |
        v
Generate cleanup report
        |
        v
Engineer approval
        |
        v

```

This is safer than unattended deletion.

# 123. Why `docker system prune -a` Is Not Our Default

Docker documents that regular system prune removes stopped containers, unused networks, dangling images, and unused build cache. Adding `-a` broadens image removal to unused images beyond just dangling ones.

That scope can be acceptable in some environments.

But for a teaching project focused on safe operations:

```text
targeted cleanup is easier to reason about.
```

---

# 124. Why `--volumes` Is Especially Sensitive

Persistent data can outlive the container using it.

An application may be intentionally stopped.

Its volume can therefore appear unused.

Deleting it could convert:

```text
temporary downtime
```

into:

```text
permanent data loss
```

Our script refuses to perform volume cleanup.
