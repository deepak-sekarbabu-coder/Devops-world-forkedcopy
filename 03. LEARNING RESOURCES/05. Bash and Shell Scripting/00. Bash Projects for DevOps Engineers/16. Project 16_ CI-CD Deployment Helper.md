# Project 16: CI/CD Deployment Helper

A deployment pipeline should not simply run:

```bash
deploy application
```

and assume success.

A reliable deployment process should verify:

```text
What application are we deploying?

Which exact version?

Which environment?

Does the artifact exist?

Are required tools available?

Did deployment succeed?

Did the application become healthy?

If health verification fails, what happens next?
```

In this project, we will build:

```text
deploy.sh
```

Usage:

```bash
./deploy.sh payments-api 2.7.4 production
```

The script will accept:

```text
APPLICATION
VERSION
ENVIRONMENT
```

and follow this workflow:

```text
CI Pipeline
     |
     v
Validate Parameters
     |
     v
Validate Environment
     |
     v
Locate / Download Artifact
     |
     v
Pre-Deployment Checks
     |
     v
Deploy
     |
     v
Verify Deployment
     |
     v
Health Check
     |
  +--+----------------+
  |                   |
  v                   v
SUCCESS              FAILURE
                      |
                      v
                Rollback Decision
```

The central production lesson is:

```text
Deployment success is not the same as command success.

A deployment is successful only when the intended version is running and the application passes validation.
```

---

# 1. Real-World Scenario

Imagine VERIQTA operates:

```text
payments-api
```

Current production version:

```text
2.7.3
```

A CI pipeline builds:

```text
2.7.4
```

The pipeline now needs to deploy it.

A weak deployment step might run:

```bash
kubectl set image deployment/payments-api \
    payments-api=registry.example/payments-api:2.7.4
```

and then immediately report:

```text
Deployment successful.
```

But many things can still go wrong:

* Image does not exist
* Kubernetes rejects deployment
* Pods enter ImagePullBackOff
* Pods enter CrashLoopBackOff
* Readiness probes fail
* Deployment never becomes available
* `/health` returns 503
* Application reports `"status":"unhealthy"`
* Wrong environment was targeted
* Wrong version was deployed

Our deployment helper will validate all of these boundaries.

---

# 5. Why Explicit Version Matters

Do not deploy:

```text
latest
```

when you can deploy:

```text
2.7.4
```

A deployment should be traceable.

You should be able to answer:

```text
Exactly what was deployed?
```

with:

```text
payments-api:2.7.4
```

not:

```text
whatever latest pointed to at the time
```

---

# 6. Better Than Mutable Tags

Preferred:

```text
payments-api:2.7.4
```

Stronger:

```text
payments-api@sha256:...
```

because digests are immutable references.

A production system may build with a version tag for readability while resolving and deploying an immutable digest.

---

# 7. Environment Validation

Allowed environments might be:

```text
development
staging
production
```

Do not accept arbitrary values such as:

```text
prodction
produuction
prd
```

and guess what they mean.

Reject unknown environments.

---

# 8. Why Environment Validation Matters

A typo in:

```text
production
```

should cause:

```text
ERROR
```

not:

```text
create a new namespace
deploy somewhere unexpected
use default credentials
```

Fail early.

---

# 9. CI/CD Exit Codes

A pipeline understands:

```text
0
```

as success.

Anything non-zero means failure.

But meaningful exit codes make troubleshooting easier.

We will use:

```text
0 = deployment successful
1 = health verification failed
2 = deployment command failed
3 = validation/configuration error
4 = artifact/image validation failed
5 = rollback failed
```

---

# 10. Stop on Failure

A deployment helper must not continue blindly after a failed critical step.

For example:

```text
Artifact download failed
        |
        v
STOP
```

not:

```text
Artifact download failed
        |
        v
Attempt deployment anyway
```

# 11. `set -e` Discussion


For this project, we will use:

That makes the control flow easier to understand.

# 20. Beginner Script

```bash
#!/usr/bin/env bash

set -u
set -o pipefail

APPLICATION="${1:-}"
VERSION="${2:-}"
ENVIRONMENT="${3:-}"

REGISTRY="registry.example.com"


if [[ -z "$APPLICATION" ||
      -z "$VERSION" ||
      -z "$ENVIRONMENT" ]]; then

    printf 'Usage: %s APPLICATION VERSION ENVIRONMENT\n' \
        "$0" >&2

    exit 3
fi


case "$ENVIRONMENT" in

    development|staging|production)
        ;;
    *)
        printf 'ERROR: Invalid environment: %s\n' \
            "$ENVIRONMENT" >&2

        exit 3
        ;;
esac


if ! command -v kubectl >/dev/null 2>&1; then

    printf 'ERROR: kubectl is required.\n' >&2
    exit 3
fi


if ! command -v curl >/dev/null 2>&1; then

    printf 'ERROR: curl is required.\n' >&2
    exit 3
fi


NAMESPACE="$ENVIRONMENT"

IMAGE="${REGISTRY}/${APPLICATION}:${VERSION}"

DEPLOYMENT="$APPLICATION"

CONTAINER="$APPLICATION"


printf 'Application: %s\n' "$APPLICATION"
printf 'Version:     %s\n' "$VERSION"
printf 'Environment: %s\n' "$ENVIRONMENT"
printf 'Namespace:   %s\n' "$NAMESPACE"
printf 'Image:       %s\n' "$IMAGE"


if ! kubectl get namespace \
    "$NAMESPACE" \
    >/dev/null 2>&1; then

    printf 'ERROR: Namespace not found: %s\n' \
        "$NAMESPACE" >&2

    exit 3
fi


if ! kubectl get deployment \
    "$DEPLOYMENT" \
    -n "$NAMESPACE" \
    >/dev/null 2>&1; then

    printf 'ERROR: Deployment not found: %s\n' \
        "$DEPLOYMENT" >&2

    exit 3
fi


if ! kubectl set image \
    "deployment/$DEPLOYMENT" \
    "$CONTAINER=$IMAGE" \
    -n "$NAMESPACE"; then

    printf 'ERROR: Deployment command failed.\n' >&2
    exit 2
fi


if ! kubectl rollout status \
    "deployment/$DEPLOYMENT" \
    -n "$NAMESPACE" \
    --timeout=180s; then

    printf 'ERROR: Deployment rollout failed.\n' >&2
    exit 2
fi


printf 'Deployment rollout completed.\n'

exit 0
```

# 22. Pre-Deployment Validation

Before changing Kubernetes, validate:

```text
Application
Version
Environment
Namespace
Deployment
Container
Cluster context
Artifact/image
Required tools
```

# 23. Version Validation

For this project we accept:

```text
2.7.4
2.7.4-rc1
2026.09.11
```

but reject:

```text
empty
spaces
shell control characters
```

A simple conservative validation:

```bash
[[ "$VERSION" =~ ^[A-Za-z0-9._-]+$ ]]
```

# 24. Application Validation

Use:

```bash
[[ "$APPLICATION" =~ ^[a-z0-9][a-z0-9-]*$ ]]
```

This works well for Kubernetes-style names.

Do not pass arbitrary user input directly into commands without validation.

# 31. Immutable Artifacts

The strongest production pattern is:

```text
Build once
Deploy the same artifact everywhere
```

Do not rebuild:

```text
2.7.4
```

separately for:

```text
development
staging
production
```

That means you are not promoting the same artifact.

---

# 32. Build Once, Deploy Many

Correct pattern:

```text
Source Commit
     |
     v
Build
     |
     v
Artifact 2.7.4
     |
     +------------+
     |            |
     v            v
 Staging      Production
```

Not:

```text
Source
 |
 +-- build staging artifact
 |
 `-- build production artifact
```

unless there is a very deliberate reason.

# 34. Production Confirmation

Interactive confirmation is useful for manual deployments.

But CI pipelines are non-interactive.

So our production script will support:

```text
--approve
```

for non-interactive production execution.

Production deployment without:

```text
--approve
```

should stop.

---

# 35. Why `--approve` Matters

This prevents someone from accidentally running:

```bash
./deploy.sh payments-api 2.7.4 production
```

from their terminal and immediately changing production.

The pipeline can intentionally run:

```bash
./deploy.sh \
    payments-api \
    2.7.4 \
    production \
    --approve
```

after its own approval process.

---

# 42. Health Check Logic

The deployment helper will verify:

```text
HTTP 200
valid JSON
.status == expected
```

If health fails:

```text
deployment is considered unsuccessful
```

even if Kubernetes rollout succeeded.

---

# 43. Health Retries

Applications may need time after rollout.

Instead of one immediate request:

```text
attempt 1
```

use:

```text
attempt 1
wait
attempt 2
wait
attempt 3
```

with bounded retries.

Example:

```text
10 attempts
5 seconds apart
```

---

# 44. Do Not Retry Forever

A pipeline must eventually fail.

Infinite retries can:

* Hide broken deployments
* Consume runner time
* Delay incident response
* Block later pipeline stages

Use bounded health validation.

---

# 45. Previous Deployment Version

Before updating the Deployment, capture the currently configured image.

Example:

```bash
kubectl get deployment \
    payments-api \
    -n production \
    -o jsonpath='{.spec.template.spec.containers[?(@.name=="payments-api")].image}'
```

Example:

```text
registry.example.com/payments-api:2.7.3
```

Store this as:

```text
PREVIOUS_IMAGE
```

---

# 46. Why Capture Previous Image First

If the new release fails health checks, you need to know:

```text
What was running before?
```

Do not try to reconstruct that from memory during an incident.

---

# 47. Rollback Strategy

We have two possible rollback approaches:

```text
kubectl rollout undo
```

or:

```text
explicitly restore PREVIOUS_IMAGE
```

For teaching, we will use the explicit previous image.

That makes rollback intent visible.

---

# 48. Rollback Is Not Always Safe

Automatic rollback can also be dangerous.

Examples:

* Database migration is not backward compatible
* New schema already written
* Previous version has security issue
* External API contract changed

Therefore our script will support:

```text
--rollback-on-failure
```

rather than making rollback unconditional.

---

# 49. Default Failure Behavior

By default:

```text
new deployment unhealthy
        |
        v
STOP
        |
        v
report failure
```

If:

```text
--rollback-on-failure
```

was supplied:

```text
new deployment unhealthy
        |
        v
restore previous image
        |
        v
wait for rollout
        |
        v
verify rollback health
```

# 50. Complete Production Script

```bash
#!/usr/bin/env bash

set -u
set -o pipefail

umask 077

# ------------------------------------------------------------------
# CI/CD Deployment Helper
# ------------------------------------------------------------------
#
# Usage:
#   ./deploy.sh APPLICATION VERSION ENVIRONMENT [options]
#
# Exit codes:
#   0 = deployment successful
#   1 = application health verification failed
#   2 = deployment/rollout failed
#   3 = validation/configuration error
#   4 = artifact/image validation failed
#   5 = rollback failed
#
# ------------------------------------------------------------------

APPLICATION=""
VERSION=""
ENVIRONMENT=""

DRY_RUN=false
APPROVED=false
ROLLBACK_ON_FAILURE=false

REGISTRY="${REGISTRY:-registry.example.com}"

HEALTH_URL="${HEALTH_URL:-}"
EXPECTED_HEALTH_STATUS="${EXPECTED_HEALTH_STATUS:-healthy}"

HEALTH_ATTEMPTS="${HEALTH_ATTEMPTS:-10}"
HEALTH_INTERVAL="${HEALTH_INTERVAL:-5}"
HEALTH_TIMEOUT="${HEALTH_TIMEOUT:-10}"

ROLLOUT_TIMEOUT="${ROLLOUT_TIMEOUT:-180s}"

DEPLOYMENT_ID="${DEPLOYMENT_ID:-manual}"
COMMIT_SHA="${COMMIT_SHA:-unknown}"
DEPLOY_ACTOR="${DEPLOY_ACTOR:-unknown}"

NAMESPACE=""
DEPLOYMENT=""
CONTAINER=""

IMAGE=""
PREVIOUS_IMAGE=""

SCRIPT_DIR=$(
    cd -- "$(dirname -- "${BASH_SOURCE[0]}")" &&
    pwd
)

readonly SCRIPT_DIR

LOG_DIR="$SCRIPT_DIR/logs"
LOG_FILE="$LOG_DIR/deployments.log"

TEMP_DIR=""


show_help() {

    cat <<EOF
Usage:
  $0 APPLICATION VERSION ENVIRONMENT [options]

Required:
  APPLICATION
  VERSION
  ENVIRONMENT

Supported environments:
  development
  staging
  production

Options:

  --dry-run
      Validate deployment and display actions without modifying Kubernetes.

  --approve
      Required for production execution.

  --rollback-on-failure
      Restore the previously configured image if rollout or health validation fails.

  --help
      Display help.

Environment variables:

  REGISTRY
      Container registry.
      Default: registry.example.com

  HEALTH_URL
      Application health endpoint.
      Required for real deployment.

  EXPECTED_HEALTH_STATUS
      Expected .status value.
      Default: healthy

  HEALTH_ATTEMPTS
      Number of health-check attempts.
      Default: 10

  HEALTH_INTERVAL
      Seconds between health checks.
      Default: 5

  HEALTH_TIMEOUT
      curl maximum request time.
      Default: 10

  ROLLOUT_TIMEOUT
      kubectl rollout timeout.
      Default: 180s

  DEPLOYMENT_ID
  COMMIT_SHA
  DEPLOY_ACTOR
      Optional pipeline metadata.

Examples:

  $0 \
    payments-api \
    2.7.4 \
    staging \
    --dry-run

  HEALTH_URL=https://payments.example.com/health \
  $0 \
    payments-api \
    2.7.4 \
    production \
    --approve

  HEALTH_URL=https://payments.example.com/health \
  $0 \
    payments-api \
    2.7.4 \
    production \
    --approve \
    --rollback-on-failure
EOF
}


cleanup() {

    if [[ -n "${TEMP_DIR:-}" &&
          -d "$TEMP_DIR" ]]; then

        rm -rf -- "$TEMP_DIR"
    fi
}


trap cleanup EXIT INT TERM


log_message() {

    local level="$1"
    local step="$2"
    local message="$3"

    mkdir -p "$LOG_DIR"

    printf '[%s] level=%s application=%s version=%s environment=%s deployment_id=%s commit=%s actor=%s step=%s message=%s\n' \
        "$(date '+%Y-%m-%d %H:%M:%S')" \
        "$level" \
        "${APPLICATION:-unknown}" \
        "${VERSION:-unknown}" \
        "${ENVIRONMENT:-unknown}" \
        "$DEPLOYMENT_ID" \
        "$COMMIT_SHA" \
        "$DEPLOY_ACTOR" \
        "$step" \
        "$message" \
        >> "$LOG_FILE"
}


fail() {

    local exit_code="$1"
    local step="$2"
    local message="$3"

    printf 'ERROR: %s\n' \
        "$message" >&2

    log_message \
        "ERROR" \
        "$step" \
        "$message"

    exit "$exit_code"
}


is_positive_integer() {
    [[ "$1" =~ ^[0-9]+$ ]] && (( $1 > 0 ))
}


parse_arguments() {

    local -a positional=()

    while [[ $# -gt 0 ]]; do

        case "$1" in

            --dry-run)

                DRY_RUN=true
                shift
                ;;

            --approve)

                APPROVED=true
                shift
                ;;

            --rollback-on-failure)

                ROLLBACK_ON_FAILURE=true
                shift
                ;;

            --help|-h)

                show_help
                exit 0
                ;;

            --*)

                printf 'ERROR: Unknown option: %s\n' \
                    "$1" >&2

                exit 3
                ;;

            *)

                positional+=("$1")
                shift
                ;;
        esac
    done


    if (( ${#positional[@]} != 3 )); then

        printf '%s\n\n' \
            'ERROR: APPLICATION VERSION ENVIRONMENT are required.' \
            >&2

        show_help
        exit 3
    fi


    APPLICATION="${positional[0]}"
    VERSION="${positional[1]}"
    ENVIRONMENT="${positional[2]}"
}


validate_inputs() {

    if [[ ! "$APPLICATION" =~ ^[a-z0-9][a-z0-9-]*$ ]]; then

        fail \
            3 \
            "validate" \
            "Invalid application name: $APPLICATION"
    fi


    if [[ ! "$VERSION" =~ ^[A-Za-z0-9._-]+$ ]]; then

        fail \
            3 \
            "validate" \
            "Invalid version: $VERSION"
    fi


    case "$ENVIRONMENT" in

        development|staging|production)
            ;;

        *)

            fail \
                3 \
                "validate" \
                "Unsupported environment: $ENVIRONMENT"
            ;;
    esac


    if ! is_positive_integer "$HEALTH_ATTEMPTS"; then

        fail \
            3 \
            "validate" \
            "HEALTH_ATTEMPTS must be a positive integer"
    fi


    if ! is_positive_integer "$HEALTH_INTERVAL"; then

        fail \
            3 \
            "validate" \
            "HEALTH_INTERVAL must be a positive integer"
    fi


    if ! is_positive_integer "$HEALTH_TIMEOUT"; then

        fail \
            3 \
            "validate" \
            "HEALTH_TIMEOUT must be a positive integer"
    fi


    if [[ "$ENVIRONMENT" == "production" &&
          "$DRY_RUN" == false &&
          "$APPROVED" != true ]]; then

        fail \
            3 \
            "validate" \
            "Production deployment requires --approve"
    fi


    if [[ "$DRY_RUN" == false &&
          -z "$HEALTH_URL" ]]; then

        fail \
            3 \
            "validate" \
            "HEALTH_URL is required for deployment execution"
    fi
}


check_dependencies() {

    local commands=(
        kubectl
        curl
        jq
        docker
        date
        mkdir
        mktemp
        rm
        sleep
    )

    local cmd

    for cmd in "${commands[@]}"; do

        if ! command -v "$cmd" >/dev/null 2>&1; then

            fail \
                3 \
                "dependencies" \
                "Required command missing: $cmd"
        fi
    done
}


resolve_environment() {

    case "$ENVIRONMENT" in

        development)
            NAMESPACE="development"
            ;;

        staging)
            NAMESPACE="staging"
            ;;

        production)
            NAMESPACE="production"
            ;;
    esac


    DEPLOYMENT="$APPLICATION"
    CONTAINER="$APPLICATION"

    IMAGE="${REGISTRY}/${APPLICATION}:${VERSION}"
}


check_cluster_access() {

    if ! kubectl cluster-info >/dev/null 2>&1; then

        fail \
            3 \
            "cluster-access" \
            "Cannot communicate with Kubernetes cluster"
    fi
}


print_context() {

    local context

    context=$(
        kubectl config current-context 2>/dev/null || true
    )

    if [[ -z "$context" ]]; then

        fail \
            3 \
            "cluster-access" \
            "Unable to determine Kubernetes context"
    fi


    printf 'Kubernetes Context: %s\n' \
        "$context"

    log_message \
        "INFO" \
        "context" \
        "kubernetes_context=$context"
}


validate_namespace() {

    if ! kubectl get namespace \
        "$NAMESPACE" \
        >/dev/null 2>&1; then

        fail \
            3 \
            "namespace" \
            "Namespace not found or inaccessible: $NAMESPACE"
    fi
}


validate_deployment() {

    if ! kubectl get deployment \
        "$DEPLOYMENT" \
        -n "$NAMESPACE" \
        >/dev/null 2>&1; then

        fail \
            3 \
            "deployment" \
            "Deployment not found: $DEPLOYMENT"
    fi
}


validate_container() {

    local container_exists

    container_exists=$(
        kubectl get deployment \
            "$DEPLOYMENT" \
            -n "$NAMESPACE" \
            -o json |
        jq -r \
            --arg container "$CONTAINER" '
              [
                .spec.template.spec.containers[]
                | select(.name == $container)
              ]
              | length
            '
    )


    if [[ "$container_exists" != "1" ]]; then

        fail \
            3 \
            "deployment" \
            "Container not found in Deployment: $CONTAINER"
    fi
}


validate_image() {

    printf 'Validating image: %s\n' \
        "$IMAGE"


    if ! docker manifest inspect \
        "$IMAGE" \
        >/dev/null 2>&1; then

        fail \
            4 \
            "artifact" \
            "Container image could not be verified: $IMAGE"
    fi


    log_message \
        "INFO" \
        "artifact" \
        "image_verified=$IMAGE"
}


capture_previous_image() {

    PREVIOUS_IMAGE=$(
        kubectl get deployment \
            "$DEPLOYMENT" \
            -n "$NAMESPACE" \
            -o json |
        jq -r \
            --arg container "$CONTAINER" '
              .spec.template.spec.containers[]
              | select(.name == $container)
              | .image
            '
    )


    if [[ -z "$PREVIOUS_IMAGE" ||
          "$PREVIOUS_IMAGE" == "null" ]]; then

        fail \
            3 \
            "pre-deployment" \
            "Unable to determine previous container image"
    fi


    printf 'Current Image:     %s\n' \
        "$PREVIOUS_IMAGE"

    log_message \
        "INFO" \
        "pre-deployment" \
        "previous_image=$PREVIOUS_IMAGE"
}

    printf '%s\n' \
        "=========================================================================="

    printf '%s\n' \
        "                         DEPLOYMENT PLAN"

    printf '%s\n' \
        "=========================================================================="

    printf '\n%-24s %s\n' \

    printf '%-24s %s\n' \

    printf '%-24s %s\n' \

    printf '%-24s %s\n' \

    printf '%-24s %s\n' \

}

        "$IMAGE" \
        "$NAMESPACE"

        "INFO" \
        "dry-run" \
        "dry_run_complete"

    exit 0
}


deploy_image() {

    printf '\nDeploying %s...\n' \
        "$IMAGE"


    if ! kubectl set image \
        "deployment/$DEPLOYMENT" \
        "$CONTAINER=$IMAGE" \
        -n "$NAMESPACE"; then

        log_message \
            "ERROR" \
            "deploy" \
            "kubectl_set_image_failed"

        return 1
    fi


    log_message \
        "INFO" \
        "deploy" \
        "image_update_submitted=$IMAGE"

    return 0
}


wait_for_rollout() {

    printf '\nWaiting for rollout...\n'


    if ! kubectl rollout status \
        "deployment/$DEPLOYMENT" \
        -n "$NAMESPACE" \
        --timeout="$ROLLOUT_TIMEOUT"; then

        log_message \
            "ERROR" \
            "rollout" \
            "rollout_failed"

        return 1
    fi


    log_message \
        "INFO" \
        "rollout" \
        "rollout_completed"

    return 0
}


verify_deployed_image() {

    local deployed_image

    deployed_image=$(
        kubectl get deployment \
            "$DEPLOYMENT" \
            -n "$NAMESPACE" \
            -o json |
        jq -r \
            --arg container "$CONTAINER" '
              .spec.template.spec.containers[]
              | select(.name == $container)
              | .image
            '
    )


    if [[ "$deployed_image" != "$IMAGE" ]]; then

        log_message \
            "ERROR" \
            "verify-image" \
            "expected=$IMAGE actual=$deployed_image"

        return 1
    fi


    printf 'Deployment image verified: %s\n' \
        "$deployed_image"


    log_message \
        "INFO" \
        "verify-image" \
        "image_verified=$deployed_image"

    return 0
}


check_health_once() {

    local response_file
    local metadata
    local curl_status
    local http_code
    local response_time
    local actual_status


    response_file="$TEMP_DIR/health-response.json"


    metadata=$(
        curl \
            -sS \
            --connect-timeout 5 \
            --max-time "$HEALTH_TIMEOUT" \
            -o "$response_file" \
            -w '%{http_code}|%{time_total}' \
            "$HEALTH_URL" \
            2>"$TEMP_DIR/curl-error.log"
    )

    curl_status=$?


    if (( curl_status != 0 )); then

        return 1
    fi


    IFS='|' read -r \
        http_code \
        response_time \
        <<< "$metadata"


    if [[ "$http_code" != "200" ]]; then

        log_message \
            "WARNING" \
            "health" \
            "http_status=$http_code response_time=$response_time"

        return 1
    fi


    if ! jq empty \
        "$response_file" \
        >/dev/null 2>&1; then

        log_message \
            "WARNING" \
            "health" \
            "invalid_json"

        return 1
    fi


    actual_status=$(
        jq -r \
            '.status // empty' \
            "$response_file"
    )


    if [[ "$actual_status" != "$EXPECTED_HEALTH_STATUS" ]]; then

        log_message \
            "WARNING" \
            "health" \
            "expected_status=$EXPECTED_HEALTH_STATUS actual_status=${actual_status:-missing}"

        return 1
    fi


    printf 'Health check passed: HTTP %s, status=%s, time=%ss\n' \
        "$http_code" \
        "$actual_status" \
        "$response_time"


    log_message \
        "INFO" \
        "health" \
        "http_status=$http_code application_status=$actual_status response_time=$response_time"

    return 0
}


verify_application_health() {

    local attempt=1


    printf '\nVerifying application health...\n'


    while (( attempt <= HEALTH_ATTEMPTS )); do

        printf 'Health attempt %s/%s...\n' \
            "$attempt" \
            "$HEALTH_ATTEMPTS"


        if check_health_once; then

            return 0
        fi


        if (( attempt < HEALTH_ATTEMPTS )); then

            sleep "$HEALTH_INTERVAL"
        fi


        ((attempt+=1))
    done


    log_message \
        "ERROR" \
        "health" \
        "health_verification_failed_after_${HEALTH_ATTEMPTS}_attempts"

    return 1
}


rollback_deployment() {

    printf '\nROLLBACK REQUESTED\n'

    printf 'Restoring previous image:\n%s\n' \
        "$PREVIOUS_IMAGE"


    log_message \
        "WARNING" \
        "rollback" \
        "rollback_started previous_image=$PREVIOUS_IMAGE"


    if ! kubectl set image \
        "deployment/$DEPLOYMENT" \
        "$CONTAINER=$PREVIOUS_IMAGE" \
        -n "$NAMESPACE"; then

        log_message \
            "ERROR" \
            "rollback" \
            "failed_to_restore_previous_image"

        return 1
    fi


    if ! kubectl rollout status \
        "deployment/$DEPLOYMENT" \
        -n "$NAMESPACE" \
        --timeout="$ROLLOUT_TIMEOUT"; then

        log_message \
            "ERROR" \
            "rollback" \
            "rollback_rollout_failed"

        return 1
    fi


    log_message \
        "INFO" \
        "rollback" \
        "rollback_rollout_completed"

    return 0
}


handle_deployment_failure() {

    local failure_type="$1"
    local original_exit="$2"


    if [[ "$ROLLBACK_ON_FAILURE" != true ]]; then

        printf '%s\n' \
            "Rollback is disabled."

        return "$original_exit"
    fi


    if ! rollback_deployment; then

        printf 'ERROR: Rollback failed.\n' >&2
        return 5
    fi


    printf '%s\n' \
        "Previous deployment image restored."


    if [[ -n "$HEALTH_URL" ]]; then

        printf '%s\n' \
            "Rechecking application after rollback..."

        if ! verify_application_health; then

            printf '%s\n' \
                "ERROR: Rollback completed but health verification still fails." \
                >&2

            log_message \
                "ERROR" \
                "rollback-health" \
                "rollback_health_failed"

            return 5
        fi
    fi


    log_message \
        "WARNING" \
        "deployment" \
        "new_release_failed failure_type=$failure_type rollback_successful=true"


    return "$original_exit"
}


main() {

    parse_arguments "$@"

    validate_inputs

    check_dependencies

    resolve_environment

    TEMP_DIR=$(
        mktemp -d
    )


    log_message \
        "INFO" \
        "start" \
        "deployment_started"


    check_cluster_access

    print_context

    validate_namespace

    validate_deployment

    validate_container

    validate_image

    capture_previous_image

    print_plan


    if [[ "$DRY_RUN" == true ]]; then
        perform_dry_run
    fi


    if [[ "$IMAGE" == "$PREVIOUS_IMAGE" ]]; then

        printf '%s\n' \
            "Requested image is already configured."

        log_message \
            "INFO" \
            "pre-deployment" \
            "requested_image_already_configured"

        if verify_application_health; then
            exit 0
        else
            exit 1
        fi
    fi


    if ! deploy_image; then

        handle_deployment_failure \
            "deployment_command" \
            2

        exit $?
    fi


    if ! wait_for_rollout; then

        handle_deployment_failure \
            "rollout" \
            2

        exit $?
    fi


    if ! verify_deployed_image; then

        handle_deployment_failure \
            "image_verification" \
            2

        exit $?
    fi


    if ! verify_application_health; then

        handle_deployment_failure \
            "health_check" \
            1

        exit $?
    fi


    printf '\n%s\n' \
        "=========================================================================="

    printf '%s\n' \
        "                       DEPLOYMENT SUCCESSFUL"

    printf '%s\n' \
        "=========================================================================="

    printf '\n%-22s %s\n' \
        "Application:" "$APPLICATION"

    printf '%-22s %s\n' \
        "Version:" "$VERSION"

    printf '%-22s %s\n' \
        "Environment:" "$ENVIRONMENT"

    printf '%-22s %s\n' \
        "Image:" "$IMAGE"

    printf '%-22s %s\n' \
        "Health:" "PASSED"

    printf '%s\n' \
        "=========================================================================="


    log_message \
        "INFO" \
        "complete" \
        "deployment_successful image=$IMAGE"


    exit 0
}


main "$@"
```

```text
registry.example.com/payments-api@sha256:...

```

Tag:

```text
2.7.4
```

is human-friendly.

Digest:

```text
sha256:...
```

is immutable.

Production pipelines often benefit from storing both.

# 80. Production Upgrade: Locking

Two pipelines should not deploy:

```text
payments-api
```

to:

```text
production
```

simultaneously.

Add a deployment lock.

Possible approaches:

* CI concurrency groups
* Environment locks
* Deployment queues
* `flock` for local scripts

Pipeline-native locking is usually better than local filesystem locking on ephemeral runners.

# 81. Why Concurrent Deployments Are Dangerous

Example:

```text
Pipeline A deploys 2.7.4
Pipeline B deploys 2.7.5
```

Both read previous image:

```text
2.7.3
```

Then one fails and rolls back.

You can accidentally overwrite the newer deployment.

Concurrency must be controlled.

# 84. Rollback Caveat: Database Migrations

Suppose version `2.7.4` runs:

```text
ALTER TABLE ...
```

and modifies the database schema.

Then restoring:

```text
2.7.3
```

might fail against the new schema.

That is why:

```text
automatic rollback
```

must match application architecture.

---

# 85. Expand-Contract Database Pattern

A safer database deployment approach often separates schema evolution.

Example:

```text
Release A:
Add new schema while keeping old compatibility

Release B:
Application begins using new schema

Later:
Remove old schema
```

This makes rollback more feasible.

Workflow may become:

```text
Validate
   |
   v
Deploy migration
   |
   v
Verify migration
   |
   v
Deploy application
   |
   v

```

But database migration tooling deserves its own project.

# 87. Production Upgrade: Canary Deployment

Instead of replacing every pod immediately:

```text
2.7.3 -> 2.7.4
```

you might deploy:

```text
95% traffic -> 2.7.3
5% traffic  -> 2.7.4
```

Then evaluate:

* Errors
* Latency
* Business metrics

before increasing traffic.

# 88. Production Upgrade: Blue-Green

Another strategy:

```text
BLUE
2.7.3

GREEN
2.7.4
```

Deploy green.

Test it.

Then switch traffic.

Rollback becomes a traffic switch rather than rebuilding infrastructure.
