# Bash Skills Every DevOps Engineer Should Know

## Shell Fundamentals

Understand:

- Shell
- Terminal
- Bash
- Command interpreter
- Interactive shell
- Non-interactive shell
- Login shell
- PATH
- Exit status

---

## Shebang

Understand:

```bash
#!/usr/bin/env bash
````

and:

```bash
#!/bin/bash
```

Understand why interpreter selection matters.

---

## Variables

Practice:

```bash
environment="production"
application="api"
```

Reference them safely:

```bash
echo "$environment"
echo "$application"
```

Learn why quoting matters.

---

## Environment Variables

Practice:

```bash
export APP_ENV="production"
```

Inspect:

```bash
env
printenv
```

Understand the difference between:

* Shell variables
* Environment variables
* CI/CD variables
* Secrets

---

## Arguments

Understand:

```bash
$0
$1
$2
$#
$@
$?
```

These are especially important for reusable automation scripts.

---

## Quoting

Understand the differences between:

```bash
'$variable'
"$variable"
$variable
```

Poor quoting is one of the most common causes of shell scripting bugs.

Read:

[https://mywiki.wooledge.org/Quotes](https://mywiki.wooledge.org/Quotes)

---

## Conditions

Practice:

```bash
if
elif
else
fi
```

Understand:

```bash
test
[ ]
[[ ]]
```

---

## Loops

Practice:

```bash
for
while
until
```

Do not write:

```bash
for file in $(ls)
```

for processing filenames.

Learn safe filename handling.

---

## Functions

Use functions to divide scripts into logical reusable operations.

Example:

```bash
check_service() {
    systemctl is-active "$1"
}
```

---

## Exit Codes

Understand:

```bash
$?
```

Conventionally:

```text
0 = success
non-zero = failure or another condition
```

CI/CD systems depend heavily on correct exit codes.

---

## Pipes

Understand:

```bash
command1 | command2
```

Learn how data moves between commands.

---

## Redirection

Understand:

```bash
>
>>
<
2>
2>&1
```

Know the difference between:

* Standard input
* Standard output
* Standard error

---

## Command Substitution

Practice:

```bash
hostname=$(hostname)
```

and:

```bash
current_date=$(date)
```

---

## Text Processing

Learn:

```bash
grep
sed
awk
cut
sort
uniq
tr
wc
```

These tools make Bash extremely useful for infrastructure automation.

---

## JSON and YAML

Learn how Bash works with:

```bash
jq
yq
```

Example:

```bash
curl -s https://example.com/api | jq .
```

This becomes especially useful when scripting:

* APIs
* Kubernetes
* Cloud CLIs
* CI/CD systems

---

## APIs

Learn:

```bash
curl
```

Understand:

* GET
* POST
* Headers
* Authentication
* JSON
* HTTP status codes
* Exit codes

---

## Error Handling

Understand:

```bash
set -e
set -u
set -o pipefail
```

and:

```bash
set -euo pipefail
```

Do not copy these options blindly.

Understand what each one changes.

---

## Signals and Cleanup

Learn:

```bash
trap
```

Use it when scripts need cleanup during:

* Interruptions
* Failures
* Termination

---

## Debugging

Run:

```bash
bash -n script.sh
```

to check syntax.

Run:

```bash
bash -x script.sh
```

to trace execution.

Be careful when tracing scripts containing secrets.

# Production Troubleshooting Practice

A DevOps engineer should eventually be able to investigate:

* Script works manually but fails in cron
* Script works locally but fails in CI/CD
* Environment variable is missing
* PATH is different
* Permission denied
* Command not found
* API call fails
* Script exits unexpectedly
* Pipeline hides an error
* Loop processes filenames incorrectly
* Variable expands unexpectedly
* Script hangs
* Background process does not terminate
* Cleanup does not happen after failure
* Secret appears in logs
* Script produces different results on another shell

Use a systematic troubleshooting flow:

**Reproduce → Identify Failed Command → Check Exit Code → Inspect Environment → Check Permissions → Check Dependencies → Trace Execution → Fix → Verify**

# Production Bash Rules

For serious DevOps automation:

* Keep scripts in Git.
* Review scripts before production use.
* Use ShellCheck.
* Quote variables correctly.
* Validate external input.
* Check exit codes.
* Handle failures explicitly.
* Log useful information.
* Never log secrets.
* Avoid unnecessary root execution.
* Avoid `eval` unless there is a very specific justified reason.
* Avoid destructive operations without validation.
* Make automation idempotent where appropriate.
* Document required dependencies.
* Test scripts in a safe environment.
* Know when Bash has become too complex.

---

# When Bash Is No Longer the Right Tool

Bash is excellent for connecting commands and automating operating-system tasks.

Consider moving to Python, Go, or another language when your script develops:

* Complex data structures
* Extensive API logic
* Large amounts of JSON processing
* Complex business logic
* Extensive error handling
* Large test suites
* Many modules
* Significant concurrency
* Long-term application-like maintenance

Knowing when not to use Bash is also a DevOps engineering skill.
