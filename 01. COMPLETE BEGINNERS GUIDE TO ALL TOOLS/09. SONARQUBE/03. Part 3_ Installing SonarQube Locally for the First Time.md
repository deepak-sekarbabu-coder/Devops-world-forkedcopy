In Parts 1 and 2, we deliberately avoided installation.

# 4. Hardware Prerequisites

Software requires resources.

SonarQube is not just a static website.

Remember from Part 2 that a SonarQube Server contains multiple important processes:

```text
Web
Compute Engine
Elasticsearch
```

Each requires CPU and memory.

Elasticsearch also performs indexing and uses disk storage.

Therefore, before installation, check:

```text
CPU
RAM
Disk
Architecture
```

Sonar's current documentation uses the following as a starting point for a small-scale installation:

```text
CPU:
2 cores

RAM:
4 GB

Disk:
approximately 30 GB starting point

System:
64-bit
```

These are starting requirements rather than guarantees for every workload. Production sizing depends on code volume, concurrency, analysis frequency, and usage.

---

# 5. Why SonarQube Needs Several Gigabytes of Memory

A beginner might think:

> It is just a code-quality dashboard. Why would it need several gigabytes?

Because you are not running only one tiny process.

Conceptually:

```text
Laptop RAM
   │
   ├── Operating System
   │
   ├── SonarQube Web JVM
   │
   ├── Compute Engine JVM
   │
   ├── Elasticsearch JVM
   │
   └── Browser + Other Applications
```

If your computer is already under heavy memory pressure, SonarQube may:

* start slowly
* fail during startup
* experience Elasticsearch failures
* become unresponsive
* be killed by the operating system

So before blaming SonarQube:

```text
Check available system resources.
```

# 12. Java Requirements

SonarQube Server is written for the Java ecosystem and its ZIP-based installation requires Java.

This means:

```text
SonarQube ZIP
+
Compatible Java Runtime
=
Server can start
```

Without a compatible Java runtime:

```text
SonarQube
↓
Cannot launch correctly
```

Current SonarQube Server host documentation lists Java 17 or Java 21 for ZIP-based server installations. For this course, use **Java 21** because it is the stronger forward-looking choice and also aligns better with current scanner runtime direction.

---

# 13. Important Distinction: Server Java vs Project Java

Suppose your application was written using:

```text
Java 11
```

Does that mean SonarQube Server must run with Java 11?

No.

These are different things.

```text
Application Java version
           ≠
SonarQube Server runtime Java
```

For example:

```text
Java Application
uses Java 17
      ↓
SonarScanner
      ↓
SonarQube Server
runs using Java 21
```

Sonar's server Java requirement concerns the Java runtime needed to operate SonarQube itself, not necessarily the Java language version of the project you analyze.

# 15. What If You See "command not found"?

Example:

```text
zsh: command not found: java
```

This generally means either:

1. Java is not installed.

or:

2. Java exists but is not available through your current command path.

On macOS:

```bash
/usr/libexec/java_home -V
```

This can list Java installations that macOS recognizes.

---

# 16. What Is JAVA_HOME?

You will often encounter:

```text
JAVA_HOME
```

`JAVA_HOME` is an environment variable pointing to a Java installation.

Example:

```text
/Library/Java/JavaVirtualMachines/jdk-21.jdk/Contents/Home
```

Applications can use it to locate Java.

Check it with:

```bash
echo $JAVA_HOME
```

Possible output:

```text
/Library/Java/JavaVirtualMachines/jdk-21.jdk/Contents/Home
```

If nothing appears:

```text
$
```

the environment variable may not currently be configured.

However, do not assume that means Java cannot work. The system may still locate Java through `PATH`.

---

# 17. JAVA_HOME vs PATH

These are related but different.

## JAVA_HOME

Points to the Java installation directory.

Example:

```text
JAVA_HOME
        ↓
/Library/Java/JavaVirtualMachines/jdk-21.jdk/Contents/Home
```

## PATH

A list of directories the shell searches when you type a command.

For example:

```bash
java
```

The shell searches directories in:

```text
PATH
```

until it finds the Java executable.

Use:

```bash
which java
```

to see which Java executable is being used.

Example:

```text
/usr/bin/java
```

---

# 18. SONAR_JAVA_PATH

SonarQube can also be told explicitly which Java executable to use.

Current Sonar documentation supports the environment variable:

```text
SONAR_JAVA_PATH
```

for this purpose.

Example:

```bash
export SONAR_JAVA_PATH="/path/to/java/bin/java"
```

This becomes useful when your system contains multiple Java versions.

For example:

```text
Java 17
Java 21
Java 23
```

and SonarQube needs to use one specific installation.

Do not configure this unnecessarily if:

```bash
java -version
```

already shows the correct supported runtime.

# 44. Understand File Ownership

Suppose your SonarQube files belong to:

```text
ann
```

and you start SonarQube as:

```text
ann
```

that is usually straightforward.

But imagine files belong to:

```text
root
```

while SonarQube is started as:

```text
ann
```

Then SonarQube may fail to write to:

```text
logs/
data/
temp/
```

resulting in permission errors.

This is why installation ownership matters.

The dot refers to the current directory.

## `/`

Separates path components.


means:

# 51. What Happens During Startup

Remember Part 2.

Starting SonarQube does not launch only one process.

Conceptually:

```text
sonar.sh
   ↓
SonarQube Bootstrap
   ↓
Start Elasticsearch
   ↓
Start Web Process
   ↓
Start Compute Engine
   ↓
Initialize Database
   ↓
Initialize Search Indexes
   ↓
Server Becomes Operational
```

This may take some time, especially on the first startup.

Do not assume:

# 93. Fix Permissions Carefully

Do not use this as your default solution:

```bash
chmod -R 777 sonarqube
```

That is a common beginner mistake.

`777` broadly grants read, write, and execute permissions to everyone.

That is usually unnecessary and insecure.

Instead determine:

```text
Who should own these files?
```

and set appropriate ownership and permissions.

Principle:

```text
Correct owner
+
Minimum necessary permissions
```

not:

```text
Everyone can do everything.
```

---

# 94. Understanding `chmod`

You may encounter:

```bash
chmod
```

This means:

```text
change mode
```

It changes Unix filesystem permissions.

But do not blindly copy permission commands without understanding them.

For example:

```bash
chmod -R 777
```

means applying extremely broad permissions recursively.

That can create security problems.

For a local lab, it is often better to extract SonarQube as the same normal user who will run it.

That prevents many permission problems from occurring in the first place.

If Jenkins runs inside another server and you configure:


then Jenkins interprets that as:

```text
the Jenkins host itself
```

not necessarily your SonarQube host.

# 116. Comments in Configuration Files

You will often see lines beginning with:

```text
#
```

Example:

```text
#sonar.web.port=9000
```

The `#` generally means:

```text
comment
```

The setting is shown but not actively applied from that line.

If SonarQube already defaults to port 9000, the property does not need to be uncommented simply to use the default.

This is a common configuration-file pattern.

```text

       │
```
```text
       └── YES
            ↓

            │

                 │

                 │

                      ↓

                      └── YES
```
