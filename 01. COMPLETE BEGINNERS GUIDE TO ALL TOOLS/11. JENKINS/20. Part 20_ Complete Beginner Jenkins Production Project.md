# Part 20: Complete Beginner Jenkins Production Project

## Learning Objective

This is the final part of the Jenkins beginner track.

Parts 1 through 19 taught individual Jenkins concepts.

Now we combine them into one complete delivery system.

You will build:

```text
Developer
    ↓
Git
    ↓
GitHub
    ↓
Webhook
    ↓
Jenkins Controller
    ↓
Jenkins Agent
    ↓
Checkout
    ↓
Dependency Installation
    ↓
Build
    ↓
Unit Tests
    ↓
Quality / Security Checks
    ↓
Docker Build
    ↓
Versioned Image
    ↓
Container Registry
    ↓
Deployment Approval
    ↓
Linux / AWS Server
    ↓
Application
    ↓
Health Check
    ↓
Logs
    ↓
Deployment Verification
    ↓
Notification
```

You will not receive a finished system.

You will build it.

You will verify each boundary before moving to the next one.

Then you will deliberately break it.

You will troubleshoot:

* Git failures
* webhook failures
* Jenkinsfile failures
* agent failures
* credential failures
* test failures
* security-check failures
* Docker failures
* registry failures
* deployment failures
* application failures
* health-check failures
* permission failures
* network failures

Finally, you will:

* perform rollback;
* back up Jenkins;
* test recovery;
* clean resources;
* document the architecture.

The final objective is not:

```text
I followed a Jenkins tutorial.
```

It is:

```text
I understand the complete delivery path.

I can build it.

I can verify it.

I can secure it.

I can break it safely.

I can troubleshoot it.

I can recover it.
```

# 2. Final Delivery Flow

A developer makes a change.

```text
Developer
↓
git add
↓
git commit
↓
git push
↓
GitHub
```

GitHub sends a webhook.

```text
GitHub
↓
Webhook
↓
Jenkins
```

Jenkins discovers the change.

```text
Jenkins Controller
↓
Queue
↓
Scheduler
↓
Jenkins Agent
```

The agent executes the Pipeline.

```text
Checkout
↓
Environment Verification
↓
Dependency Installation
↓
Unit Tests
↓
Quality Checks
↓
Security Checks
↓
Docker Build
↓
Container Test
↓
Image Versioning
↓
Registry Authentication
↓
Image Push
```

Production deployment does not happen immediately.

```text
Published Artifact
↓
Approval
↓
Deployment
```

The deployment server receives the exact image.

```text
Registry
↓
Application Server
↓
docker pull
↓
docker run
↓
Health Check
```

Jenkins verifies the deployment.

```text
Expected Version
↓
Running Version
↓
Health
↓
Logs
↓
Verification
```

Only then should the delivery process report success.

# 3. Why This Architecture Matters

A beginner may think CI/CD means:

```text

↓

```

A real delivery system contains boundaries.

```text
Source Boundary
↓
Build Boundary
↓
Test Boundary
↓
Security Boundary
↓
Artifact Boundary
↓
Approval Boundary
↓
Deployment Boundary
↓
Runtime Boundary
↓
```

Each boundary can fail independently.

That is why Part 20 is not simply one giant Jenkinsfile.

# 54. Generate Version Stage

After checkout:

```groovy
stage('Generate Version') {
    steps {
        script {
            env.GIT_SHA = sh(
                script: 'git rev-parse --short=12 HEAD',
                returnStdout: true
            ).trim()

            env.APP_VERSION = "${env.BUILD_NUMBER}-${env.GIT_SHA}"
            env.IMAGE = "${env.REGISTRY_REPOSITORY}:${env.APP_VERSION}"
        }

        echo "Application version: ${env.APP_VERSION}"
    }
}
```

# 71. Runtime Verification Stage

Example:

```groovy
stage('Runtime Verification') {
    steps {
        sh '''
            set -eu

            NAME="ci-${BUILD_NUMBER}"

            cleanup() {
                docker logs "$NAME" > runtime.log 2>&1 || true
                docker rm -f "$NAME" >/dev/null 2>&1 || true
            }

            trap cleanup EXIT

            docker run -d \
              --name "$NAME" \
              -p 127.0.0.1::5000 \
              "$IMAGE"

            PORT="$(docker port "$NAME" 5000/tcp | head -n1 | awk -F: '{print $NF}')"

            i=1
            while [ "$i" -le 20 ]; do
                if curl --fail --silent \
                    "http://127.0.0.1:${PORT}/health" \
                    >/dev/null; then
                    echo "Container is healthy."
                    exit 0
                fi

                sleep 2
                i=$((i + 1))
            done

            echo "Container failed health verification."
            exit 1
        '''
    }

    post {
        always {
            archiveArtifacts(
                artifacts: 'runtime.log',
                allowEmptyArchive: true
            )
        }
    }
}
```

# 109. Rollback Function

A teaching version:

```bash
rollback() {
    if [ -z "${PREVIOUS_IMAGE:-}" ]; then
        echo "No previous image available for rollback."
        return 1
    fi

    echo "Rolling back to: $PREVIOUS_IMAGE"

    docker rm -f "$APP_NAME" >/dev/null 2>&1 || true

    if ! docker pull "$PREVIOUS_IMAGE"; then
        echo "Rollback failed: previous image could not be pulled."
        return 1
    fi

    if ! docker run -d \
        --name "$APP_NAME" \
        --restart unless-stopped \
        -p "${HOST_PORT}:${CONTAINER_PORT}" \
        "$PREVIOUS_IMAGE"; then

        echo "Rollback failed: previous container could not start."
        return 1
    fi

    return 0
}
```

# 111. Handle New Container Start Failure

Do not write:

```bash
docker run ...
```

under `set -e` and assume later rollback code will execute.

Control the failure explicitly:

```bash
if ! docker run -d \
    --name "$APP_NAME" \
    --restart unless-stopped \
    -p "${HOST_PORT}:${CONTAINER_PORT}" \
    "$IMAGE"; then

    echo "New container failed to start."

    rollback || {
        echo "CRITICAL: deployment and rollback both failed."
        exit 2
    }

    exit 1
fi
```

This is an important production-thinking improvement.

---

# 112. Handle Health Failure

```bash
if ! wait_for_health; then
    echo "New release failed health verification."

    docker logs "$APP_NAME" || true

    rollback || {
        echo "CRITICAL: health failed and rollback failed."
        exit 2
    }

    if wait_for_health; then
        echo "Previous release restored successfully."
    else
        echo "CRITICAL: rollback container is unhealthy."
        exit 2
    fi

    exit 1
fi
```

Even when rollback succeeds, the attempted deployment should still be reported as failed.

Why?

Because:

```text
new release
FAILED
```

That fact should not disappear simply because service was restored.

```groovy
    )
}
```

Do not use arbitrary production timeouts without understanding normal build duration.

# 131. Concurrent Deployments

Prevent two builds from trying to replace the same single-server application simultaneously.

For this beginner project:

```groovy
options {
    disableConcurrentBuilds()
}
```

More advanced systems may control concurrency specifically around deployment rather than blocking all CI concurrency.

# 133. Final Jenkinsfile

The following is a reference implementation for the lab.

You must replace environment-specific values and configure the required credentials, agent labels, host trust, plugins, and tools.

```groovy
pipeline {
    agent {
        label 'linux && docker && python'
    }

    options {
        disableConcurrentBuilds()

        timeout(
            time: 45,
            unit: 'MINUTES'
        )

        buildDiscarder(
            logRotator(
                numToKeepStr: '30',
                artifactNumToKeepStr: '10'
            )
        )
    }

    parameters {
        choice(
            name: 'DEPLOY_ENV',
            choices: ['none', 'production'],
            description: 'Select deployment target'
        )

        booleanParam(
            name: 'RUN_SECURITY_CHECKS',
            defaultValue: true,
            description: 'Run security checks'
        )
    }

    environment {
        APP_NAME = 'veriqta-app'

        REGISTRY_REPOSITORY =
            'YOUR_DOCKERHUB_USERNAME/veriqta-jenkins-app'

        DEPLOY_HOST = 'YOUR_DEPLOYMENT_HOST'
        DEPLOY_USER = 'deploy'
        DEPLOY_PORT = '22'

        DEPLOY_DIR = '/opt/veriqta/app'

        APP_PORT = '8080'
        CONTAINER_PORT = '5000'
    }

    stages {

        stage('Verify Environment') {
            steps {
                sh '''
                    set -eu

                    echo "Host: $(hostname)"
                    echo "User: $(whoami)"
                    echo "Workspace: $(pwd)"

                    command -v git
                    command -v python3
                    command -v docker
                    command -v ssh
                    command -v scp
                    command -v ssh-agent
                    command -v curl

                    git --version
                    python3 --version
                    docker version
                    ssh -V
                    curl --version

                    df -h .
                    df -i .
                '''
            }
        }

        stage('Checkout') {
            steps {
                checkout scm

                sh '''
                    git status --short
                    git log -1 --oneline
                '''
            }
        }

        stage('Generate Version') {
            steps {
                script {
                    env.GIT_SHA = sh(
                        script: 'git rev-parse --short=12 HEAD',
                        returnStdout: true
                    ).trim()

                    env.APP_VERSION =
                        "${env.BUILD_NUMBER}-${env.GIT_SHA}"

                    env.IMAGE =
                        "${env.REGISTRY_REPOSITORY}:${env.APP_VERSION}"
                }

                echo "Version: ${env.APP_VERSION}"
                echo "Image: ${env.IMAGE}"
            }
        }

        stage('Install Dependencies') {
            steps {
                sh '''
                    set -eu

                    rm -rf .venv

                    python3 -m venv .venv

                    .venv/bin/python \
                        -m pip install \
                        --upgrade pip

                    .venv/bin/python \
                        -m pip install \
                        -r requirements-dev.txt
                '''
            }
        }

        stage('Unit Tests') {
            steps {
                sh '''
                    set -eu

                    mkdir -p reports

                    .venv/bin/pytest \
                        --junitxml=reports/unit-tests.xml \
                        -v
                '''
            }

            post {
                always {
                    junit(
                        testResults:
                            'reports/unit-tests.xml',
                        allowEmptyResults: false
                    )
                }
            }
        }

        stage('Quality Check') {
            steps {
                sh '''
                    set -eu

                    .venv/bin/python \
                        -m compileall \
                        app.py \
                        tests
                '''
            }
        }

        stage('Security Check') {
            when {
                expression {
                    return params.RUN_SECURITY_CHECKS
                }
            }

            steps {
                sh '''
                    set -eu

                    if [ ! -x scripts/security-check.sh ]; then
                        echo "Security check script is missing or not executable."
                        exit 1
                    fi

                    ./scripts/security-check.sh
                '''
            }
        }

        stage('Docker Build') {
            steps {
                sh '''
                    set -eu

                    docker build \
                        --build-arg \
                        APP_VERSION="$APP_VERSION" \
                        --label \
                        org.opencontainers.image.revision="$GIT_SHA" \
                        --label \
                        org.opencontainers.image.version="$APP_VERSION" \
                        -t "$IMAGE" \
                        .
                '''
            }
        }

        stage('Container Tests') {
            steps {
                sh '''
                    set -eu

                    docker run \
                        --rm \
                        "$IMAGE" \
                        pytest -v
                '''
            }
        }

        stage('Runtime Verification') {
            steps {
                sh '''
                    set -eu

                    NAME="ci-${BUILD_NUMBER}"

                    cleanup_runtime() {
                        docker logs "$NAME" \
                            > runtime.log \
                            2>&1 || true

                        docker rm -f "$NAME" \
                            >/dev/null \
                            2>&1 || true
                    }

                    trap cleanup_runtime EXIT

                    docker run \
                        -d \
                        --name "$NAME" \
                        -p 127.0.0.1::5000 \
                        "$IMAGE"

                    PORT="$(
                        docker port "$NAME" 5000/tcp |
                        head -n1 |
                        awk -F: '{print $NF}'
                    )"

                    i=1

                    while [ "$i" -le 20 ]; do

                        if curl \
                            --fail \
                            --silent \
                            "http://127.0.0.1:${PORT}/health" \
                            >/dev/null; then

                            echo "Runtime verification passed."
                            exit 0
                        fi

                        sleep 2
                        i=$((i + 1))
                    done

                    echo "Runtime verification failed."
                    exit 1
                '''
            }

            post {
                always {
                    archiveArtifacts(
                        artifacts: 'runtime.log',
                        allowEmptyArchive: true
                    )
                }
            }
        }

        stage('Build Metadata') {
            steps {
                sh '''
                    set -eu

                    mkdir -p build-metadata

                    {
                        echo "build_number=$BUILD_NUMBER"
                        echo "git_sha=$GIT_SHA"
                        echo "app_version=$APP_VERSION"
                        echo "image=$IMAGE"
                        echo "build_url=$BUILD_URL"
                    } > build-metadata/release.txt
                '''

                archiveArtifacts(
                    artifacts:
                        'build-metadata/release.txt',
                    fingerprint: true
                )
            }
        }

        stage('Publish Image') {
            steps {
                withCredentials([
                    usernamePassword(
                        credentialsId:
                            'dockerhub-push',
                        usernameVariable:
                            'REGISTRY_USER',
                        passwordVariable:
                            'REGISTRY_TOKEN'
                    )
                ]) {
                    sh '''
                        set +x
                        set -eu

                        export DOCKER_CONFIG="$WORKSPACE/.docker-publish"

                        rm -rf "$DOCKER_CONFIG"

                        mkdir -p "$DOCKER_CONFIG"

                        chmod 700 "$DOCKER_CONFIG"

                        printf '%s' "$REGISTRY_TOKEN" |
                            docker login \
                                --username "$REGISTRY_USER" \
                                --password-stdin

                        docker push "$IMAGE"

                        docker logout || true
                    '''
                }
            }
        }

        stage('Verify Published Artifact') {
            steps {
                sh '''
                    set -eu

                    docker pull "$IMAGE"

                    docker image inspect \
                        "$IMAGE" \
                        >/dev/null

                    echo "Published artifact verified."
                '''
            }
        }

        stage('Deployment Preflight') {
            when {
                allOf {
                    branch 'main'

                    expression {
                        return params.DEPLOY_ENV ==
                            'production'
                    }
                }
            }

            steps {
                sshagent(
                    credentials:
                        ['production-deploy-ssh']
                ) {
                    sh '''
                        set -eu

                        ssh \
                            -p "$DEPLOY_PORT" \
                            -o BatchMode=yes \
                            -o StrictHostKeyChecking=yes \
                            -o ConnectTimeout=10 \
                            "$DEPLOY_USER@$DEPLOY_HOST" \
                            '
                                set -eu

                                command -v docker
                                command -v curl

                                docker info >/dev/null

                                df -h .
                                df -i .

                                echo "Deployment preflight passed."
                            '
                    '''
                }
            }
        }

        stage('Production Approval') {
            when {
                allOf {
                    branch 'main'

                    expression {
                        return params.DEPLOY_ENV ==
                            'production'
                    }
                }
            }

            steps {
                timeout(
                    time: 15,
                    unit: 'MINUTES'
                ) {
                    input(
                        message:
                            "Deploy ${env.APP_VERSION} to production?",
                        ok:
                            'Deploy'
                    )
                }
            }
        }

        stage('Install Deployment Script') {
            when {
                allOf {
                    branch 'main'

                    expression {
                        return params.DEPLOY_ENV ==
                            'production'
                    }
                }
            }

            steps {
                sshagent(
                    credentials:
                        ['production-deploy-ssh']
                ) {
                    sh '''
                        set -eu

                        test -f scripts/deploy.sh

                        chmod +x scripts/deploy.sh

                        scp \
                            -P "$DEPLOY_PORT" \
                            -o BatchMode=yes \
                            -o StrictHostKeyChecking=yes \
                            -o ConnectTimeout=10 \
                            scripts/deploy.sh \
                            "$DEPLOY_USER@$DEPLOY_HOST:/tmp/deploy.sh.${BUILD_NUMBER}"

                        ssh \
                            -p "$DEPLOY_PORT" \
                            -o BatchMode=yes \
                            -o StrictHostKeyChecking=yes \
                            -o ConnectTimeout=10 \
                            "$DEPLOY_USER@$DEPLOY_HOST" \
                            "install -m 0755 \
                            /tmp/deploy.sh.${BUILD_NUMBER} \
                            ${DEPLOY_DIR}/deploy.sh \
                            && rm -f \
                            /tmp/deploy.sh.${BUILD_NUMBER}"
                    '''
                }
            }
        }

        stage('Deploy') {
            when {
                allOf {
                    branch 'main'

                    expression {
                        return params.DEPLOY_ENV ==
                            'production'
                    }
                }
            }

            steps {
                sshagent(
                    credentials:
                        ['production-deploy-ssh']
                ) {
                    sh '''
                        set -eu

                        ssh \
                            -p "$DEPLOY_PORT" \
                            -o BatchMode=yes \
                            -o StrictHostKeyChecking=yes \
                            -o ConnectTimeout=10 \
                            "$DEPLOY_USER@$DEPLOY_HOST" \
                            "${DEPLOY_DIR}/deploy.sh \
                            '$IMAGE' \
                            '$APP_NAME' \
                            '$APP_PORT' \
                            '$CONTAINER_PORT'"
                    '''
                }
            }
        }

        stage('Deployment Verification') {
            when {
                allOf {
                    branch 'main'

                    expression {
                        return params.DEPLOY_ENV ==
                            'production'
                    }
                }
            }

            steps {
                sshagent(
                    credentials:
                        ['production-deploy-ssh']
                ) {
                    sh '''
                        set -eu

                        ssh \
                            -p "$DEPLOY_PORT" \
                            -o BatchMode=yes \
                            -o StrictHostKeyChecking=yes \
                            -o ConnectTimeout=10 \
                            "$DEPLOY_USER@$DEPLOY_HOST" \
                            "curl \
                            --fail \
                            --silent \
                            http://127.0.0.1:${APP_PORT}/health"
                    '''
                }
            }
        }

        stage('Verify Expected Version') {
            when {
                allOf {
                    branch 'main'

                    expression {
                        return params.DEPLOY_ENV ==
                            'production'
                    }
                }
            }

            steps {
                sshagent(
                    credentials:
                        ['production-deploy-ssh']
                ) {
                    sh '''
                        set -eu

                        ACTUAL="$(
                            ssh \
                                -p "$DEPLOY_PORT" \
                                -o BatchMode=yes \
                                -o StrictHostKeyChecking=yes \
                                -o ConnectTimeout=10 \
                                "$DEPLOY_USER@$DEPLOY_HOST" \
                                "curl \
                                --fail \
                                --silent \
                                http://127.0.0.1:${APP_PORT}/"
                        )"

                        printf '%s\n' "$ACTUAL"

                        printf '%s\n' "$ACTUAL" |
                            grep -F \
                            "\\"version\\":\\"$APP_VERSION\\""
                    '''
                }
            }
        }
    }

    post {
        success {
            echo """
Pipeline successful.

Build: ${env.BUILD_NUMBER}
Version: ${env.APP_VERSION ?: 'unknown'}
Image: ${env.IMAGE ?: 'not-created'}
"""
        }

        unstable {
            echo "Pipeline is unstable."
        }

        failure {
            echo """
Pipeline failed.

Build: ${env.BUILD_NUMBER}
Review the failed stage and console output.
"""
        }

        aborted {
            echo "Pipeline aborted."
        }

        cleanup {
            sh '''
                rm -rf .docker-publish || true

                docker rm -f \
                    "ci-${BUILD_NUMBER}" \
                    >/dev/null \
                    2>&1 || true
            '''
        }
    }
}
```

# 213. The Final Question

At the beginning of this series, a Jenkins Pipeline might have looked mysterious:

```groovy
pipeline {
    agent any

    stages {
        stage('Build') {
            steps {
                sh './build.sh'
            }
        }
    }
}
```

Now when you see:

```text
Developer
→ GitHub
→ Jenkins
→ Test
→ Build
→ Artifact
→ Docker
→ Registry
→ Deployment
→ Application
→ Verification
```

you should be able to explain:

* who initiates each transition;
* which machine performs the work;
* which credentials are required;
* which network path is used;
* what files are created;
* what commands run;
* what constitutes success;
* what can fail;
* where evidence appears;
* how Jenkins knows the stage passed;
* why the next stage is allowed to run;
* which artifact is being deployed;
* which source commit created it;
* how the target retrieves it;
* how application health is determined;
* how the running version is verified;
* how secrets are protected;
* how production access is restricted;
* what happens when deployment fails;
* how rollback works;
* how Jenkins itself is recovered;
* how the infrastructure is cleaned up.

That is the purpose of the entire 20-part track.

You started with:

```text
What is Jenkins?
```

You finish with:

```text
I can design, build, secure, operate, troubleshoot, and recover a complete Jenkins-driven CI/CD workflow.
```
