# Part 13: Maven Archetypes and Project Generation

## Introduction

Up to this point, you have learned how to build a Maven project deliberately.

You created directories such as:

```text
src/main/java
src/main/resources
src/test/java
src/test/resources
```

You created:

```text
pom.xml
```

You learned what the POM contains, how Maven coordinates work, how dependencies are resolved, how plugins perform work, how the lifecycle operates, how Java is compiled and tested, and how resources become part of the final artifact.

That manual approach was important.

Before using a project generator, you should understand what the generator is creating.

Now we can introduce Maven archetypes.

Instead of manually creating:

```text
Project directory
→ pom.xml
→ src
→ main
→ java
→ package directories
→ test
→ java
→ test package directories
```

Maven can generate a starting project structure for you.

The basic idea is:

```text
Archetype
    |
    v
Project Template
    |
    +---- project structure
    +---- pom.xml
    +---- starter source
    +---- starter tests
    |
    v
Generated Maven Project
```

In this part, you will learn what archetypes are, how Maven generates projects from them, how to use interactive and non-interactive generation, how archetype coordinates work, why you should not blindly trust templates, and how organizations can use internal templates to standardize projects.

At the end, we will generate a second VERIQTA Maven application and compare it with the project you created manually.

---

# 1. What Is an Archetype?

In Maven, an archetype is a project template.

It describes a starting structure from which Maven can generate a new project.

Think of it as:

```text
Reusable project blueprint
        |
        v
New Maven project
```

An archetype can provide things such as:

* Directory structure
* `pom.xml`
* Java package structure
* Starter Java classes
* Starter test classes
* Resource directories
* Configuration files
* Default dependencies
* Plugin configuration
* Project metadata

The exact contents depend on the archetype.

An archetype does not represent your completed application.

It provides a starting point.

---

# 2. Why Project Templates Exist

Imagine that every time you start a Java application you manually create:

```text
my-app/
├── pom.xml
└── src/
    ├── main/
    │   └── java/
    └── test/
        └── java/
```

Then you manually create the Java package structure:

```text
src/main/java/com/veriqta/app
```

Then:

```text
src/test/java/com/veriqta/app
```

Then you write the basic POM.

Doing this once is useful for learning.

Doing it repeatedly becomes repetitive.

Project templates exist to automate repeatable setup.

Instead of:

```text
Create directory
→ Create POM
→ Create src
→ Create main
→ Create java
→ Create package
→ Create test
→ Create test package
→ Create starter class
→ Create starter test
```

you can use:

```text
Choose template
→ Supply project information
→ Generate
```

The template performs the repetitive scaffolding.

# 3. What Is Scaffolding?

You may encounter the word:

```text
scaffolding
```

in software development.

Scaffolding means automatically creating an initial project structure and often some starter files.

For example:

```text
Input:

groupId=com.veriqta
artifactId=veriqta-generated-app
version=1.0-SNAPSHOT
package=com.veriqta.app

        |
        v

Scaffolding

        |
        v

veriqta-generated-app/
├── pom.xml
└── src/
    ├── main/
    │   └── java/
    │       └── com/
    │           └── veriqta/
    │               └── app/
    │                   └── App.java
    └── test/
        └── java/
            └── com/
                └── veriqta/
                    └── app/
                        └── AppTest.java
```

You still own and maintain the resulting project.

# 4. Archetype Versus Maven Project

Do not confuse these concepts.

An archetype is:

```text
Template
```

A Maven project is:

```text
Actual project created from the template
```

Mental model:

```text
Archetype
   |
   | generate
   v
Maven Project
```

The archetype is not normally something your application needs every time it builds.

It is primarily involved in project creation.

---

# 5. Archetype Versus Artifact

These words look similar but mean different things.

## Archetype

A project template.

Example:

```text
maven-archetype-quickstart
```

## Artifact

A software component identified by Maven coordinates or an output produced by a build.

Examples:

```text
junit-jupiter-api
```

or:

```text
veriqta-maven-app-1.0.0.jar
```

Remember:

```text
Archetype
→ helps create a project

Artifact
→ a Maven-addressable component or build output
```

An archetype itself is also distributed as a Maven artifact, but its purpose is project generation.

# 6. Why You Learned Manual Project Creation First

In Part 3, you manually built a project.

That was deliberate.

If you had started with an archetype immediately, Maven could have generated:

```text
pom.xml
src/main/java
src/test/java
App.java
AppTest.java
```

without you understanding why those files existed.

Now, when an archetype generates:

```text
src/main/java
```

you know what it means.

When it generates:

```text
pom.xml
```

you know why it exists.

When it creates:

```text
src/test/java
```

you know why tests are separate.

When you see:

```text
target/
```

after building, you know that it is generated build output rather than something the archetype originally needs to provide.

This gives us an important beginner rule:

```text
Automation is easier to understand
when you understand the manual process
that it automates.
```

# 8. Understanding `archetype:generate`

The command commonly begins:

```bash
mvn archetype:generate
```

Break it apart:

```text
mvn
```

starts Maven.

```text
archetype
```

is the plugin prefix.

```text
generate
```

is the goal.

Therefore:

```text
mvn archetype:generate
```

means conceptually:

```text
Run Maven
      |
      v
Use Archetype Plugin
      |
      v
Run generate goal
      |
      v
Generate a project from an archetype
```

---

# 9. Goal Versus Lifecycle Phase

Recall Part 5.

You can invoke a lifecycle phase:

```bash
mvn package
```

or a plugin goal:

```bash
mvn archetype:generate
```

These are different forms.

`package` is a lifecycle phase.

`archetype:generate` is a plugin goal.

Compare:

```text
mvn package
    |
    v
Default lifecycle
    |
    v
Execute phases through package
```

with:

```text
mvn archetype:generate
    |
    v
Archetype Plugin
    |
    v
generate goal
```

This reinforces the distinction between phases and goals.

```text
        |
```

# 11. Archetype Coordinates

An archetype needs to be identified.

Because archetypes are distributed through Maven's artifact system, they use Maven coordinates.

Important archetype coordinate fields include:

```text
archetypeGroupId
archetypeArtifactId
archetypeVersion
```

For example:

```text
archetypeGroupId
→ org.apache.maven.archetypes

archetypeArtifactId
→ maven-archetype-quickstart

archetypeVersion
→ selected archetype version
```

Together they identify the archetype Maven should use.

---

# 12. Do Not Confuse Archetype Coordinates With Project Coordinates

This is one of the most important concepts in this part.

There are two different sets of coordinates involved.

First:

```text
Archetype coordinates
```

These identify the template.

Second:

```text
Project coordinates
```

These identify the project being generated.

For example:

```text
ARCHETYPE

archetypeGroupId=org.apache.maven.archetypes
archetypeArtifactId=maven-archetype-quickstart
archetypeVersion=<selected version>
```

versus:

```text
NEW PROJECT

groupId=com.veriqta
artifactId=veriqta-generated-app
version=1.0-SNAPSHOT
```

Do not mix them.

# 14. `groupId` for the New Project

Suppose we choose:

```text
groupId=com.veriqta
```

Example:


This can become part of the project's Maven coordinates:

```text

```

# 15. `artifactId` for the New Project

Suppose:

```text
artifactId=veriqta-generated-app
```

The `artifactId` identifies the project or artifact within its group.

It commonly also becomes the generated directory name.

For example:

```text
Current directory
        |
        v
Generate
        |
        v
veriqta-generated-app/
```

Later, the built JAR might be named something like:

```text
veriqta-generated-app-1.0-SNAPSHOT.jar
```

depending on the POM and packaging configuration.

# 16. Project Version

A generated project also needs a version.

Example:

```text
1.0-SNAPSHOT
```

Recall:

```text
SNAPSHOT
```

indicates a development version that may continue changing.

A release version might eventually look like:

```text
1.0.0
```

The version belongs to the generated project, not the archetype itself.

---

# 17. Package

The generator may ask for:

```text
package
```

For example:

```text
com.veriqta.app
```

This determines the Java package used by generated source files.

The generated structure may become:

```text
src/main/java/com/veriqta/app/App.java
```

and:

```text
src/test/java/com/veriqta/app/AppTest.java
```

The directory structure corresponds to:

```java
package com.veriqta.app;
```

---

# 18. `groupId` Versus Java Package

These values can look similar:

```text
groupId=com.veriqta
package=com.veriqta.app
```

but they serve different purposes.

`groupId` is part of Maven artifact identity.

`package` is part of Java's namespace and source-code organization.

They may be related by naming convention, but they are not the same concept.

For example:

```text
Maven coordinate:

com.veriqta:veriqta-generated-app:1.0-SNAPSHOT
```

while Java code may declare:

```java
package com.veriqta.app;
```

# 19. The Quickstart Archetype


Its archetype coordinates use:

# 20. Why Use Quickstart for Learning?

The quickstart archetype is useful here because it allows us to compare:

```text
Project created manually
```

with:

```text
Project generated automatically
```

We are not using it because every production Java application should begin with this exact archetype.

The important process is:

```text

        |
        v
Provide groupId
        |
        v
Provide artifactId
        |
        v
Provide version
        |
        v
Provide package
        |
        v

        |

```

# 22. Why Interactive Generation Can Be Confusing

A broad interactive archetype search can expose many available templates.

A beginner might see a long list and think:

```text
Which one am I supposed to choose?
```

That is one reason explicit archetype coordinates are often easier when following a controlled tutorial.

Instead of browsing blindly, we can tell Maven exactly which archetype we intend to use.

---

# 23. Interactive Generation With a Selected Archetype

A more controlled command can provide the archetype coordinates while allowing Maven to ask for project information.

Conceptually:

```bash
mvn archetype:generate \
  -DarchetypeGroupId=org.apache.maven.archetypes \
  -DarchetypeArtifactId=maven-archetype-quickstart \
  -DarchetypeVersion=<selected-version>
```

The backslash:

```text
\
```

on macOS/Linux shells allows a long command to continue onto another line.

You could also write the command on one line.

Do not type:

```text
<selected-version>
```

literally.

Replace it with the archetype version you have deliberately selected.

---

# 24. What `-D` Means Here

You have already encountered:

```text
-D
```

in Part 12.

It supplies a property to the Maven process.

For example:

```text
-DarchetypeArtifactId=maven-archetype-quickstart
```

means:

```text
Property:
archetypeArtifactId

Value:
maven-archetype-quickstart
```

Maven's archetype generation process uses that property to determine which template you want.

# 27. Non-Interactive Generation

Interactive generation is useful for learning.

Automation requires a different approach.

Suppose a CI job, script, training lab, or development platform needs to generate a project without a human answering prompts.

Maven supports non-interactive archetype generation.

A command can look conceptually like:

```bash
mvn archetype:generate \
  -DgroupId=com.veriqta \
  -DartifactId=veriqta-archetype-app \
  -Dversion=1.0-SNAPSHOT \
  -Dpackage=com.veriqta.app \
  -DarchetypeGroupId=org.apache.maven.archetypes \
  -DarchetypeArtifactId=maven-archetype-quickstart \
  -DarchetypeVersion=<selected-version> \
  -DinteractiveMode=false
```

Again, replace:

```text
<selected-version>
```

with the intended version.

---

# 28. Understanding Every Important Part

Start:

```bash
mvn archetype:generate
```

means:

```text
Run Maven Archetype Plugin's generate goal.
```

Then:

```text
-DgroupId=com.veriqta
```

sets the generated project's group ID.

Then:

```text
-DartifactId=veriqta-archetype-app
```

sets the generated project's artifact ID and commonly its directory name.

Then:

```text
-Dversion=1.0-SNAPSHOT
```

sets the generated project version.

Then:

```text
-Dpackage=com.veriqta.app
```

sets the generated Java package.

Then:

```text
-DarchetypeGroupId=org.apache.maven.archetypes
```

identifies the archetype's group.

Then:

```text
-DarchetypeArtifactId=maven-archetype-quickstart
```

identifies the archetype.

Then:

```text
-DarchetypeVersion=<selected-version>
```

selects the archetype version.

Finally:

```text
-DinteractiveMode=false
```

tells the generation process not to stop and ask the user for interactive input.

# 29. Interactive Versus Non-Interactive

Interactive:

```text
Command
   |
   v
Maven asks questions
   |
   v
Human answers
   |
   v
Project generated
```

Non-interactive:

```text
Command already contains required properties
   |
   v
Maven receives values
   |
   v
Project generated
```

Use interactive mode when:

* Learning
* Exploring a template
* Manually starting a project
* You want to review values as you go

Use non-interactive mode when:

* Automating
* Scripting
* Creating repeatable labs
* Building developer tooling
* Generating standardized projects
* Running unattended workflows

# 30. What Maven May Download

When you run archetype generation for the first time, Maven may download artifacts.

This should no longer surprise you.

The process can involve:

```text
Maven
  |
  v
Check local repository
  |
  v
Required artifact available?
  |
  +---- Yes → use cached artifact
  |
  +---- No
          |
          v
     Remote repository
          |
          v
       Download
          |
          v
     Store in .m2
          |
          v
         Use
```

The Archetype Plugin and selected archetype may need to be resolved like other Maven artifacts.

---

# 31. The `.m2` Connection

Recall:

```text
~/.m2/repository
```

Maven caches downloaded artifacts there.

Archetype-related artifacts and plugin artifacts can also be resolved through Maven's repository system.

Therefore the concepts from Part 7 still apply.

This is not a separate downloading system.

It builds on Maven's existing artifact-resolution model.

# 41. Archetype Generation Versus Project Build

This distinction is important.

First:

```text
Archetype
   |
   v
Generate
   |
   v
Source project
```

Then:

```text
Source project
   |
   v
mvn package
   |
   v
Build output
```

Therefore:

```text

```

does not mean:

```text

```

```text

```

```text
        |
        v

        |

        |
        v
```

# 44. What Both Projects Have in Common

Both are Maven projects.

They can both have:

```text
pom.xml
src/main/java
src/main/resources
src/test/java
src/test/resources
target
```

They both follow the same fundamental Maven project model.

The difference is how the initial structure was created.

```text
Manual project
→ you created it

Archetype project
→ Maven generated it from a template
```

After generation, Maven treats the project like an ordinary Maven project.

# 45. Archetypes Do Not Create a Different Type of Maven

A common beginner misunderstanding would be:

> Is an archetype project a special kind of Maven project?

Not necessarily.

Once generated:

```text
Archetype
        |
        v
Project files
        |
        v
Normal Maven project
```

You can edit:

```text
pom.xml
```

Add:

```text
dependencies
plugins
resources
tests
```

and run:

```bash
mvn test
mvn package
mvn verify
mvn install
```

just as you would with the manually created project.

# 46. Creating Projects Manually

Manual creation gives you maximum visibility.

You decide:

```text
Directory structure
POM contents
Java packages
Dependencies
Plugins
Testing framework
Resources
Configuration
```

Advantages include:

* Excellent for learning
* No unexpected template contents
* Minimal starting configuration
* Full understanding of each file
* Easy to create a deliberately small project

Disadvantages include:

* Repetitive
* Slower for common structures
* Easier to make structural mistakes
* Teams may create inconsistent projects

# 47. Creating Projects With Archetypes

Archetypes automate initial setup.

Advantages include:

* Faster project creation
* Repeatable structure
* Reduced repetitive setup
* Can standardize conventions
* Useful for teams and organizations
* Can package organization-specific starter patterns

Disadvantages include:

* Template may be outdated
* Template may contain unnecessary dependencies
* Beginners may not understand generated files
* Different archetypes vary significantly in quality
* Generated defaults may not match your requirements
* A template can create a false sense of correctness

---

# 48. Manual Versus Archetype Decision

Think:

```text
Need to learn Maven fundamentals?
        |
        v
Manual creation is valuable.

Need repeatable starter structure?
        |
        v
Archetype may help.

Need organization-standard project setup?
        |
        v
Internal template/archetype may help.

Need complete control over a small project?
        |
        v
Manual setup may be simpler.
```

Neither approach is automatically superior.

Use the approach that solves the actual problem.

# 49. Choosing Archetypes Carefully

Do not choose an archetype only because:

```text

```

or:

```text

```

Before adopting one, investigate:

* Who maintains it
* What it generates
* Archetype version
* Dependencies it adds
* Plugin versions
* Java assumptions
* Testing framework
* Packaging type
* Framework assumptions
* Security implications
* Whether it is still maintained
* Whether your organization approves it

A template is executable engineering input into your project structure.

Treat it accordingly.

# 50. Why Random Archetypes Can Be Risky

An archetype can generate a POM containing dependencies and plugins.

For example:

```text
Unknown archetype
        |
        v
Generated pom.xml
        |
        +---- dependency A
        +---- dependency B
        +---- plugin C
        +---- repository D
        |
        v
mvn package
```

Maven may then resolve those components.

If you blindly generate and build projects from arbitrary templates, you may introduce unnecessary or undesirable dependencies and configuration.

The same supply-chain awareness you apply to dependencies should influence template selection.

# 120. Should You Commit `target`?

No, normally not.

This principle applies whether the project was:

```text

```

or:


# 127. Does Updating an Archetype Automatically Update Existing Projects?

This is a crucial concept.

Suppose:

```text
Project A
```

was generated using:

```text
archetype version 1
```

Later:

```text
archetype version 2
```

is released.

Project A does not automatically become the new project structure merely because the archetype changed.

Think:

```text
Archetype v1
        |
        v
Generate Project A
        |
        v
Project A now evolves independently

Later:

Archetype v2
        |
        v
Generate Project B
```

Template generation and ongoing project maintenance are separate problems.

---

# 128. The Template Drift Problem

Over time:

```text
Template v1
        |
        +---- Project A
        +---- Project B

Template evolves to v2

Project A still contains old setup
Project B still contains old setup
New Project C gets new setup
```

This creates:

```text
template drift
```

or project divergence from the current recommended baseline.

Organizations therefore need mechanisms beyond initial project generation to maintain standards over time.

An archetype solves:

```text
How do we start?
```

It does not completely solve:

```text
How do we keep every project updated forever?
```

The key lesson is simple:

An archetype saves you from repeatedly creating the same starting structure. It does not save you from understanding that structure.

A strong Maven engineer should be able to look at an archetype-generated project and explain what was generated, why each important file exists, which values came from the archetype, which came from the project coordinates, what Maven will do with those files during the build, and which generated defaults should be changed before the project is treated as production-ready.
